# @fibrae/semi-next

[简体中文](README.zh-CN.md)

The Next.js build plugin of Semi Design Next, for Next.js applications that use the Semi React component packages. Semi's component JS imports its own `.css`, and the plugin makes those imports build and server-render under Turbopack, the Pages Router and custom prefixes. The `next` in the package name refers to Next.js.

## When you need it

| Scenario                                                              | Setup                                                                                                                     |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| App Router, `next dev --webpack`, `next build --webpack`              | No plugin needed, just install `@fibrae/semi-ui-react`                                                                    |
| Next.js 16 default Turbopack, the Pages Router, or both Routers mixed | `semiNext()`, with no separate style import                                                                               |
| Custom class prefix                                                   | `semiNext({ prefixCls: 'my', omitCss: true })`, and import the stylesheet generated by `semi-build-scss --prefix my` once |

## Installation

```shell
pnpm add -D @fibrae/semi-next
```

Ships ESM only. Depends on [`@fibrae/semi-webpack-plugin`](../semi-webpack/README.md); the application brings its own `next`.

## Usage

### Turbopack and the Pages Router

```js
// next.config.mjs
import semiNext from '@fibrae/semi-next';

export default semiNext()({
    // your Next.js config
});
```

Components bring their own styles on demand, so do not import `styles.css`. `semiNext(options)` returns `(nextConfig) => nextConfig`, and on your config it:

- Merges `@fibrae/semi-ui-react`, `@fibrae/semi-ai-react`, `@fibrae/semi-icons-react` and `@fibrae/semi-icons-react/illustrations` into `transpilePackages`. The Pages Router server loads `node_modules` directly with Node, and Node cannot import `.css`.
- Adds `turbopack.rules`: with `omitCss` or `prefixCls`, it attaches the matching loader to Semi's JS. Your other rules stay. A rule on the same glob as the plugin (`*.js`) throws, so use a different glob.
- Adds `webpack()`: under `--webpack`, it attaches `SemiWebpackPlugin` according to the options, then calls your original `webpack` function. With no options it attaches no plugin, and Next handles the `.css` imported by components directly.

Next.js 16 exits with an error under Turbopack when the config has only a `webpack` key, so both keys are always returned together.

### Custom prefix

```js
// next.config.mjs
import semiNext from '@fibrae/semi-next';

export default semiNext({ prefixCls: 'my', omitCss: true })({});
```

`omitCss` removes the `.css` imports inside Semi packages, and `prefixCls` rewrites the class prefix in Semi's JS. Styles then come from a full stylesheet with the same prefix. Generate it with [`@fibrae/semi-scss-compile`](../semi-scss-compile/README.md) and import it once in the root layout (`pages/_app` for the Pages Router):

```shell
pnpm add -D @fibrae/semi-scss-compile
semi-build-scss --prefix my -o app/semi-my.css --min
# with @fibrae/semi-ai-react, also install -D @fibrae/semi-ai-foundation and import after app/semi-my.css
semi-build-scss --ai node_modules/@fibrae/semi-ai-foundation/dist -o app/semi-ai-my.css --min --prefix my
```

`prefixCls` requires `omitCss: true`, or reading the config throws (Turbopack cannot recompile Semi's SCSS, and under `--webpack` recompiling conflicts with Next's own style rules).

## Options

The options are `SemiWebpackPluginOptions` from [`@fibrae/semi-webpack-plugin`](../semi-webpack/README.md) (this package exports the alias type `SemiNextOptions`).

| Option                                                       | Type      | Default | Description                                                                                                       |
| ------------------------------------------------------------ | --------- | ------- | ----------------------------------------------------------------------------------------------------------------- |
| `omitCss`                                                    | `boolean` | `false` | Removes the `.css` imports inside Semi packages. Styles come from a full stylesheet the application imports.      |
| `prefixCls`                                                  | `string`  | `semi`  | Class prefix, which must match the prefix of the imported stylesheet. Requires `omitCss: true`.                   |
| `cssLayer`, `extractCssOptions`, `overrideStylesheetLoaders` | -         | -       | SCSS recompile options, passed to the webpack plugin only under `--webpack`. Passing them under Turbopack throws. |

The plugin detects the bundler through `process.env.TURBOPACK`, which Next sets before reading `next.config`: `auto` for the default bundler, `1` for `--turbopack`, and unset for `--webpack` and `next start`.

Known limitation: under `--webpack` on Next.js 16.4.3, the webpack plugin's SCSS recompile triggered by `cssLayer` conflicts with Next's own style rules, and the build reports `Invalid generator object`. `extractCssOptions` and `overrideStylesheetLoaders` are unverified.

The Turbopack `*.css` rule does not change the module type, so your own `*.module.css` files still work as CSS Modules.

## Development

- `pnpm --filter @fibrae/semi-next build`: builds with `vp pack`.
- `pnpm --filter @fibrae/semi-next test`: builds first, then uses `test/run.ts` to verify the returned `transpilePackages` and `turbopack.rules` (loader paths point at published files, and the `*.css` rule has no `as`, which keeps CSS Modules), when `webpack()` attaches the plugin, and the option checks for `prefixCls` and Turbopack.
