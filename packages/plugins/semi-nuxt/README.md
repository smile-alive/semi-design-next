# @fibrae/semi-nuxt

[简体中文](README.zh-CN.md)

The Nuxt module of Semi Design Next, for Nuxt applications that use `@fibrae/semi-ui-vue`. The module does two things. It registers [`@fibrae/semi-vite-plugin`](../semi-vite/README.md) in Nuxt's Vite build, so Semi components work directly under server rendering and hydration. It also turns off Nuxt's `features.inlineStyles` when the application has not set it, as explained in [Inline styles](#inline-styles).

## Installation

```shell
pnpm add @fibrae/semi-ui-vue
pnpm add -D @fibrae/semi-nuxt
```

Peer dependency: `nuxt >=4.6.2`. Ships ESM only.

## Usage

```ts
// nuxt.config.ts
export default defineNuxtConfig({
    modules: ['@fibrae/semi-nuxt'],
});
```

No other configuration is needed. The component JS brings its own style imports, so do not import `styles.css`, and Nuxt's dev and production builds server-render directly. The module does not auto-import components, so import them from `@fibrae/semi-ui-vue` as usual.

Options go under the `semi` config key and pass through to the semi-vite plugin as they are:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
    modules: ['@fibrae/semi-nuxt'],
    semi: { prefixCls: 'my' },
});
```

With a custom prefix, keep the default per-component style loading, and the plugin recompiles each component's SCSS with the prefix.

The full stylesheet is an optional route: turn on `omitCss` and import `styles.css` once in `css`. Do not mix the two routes; mixing roughly doubles the CSS size. `styles.css` is precompiled with a fixed `semi-` prefix and does not follow `prefixCls`. For a full stylesheet with a custom prefix, import one generated by `semi-build-scss --prefix my` instead (requires `-D @fibrae/semi-scss-compile`).

```ts
// nuxt.config.ts
export default defineNuxtConfig({
    modules: ['@fibrae/semi-nuxt'],
    semi: { omitCss: true },
    css: ['@fibrae/semi-ui-vue/styles.css'],
});
```

## Inline styles

When the application has not set `features.inlineStyles`, the module sets it to `false`. Nuxt's production SSR then loads styles only through `<link>` and no longer inlines them into the HTML.

The reason: Nuxt counts all CSS in a page's client chunk as that page component's styles, and the function form of `inlineStyles` can judge only by component, not exclude by stylesheet. Semi component styles imported by a single page, and so bundled into that page's chunk, get inlined into every SSR response of that page, while the same CSS still loads through `<link>`. Semi components shared by several pages go into a shared chunk and are not inlined. The increase depends on the components exclusive to the page. In one measurement, with a few common components imported by only one page, that page's HTML grew from about 5KB to about 210KB. Setting `false` removes only this duplication, and page content and styles stay the same.

The cost: your own SFC `<style>` blocks are no longer inlined either and load through `<link>`. To keep Nuxt's inlining, set `features.inlineStyles` (or the old key `experimental.inlineSSRStyles`) explicitly in `nuxt.config.ts`, `.nuxtrc` or the overrides of loadNuxt, and the module will not overwrite it. Known limitation: when a module ordered before this one sets it to a function in code, this module cannot tell it apart from Nuxt's default function and changes it to `false`.

```ts
// nuxt.config.ts
export default defineNuxtConfig({
    modules: ['@fibrae/semi-nuxt'],
    features: { inlineStyles: true },
});
```

## Options

The options are `SemiVitePluginOptions` from `@fibrae/semi-vite-plugin` (this package exports the alias type `ModuleOptions`). For meanings and defaults, see the [semi-vite options table](../semi-vite/README.md#options).

## Related packages

noExternal and the dev pre-bundling of `omitCss` are implemented in the semi-vite plugin, as described in its "How it works" section, and this package does not reimplement them.

## Development

- `pnpm --filter @fibrae/semi-nuxt build`: builds with `vp pack`.
- `pnpm --filter @fibrae/semi-nuxt test`: builds first, then uses `test/run.ts` to load the module through `loadNuxt` from `@nuxt/kit` and trigger `vite:extend`. It asserts that the semi-vite plugin is registered and that options under the `semi` key reach the plugin as they are. It also asserts that `features.inlineStyles` is `false` when unset, and keeps its value when set explicitly through overrides, the old key `experimental.inlineSSRStyles`, `test/inline-styles/nuxt.config.ts` or `test/inline-styles-rc/.nuxtrc`.
