# 无障碍

原组件只作参考实现（F10）：角色、状态、关联属性和键盘操作，都按 WAI-ARIA 与 [APG](https://www.w3.org/WAI/ARIA/apg/patterns/) 中对应模式的推荐做法实现，可以和原 Semi 不一致。

## 实现

- 优先用原生元素承担语义和焦点：可点击的东西是 `button`，链接是 `a href`，范围输入是 `input type="range"`。已有的结构决定，例如 Slider 每个手柄内放视觉隐藏的原生 range、可点击的 List.Item 在 li 内放铺满整行的原生 button、BackTop 是单个原生 button。
- 一个控件只有一个焦点目标。不嵌套交互元素，不多出、也不缺少 Tab 停靠点。`id`、`aria-*`、`name` 落在真正的焦点目标上，见 [components](components.md#属性透传与-ref)。
    - Tooltip、Popover、Dropdown 会给 tabIndex 为假值的触发元素注入 `tabIndex=0`。优先让它们直接包住获得焦点的控件；只有做不到时（例如禁用的 Button 外的 span），才给包裹的 span 或 div 传 `tabIndex={-1}`，禁用态传 -1，不传 `null`。
    - 输入类组件内的清除按钮是例外：有值时出现的原生 button，单独占一个 Tab 停靠点。焦点在组件内部移动（输入框与清除按钮之间）不算离开组件，不触发 `onBlur`、`onFocus`，判断方式同 PinCode：`!e.currentTarget.contains(e.relatedTarget)`。
- 键盘操作写全，并在 zh-CN、en-US 两份文档的「键盘和焦点」一节说明，和实际行为保持一致。
- 组合控件（combobox、listbox、grid、tree）的选项不能获得焦点，键盘焦点留在输入框或容器上，用 `aria-activedescendant` 指向当前选项。
- 对话框的 `aria-label`、`aria-labelledby`、`aria-describedby` 落在 `role="dialog"` 元素上（F12）。
- 组件自己画的可聚焦元素（不用 Semi Button 的箭头、触发器、复制按钮、`role="button"` 的 div 等）要在 `:focus-visible` 里 `@include focus-ring`（`@use '../base/mixin' as *`；原生 button 包裹的内联图标用同文件的 `@include bare-button`），得到与 Semi Button 一致的主题焦点环；宽度与颜色是全局 token `$width-focus-ring`、`$color-focus-ring`。不写就会露出浏览器默认的 `auto` 焦点环，check-pages 的 `userAgentFocusRings` 会报出来。不新增组件级焦点变量；上游已有的组件焦点变量（如 `$color-tag-outline-focus`）保留，默认值指向全局 token。焦点环被裁切时传负的 offset 向内收：`@include focus-ring(-2px)`。只有焦点环要画在别的元素上时才写 `outline: none`：`aria-activedescendant` 指向的项，或可聚焦按钮只占一部分、焦点环要框住整个可点击区域（Collapse 标题行用 `:has(... :focus-visible)`）。浏览器测试用 `@test/utils/browser` 的 `tabTo` 与 `expectThemeFocusRing` 断言。

## 可访问名称

- 可访问名称和内置文案一律从语言包读取（读取方式见各框架目录的 `components.md`），再用 `locale.pageN.replace('${page}', String(page))` 这类方式代入值。不写死英文字面量，也不用模板字符串拼名称；可以用 `grep -rnE 'aria-label="[A-Za-z]' packages/semi-ui-*/src` 自查。
- 使用方传入的名称优先于语言包。
- 新增文案按 [locale-text](../skills/locale-text/SKILL.md) 补齐 57 个语言包。
- 名称随语言切换的用例写在框架包的 `src/locale/__tests__/accessible-names.test.tsx`，用 ja_JP 断言：它既不是默认的 zh_CN，也不是英文。

## lint 与扫描

- jsx-a11y 规则整类开启。语义上必须保留的 `role` 写法、没有键盘操作的点击处理（例如只把焦点交给原生控件的点击区域），在文件所属框架的 `lint/<框架>/exemptions.ts` 里按文件加豁免条目，只列确实报错的规则，注释写明原因。源码里不写 disable 注释。新豁免先确认确实有报错，不预防性添加。
- 文档站的 axe 扫描以 `website/scripts/a11y-baseline.json` 为基线：新增违规和「已修复但仍在基线里」的条目都算失败。扫描与基线维护见 [check-pages](../skills/check-pages/SKILL.md)。
- 改动了无障碍行为后，在 dev server 上扫描该组件和主要使用方的页面。
