## 代码演示

### 如何引入

<Framework only="react">

```jsx
import { Steps } from '@fibrae/semi-ui-react';
const Step = Steps.Step;
```

Steps 把每个子元素按顺序当作一个步骤位置（文本除外），fill 的列宽按它计数。自行封装的 Step 组件把属性透传给 Steps.Step 即可正常编号，不需要声明静态属性；原生元素只占序号、原样渲染。

</Framework>

<Framework only="vue">

```vue
<script setup lang="ts">
    import { Steps } from '@fibrae/semi-ui-vue';
</script>
```

`Steps.Step` 也可以按名导入：`Step`。Step 的 `title`、`description`、`icon` 是插槽（`#title`、`#description`、`#icon`）。Steps 只识别直接子节点中的 Steps.Step，其他子节点不渲染、不占序号，开发环境给出警告；Step 在 Steps 之外不渲染任何内容。

</Framework>

<Framework only="solid">

```jsx
import { Steps } from '@fibrae/semi-ui-solid';
```

只有 Steps.Step 占一个步骤位置；其他子节点（包括原生元素与文本）不渲染、不占序号，开发环境给出警告。Step 在 Steps 之外不渲染任何内容。

</Framework>

### 导航步骤条

通过设置 type="nav" 显示为导航风格步骤条。导航风格的步骤条有以下特点：

1. 步骤条同样支持交互：Steps 监听步骤切换或 Step 绑定点击回调后，步骤可聚焦、可点击，行为与其他类型一致。

2. 适用于步骤间互相关联较小，内容互不影响，且需要突出页面视觉元素时使用。

3. 步骤条的宽度按照内容物撑开。

4. Steps.Step 只渲染标题，`description`、`icon`、`status` 不生效；其余属性与事件（`aria-label`、`role`、点击与键盘回调、类名与样式等）与其他类型相同。

### onChange 回调

<Framework only="react">

可以使用 onChange 来实现处理进度。onChange 接收一个 number 类型的参数，等于 initial 加所选步骤的索引；点击当前步骤不会触发。

</Framework>

<Framework only="vue">

通过 `@change` 监听步骤切换（Steps 的 `onChange` 是函数 prop，监听与否决定步骤是否可点击），回调接收一个 number 类型的参数，等于 initial 加所选步骤的索引；点击当前步骤不会触发。`current` 也支持 `v-model:current`，绑定后所有步骤同样变为可点击。

</Framework>

<Framework only="solid">

通过 `onChange` 监听步骤切换，回调接收一个 number 类型的参数，等于 initial 加所选步骤的索引；点击当前步骤不会触发。传入 `onChange` 后所有步骤变为可点击。

</Framework>

## Accessibility

### ARIA

- Steps、Step 组件支持传入 `aria-label` 或 `aria-labelledby`。Steps 根元素与不可点击的 Step 本身没有语义角色，传入名称时带 `role="group"`，名称因此能进入可访问名称；没有名称时不加 `role`。fill、basic、nav 三种类型一致
- 当前步骤带有 `aria-current="step"`，其余步骤不带该属性
- Steps 监听步骤切换或 Step 绑定点击回调后，步骤可通过 Tab 聚焦，`role` 默认为 `button`（优先于 `group`，显式传入的 `role` 优先于二者）；焦点在步骤上时按 `Enter` 或空格与鼠标点击一致，同时触发 Step 的点击回调与 Steps 的切换回调；不可点击的步骤不可聚焦
- 点击来自步骤内其他可聚焦元素（`input`、`button`、链接等）时只触发 Step 的点击回调，不触发 Steps 的切换回调。可点击的步骤本身是 `role="button"`，title、description 中放可聚焦控件会形成嵌套交互元素，此时不要让步骤可点击

### Steps

整体步骤条。

<Framework only="react">

<StepsReactApi />

</Framework>

<Framework only="vue">

<StepsVueApi />

</Framework>

<Framework only="solid">

<StepsSolidApi />

`class`、`style`、`ref` 与其他原生属性落在 Steps 根元素上。

</Framework>

### Steps.Step

步骤条内的每一个步骤。

<Framework only="react">

<StepReactApi />

`aria-label`、`role`、`onKeyDown` 与其他原生属性落在步骤项（根元素）上。`role` 在步骤可点击时默认为 `button`，显式传入时优先；`onKeyDown` 任意按键都会调用。步骤可点击时，焦点在步骤项上按 `Enter` 或空格等同于点击。

</Framework>

<Framework only="vue">

<StepVueApi />

`class`、`style`、`aria-*`、`role`、`tabindex` 与 `@click`、`@keydown` 等原生属性和事件经 attrs 落在 Step 的根元素上。使用方的 `@click` 让该 Step 可点击；Steps 的 `onChange` 先于 Step 自身的 `@click` 执行。`tabindex` 可由使用方覆盖。

</Framework>

<Framework only="solid">

<StepSolidApi />

`class`、`style`、`aria-*` 与原生事件（如 `onClick`、`onKeyDown`）落在 Step 的根元素（步骤项）上。`role` 由步骤是否可点击决定，传入时优先；`tabindex` 同样由步骤是否可点击决定，不能覆盖。

</Framework>
