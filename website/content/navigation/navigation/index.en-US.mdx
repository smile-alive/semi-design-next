### Basic Usage

By passing `items` Parameters, you can quickly get a navigation bar.

<Framework only="react">

Each navigation item includes:

- `itemKey`: The unique identity of the navigation project (must)
- `text`: Navigation copywriting
- `icon`: Navigation icon, which you can pick from `@fibrae/semi-icons-react` and `@fibrae/semi-icons-react/lab`, see the [Icon documentation](/en-US/react/basic/icon)

</Framework>

<Framework only="vue">

Each navigation item includes:

- `itemKey`: The unique identity of the navigation project (must)
- `text`: Navigation copywriting

`items` holds data only. Icons are provided through the `#icon="{ item, level }"` scoped slot of Nav, and you can pick them from `@fibrae/semi-icons-vue` and `@fibrae/semi-icons-vue/lab`, see the [Icon documentation](/en-US/react/basic/icon).

</Framework>

<Framework only="solid">

Each navigation item includes:

- `itemKey`: The unique identity of the navigation project (must)
- `text`: Navigation copywriting

`items` holds data only. Icons are provided through `renderItemIcon({ item, level })` of Nav, and you can pick them from `@fibrae/semi-icons-solid` and `@fibrae/semi-icons-solid/lab`, see the [Icon documentation](/en-US/react/basic/icon). The shown text and the toggle and expand arrows come from `renderItemText`, `renderItemToggleIcon` and `renderItemExpandIcon` in the same way, called only when the item is shown.

</Framework>

<Framework only="svelte">

- `itemKey`: Unique identifier of the navigation item (required)
- `text`: Navigation copywriting

`items` holds data only. Icons are provided through the `icon` snippet of Nav, whose parameter is `{ item, level, size }`; pass `size` to the icon: `<Icon {size} />`. You can pick icons from `@fibrae/semi-icons-svelte` and `@fibrae/semi-icons-svelte/lab`, see the [Icon documentation](/en-US/react/basic/icon). The shown text and the toggle and expand arrows come from the `text`, `toggleIcon` and `expandIcon` snippets in the same way.

</Framework>

For the meaning of the parameters, see [Nav.Item](#Nav.Item) Or [Nav.Sub](#Nav.Sub)

Developers may often define the Logo area and the put away button area, while Navigation provides such a container for developers to quickly define the navigation head and bottom, and you only need to pass in the `header` or `footer` as required.

For `footer`, semi-ui extra encapsulates a pull-up feature button that developers can pass through `collapseButton = true` to turn on the function, but the parameter takes effect only with `mode = "vertical"` (Vertical navigation).

<Framework only="vue">

`header` and `footer` accept data only. Nodes such as the logo are provided through the `#logo` slot of `<Nav.Header>` and the `#header` and `#footer` slots of Nav.

</Framework>

<Framework only="solid">

The configuration objects of `header` and `footer` hold data only: `logo` is a render function returning the logo, such as `logo: () => <IconSemiLogo />`, called only when shown, and `text` is a string or number. For other nodes, pass JSX directly or use Nav.Header and Nav.Footer children.

</Framework>

<Framework only="svelte">

`header` and `footer` can be a data configuration or a snippet. A configuration object holds data only, and the `logo` of `header` is a snippet. For other nodes, use `NavHeader` and `NavFooter` inside a snippet (they are not picked up from the children of Nav).

</Framework>

For the parameters, see [Nav.Header](#Nav.Header) and [Nav.Footer](#Nav.Footer).

### JSX Writing

Users can use JSX to define navigation headers, navigation items, and navigation bottoms. Nav collects the elements that carry `itemKey` (recursing into their children) to open the ancestors of the default selected items and mark the top-level parent as selected. A component that wraps a navigation item takes part as long as it passes `itemKey` and its other props on to Nav.Item or Nav.Sub; no static property is needed.

</Framework>

<Framework only="vue">

### Template Writing

Users can use templates to define navigation headers, navigation items, and navigation bottoms. Besides Nav.Header, Nav.Item, Nav.Sub and Nav.Footer, the default slot of Nav also accepts other custom elements. Nodes such as icons and the logo are provided through slots of the child components, such as `#icon` and `#logo`.

</Framework>

<Framework only="solid">

### JSX Writing

Users can use JSX to define navigation headers, navigation items, and navigation bottoms. Besides Nav.Header, Nav.Item, Nav.Sub and Nav.Footer, the children of Nav can also hold other custom JSX elements; they are wrapped in a `li` of the list. Nav collects the items that carry `itemKey` from Nav.Item and Nav.Sub, to open the ancestors of the default selected items and mark the top-level parent as selected. A component that wraps a navigation item takes part by returning a Nav.Item or Nav.Sub; no static property is needed.

</Framework>

<Framework only="svelte">

### Children Writing

`NavItem` and `SubNav` can be written as the children of Nav, and the head and bottom as `header` and `footer` snippets that hold `NavHeader` and `NavFooter`. Icons are provided through the `icon` snippet of each child component, and the text snippet is named `label` (it corresponds to the `text` slot of Vue and is renamed because it shares its name with the `text` prop). The children read their parent through context. This form does not open the ancestors of the selected item automatically, and a top-level Sub gets no selected mark; use `items` when you need either.

</Framework>

### Use router lib

<Framework only="react">

In order to use routing components such as react-router, NavItem can be wrapped in the Link or NavLink provided by the routing component to let users click NavItem to trigger the routing component. We need to customize rendering.

Use renderWrapper to customize navigation components in each navigation item. [See CodeSandBox demo](https://codesandbox.io/s/semi-navigation-with-react-router-9kk9dm?file=/src/App.js)

```jsx
import { Link } from 'react-router-dom';

() => {
    return (
        <Nav
            renderWrapper={({ itemElement, isSubNav, isInSubNav, props }) => {
                const routerMap = {
                    Home: '/',
                    About: '/about',
                    Dashboard: '/dashboard',
                    'Nothing Here': '/nothing-here',
                };
                return (
                    <Link style={{ textDecoration: 'none' }} to={routerMap[props.itemKey]}>
                        {itemElement}
                    </Link>
                );
            }}
            items={[
                { itemKey: 'Home', text: 'Home' },
                { itemKey: 'About', text: 'About' },
                {
                    text: 'Sub',

                    itemKey: 'Sub',
                    items: ['Dashboard', 'Nothing Here'],
                },
            ]}
        ></Nav>
    );
};
```

</Framework>

<Framework only="vue">

In order to use routing components such as vue-router, Nav.Item can be wrapped in the RouterLink provided by the routing component to let users click an item to trigger the routing component. We need to customize rendering.

Use the `#wrapper="{ itemElement, isSubNav, isInSubNav, props }"` scoped slot to wrap each navigation item in a custom component, and mount the `li` of the item with `<component :is="itemElement" />`.

```vue
<script setup lang="ts">
    import { RouterLink } from 'vue-router';
    import { Nav } from '@fibrae/semi-ui-vue';

    const routerMap = {
        Home: '/',
        About: '/about',
        Dashboard: '/dashboard',
        'Nothing Here': '/nothing-here',
    };
    const items = [
        { itemKey: 'Home', text: 'Home' },
        { itemKey: 'About', text: 'About' },
        { itemKey: 'Sub', text: 'Sub', items: ['Dashboard', 'Nothing Here'] },
    ];
</script>

<template>
    <Nav :items="items">
        <template #wrapper="{ itemElement, props }">
            <RouterLink :to="routerMap[props.itemKey as keyof typeof routerMap]" style="text-decoration: none">
                <component :is="itemElement" />
            </RouterLink>
        </template>
    </Nav>
</template>
```

</Framework>

<Framework only="solid">

In order to use routing components such as `@solidjs/router`, a navigation item can be wrapped in the link provided by the routing component, so that clicking the item triggers a route change. We need to customize rendering.

Use `renderWrapper` to wrap each navigation item in a custom component. `itemElement` is the `li` of the item and must be rendered exactly once.

```jsx
import { A } from '@solidjs/router';
import { Nav } from '@fibrae/semi-ui-solid';

const routerMap = {
    Home: '/',
    About: '/about',
    Dashboard: '/dashboard',
    'Nothing Here': '/nothing-here',
};

export default function RouterNav() {
    return (
        <Nav
            renderWrapper={({ itemElement, props }) => (
                <A href={routerMap[props.itemKey as keyof typeof routerMap]} style={{ 'text-decoration': 'none' }}>
                    {itemElement}
                </A>
            )}
            items={[
                { itemKey: 'Home', text: 'Home' },
                { itemKey: 'About', text: 'About' },
                { itemKey: 'Sub', text: 'Sub', items: ['Dashboard', 'Nothing Here'] },
            ]}
        />
    );
}
```

</Framework>

<Framework only="svelte">

To wrap navigation items in links when using a router such as SvelteKit, so that clicking an item triggers navigation, customize the rendering.

Use the `wrapper` snippet to wrap each item in a custom element. `itemElement` is the `li` of the item; render it with `{@render itemElement()}`, exactly once.

```svelte
<script lang="ts">
    import { Nav } from '@fibrae/semi-ui-svelte';

    const routerMap = {
        Home: '/',
        About: '/about',
        Dashboard: '/dashboard',
        'Nothing Here': '/nothing-here',
    };
    const items = [
        { itemKey: 'Home', text: 'Home' },
        { itemKey: 'About', text: 'About' },
        { itemKey: 'Sub', text: 'Sub', items: ['Dashboard', 'Nothing Here'] },
    ];
</script>

<Nav {items}>
    {#snippet wrapper({ itemElement, props })}
        <a href={routerMap[props.itemKey as keyof typeof routerMap]} style="text-decoration: none">
            {@render itemElement()}
        </a>
    {/snippet}
</Nav>
```

</Framework>

### Controlled Properties

<Framework only="react">

The Navigation component provides several controlled properties that, combined with a variety of callbacks, can easily control navigation.

The properties currently controlled are:

- `isCollapsed`(whether the sidebar is closed, effective only when `mode="vertical"`)
- `selectedKeys` (currently selected navigation item `key` array)
- `openKeys` (currently expanded array of navigation items, only `mode="vertical"` and `isCollapsed=false` valid)

The corresponding callback is:

- `onCollapseChange(isCollapsed: boolean) => void`
- `onSelect ({ itemKey: string, selectedKeys: string[], domEvent: MouseEvent | KeyboardEvent }) => void`
- `onOpenChange ({ itemKey: string, openKeys: string[], domEvent?: MouseEvent | KeyboardEvent, isOpen: boolean }) => void`

</Framework>

<Framework only="vue">

The Navigation component provides several controlled properties. Use `v-model` to control navigation easily, optionally together with events.

The properties currently controlled are:

- `v-model:isCollapsed` (whether the sidebar is closed, effective only when `mode="vertical"`)
- `v-model:selectedKeys` (currently selected navigation item `key` array, containing the selected item only)
- `v-model:openKeys` (currently expanded array of navigation items, only `mode="vertical"` and `isCollapsed=false` valid)

The corresponding events are:

- `@collapseChange(isCollapsed: boolean)`
- `@select({ itemKey: string, selectedKeys: string[], domEvent: MouseEvent | KeyboardEvent })`
- `@openChange({ itemKey: string, openKeys: string[], domEvent?: MouseEvent | KeyboardEvent, isOpen: boolean })`

In horizontal or collapsed mode, opening a submenu on hover also emits `update:openKeys`, and the popup is not controlled by `openKeys`.

</Framework>

<Framework only="solid">

The Navigation component provides several controlled properties. Combined with callbacks, they can easily control navigation.

The properties currently controlled are:

- `isCollapsed` (whether the sidebar is collapsed, effective only when `mode = "vertical"`)
- `selectedKeys` (currently selected navigation item `key` array)
- `openKeys` (currently expanded array of navigation items, valid only when `mode = "vertical"` and `isCollapsed = false`)

The corresponding callbacks are:

- `onCollapseChange(isCollapse: boolean): void`
- `onSelect({ itemKey, selectedKeys, selectedItems, domEvent }): void`
- `onOpenChange({ itemKey, openKeys, domEvent, isOpen }): void`

<Framework only="svelte">

The Navigation component provides several bindable properties. Use `bind:` to control the navigation easily, and combine it with callbacks if needed.

The bindable properties are:

- `bind:isCollapsed` (whether the sidebar is collapsed, effective only when `mode = "vertical"`)
- `bind:selectedKeys` (currently selected navigation item `key` array, holding only the selected item itself)

</Framework>

## Accessibility

### ARIA

Navigation follows the WAI-ARIA APG [Disclosure Navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) example and does not use the `menu` role.

- The root element is a `nav` (navigation landmark). When a page has several Navigations, give each a different `aria-label`, such as "Top navigation" and "Side navigation"
- The items are a plain `ul` / `li` list. Header and Footer are outside the list; other children that are not items are wrapped in a `li` that renders no box
- A Nav.Item with `link` is a link (`a href`), any other Nav.Item is a native `button`. The selected item has `aria-current="page"`, a disabled item has `aria-disabled="true"`
- In the expanded vertical mode, the title of a Nav.Sub is a native `button` with `aria-expanded` telling whether its list is shown and `aria-controls` pointing to that list
- In horizontal and collapsed mode, the title of a Nav.Sub is a menu button with `aria-haspopup="menu"` and an `aria-expanded` that follows the popup. The popup is a `menu` whose items are `menuitem`s; the selected one has `aria-current="page"`
- `aria-*` passed to Nav.Item or Nav.Sub land on the link or button that takes focus, other undeclared props on the `li`
- When the Nav is collapsed, the link of Nav.Header is named by its `text`

### Keyboard and Focus

- Every item and every inline sub title is a `Tab` stop; `Tab` and `Shift + Tab` move between them. Items in a closed sub are not in the Tab sequence
- On an item, `Enter` follows its link; an item without `link` is selected with `Enter` or `Space`
- On the title of an inline sub, `Enter` or `Space` expands or collapses its list
- In collapsed mode, a focused top level item shows its text in a Tooltip, which also describes the item
- The title of a sub in horizontal or collapsed mode:
    - Opens its popup when it gets focus (hover trigger); `Down Arrow` and `Up Arrow` move focus to the first and last item of the menu
    - In the menu, `Up Arrow`, `Down Arrow`, `Home` and `End` move focus, `Enter` or `Space` selects an item, `Right Arrow` opens a nested submenu and `Left Arrow` closes it and returns to the parent item (swapped on RTL pages)
    - `Esc` closes the current menu and returns focus to the title that opened it; `Tab` closes all menus and moves focus as usual

## FAQ

<Framework only="react">

- **Lost animation in navigation bar?**

    When using functional components, you should give items with useState or useMemo, because passing an array directly to items will trigger component rerendering.

</Framework>

<Framework only="vue">

- **Lost animation in navigation bar?**

    Do not write a `:items="[...]"` literal in the template: the parent creates a new array on every render, which rebuilds the navigation and resets the uncontrolled selection to `defaultSelectedKeys`. Define items at the top level of `script setup`, or in a `ref` or `computed`.

</Framework>

<Framework only="solid">

- **Lost animation in navigation bar?**

    When a signal read inside `items` changes, every navigation item is created again, so focus is lost. Only let the data that really changes pass through a signal, and keep frequently updated signals out of `items`.

</Framework>

- **Lost item when subNav is too height >=999px ?** Please refer to [this issue](https://github.com/DouyinFE/semi-design/issues/563)
