### Basic Usage

Tabs supports four types of styles: `line`, `button`, `card`, and `slash`. By default, the first enabled tab is selected.

Tabs supports two declare ways, and the rendering process of the two is different:

- Pass the array of objects through `tabList`, when using `tabList`, only render the currently passed node each time
- Or use `<TabPane>` to explicitly pass in item by item. When using `<TabPane>`, all panels will be rendered by default. You can set `keepDOM` to `false` to only render the current panel, and there will be no animation effect at this time.

<Notice title='Notice'>

1. When tabList and TabPane Children are used at the same time, the data passed in through tabList will be rendered first. It is not recommended to configure both
2. When using TabPane Children, TabPane must be a direct child element of Tabs, otherwise Tabs will not be able to correctly collect related attributes such as itemKey and other subcomponents

</Notice>

<Framework only="vue">

In Vue the text of a tab goes in the `#tab` slot of `<TabPane>` and its icon in the `#icon` slot. The items of `tabList` hold data only (`itemKey`, `tab`, `disabled`, `closable`); for markup use the `#tab` and `#icon` scoped slots of Tabs, which receive `{ item, index }`. Without a slot the `tab` text of the item is shown. Any array, even an empty one, makes the default slot the content of the active tab instead of TabPanes.

</Framework>

<Framework only="solid">

The items of `tabList` hold data only (`itemKey`, `tab`, `disabled`, `closable`); for markup use `renderTab` and `renderIcon` of Tabs, which receive the item and its index. Without `renderTab` the `tab` text of the item is shown. The render functions are called once at each place the tab shows (the tab, a "more" menu item, the panel's name) and again only when the item's data or index changes.

</Framework>

### Auto Overflow Detection

Set `collapsible="auto"` to enable automatic overflow detection. The component will automatically detect whether tabs overflow the container:

- When tabs exceed the container width or wrap to multiple lines, it automatically enables collapse mode (shows left/right arrows)
- When the container width increases or tab count decreases and all tabs can be fully displayed, it automatically exits collapse mode

This feature eliminates the need for developers to manually determine whether folding is needed, making it especially suitable for responsive layouts.

### Custom Render

<Framework only="react">

Use `renderTabBar` to customize tabBar render behavior.

</Framework>

<Framework only="vue">

Use the `#tabBar="{ tabBarProps, tabBar }"` scoped slot to customize the tab bar. `tabBarProps` holds data only (see TabBarProps below) and `tabBar` is the default tab bar node, rendered with `<component :is="tabBar" />`.

When `#tabBar` replaces the bar entirely, the `aria-label` and `aria-labelledby` of Tabs do not reach your own element: put the accessible name on your own `role="tablist"` element. The entries of `tabBarProps.list` carry the `tab` text only when the `#tab` slot of the TabPane is plain text.

</Framework>

<Framework only="solid">

Use `renderTabBar` to customize tabBar render behavior; the same function is called once. `tabBarProps` is live, so read its fields inside the returned JSX; `DefaultTabBar` is the default tab bar component, rendered with `<DefaultTabBar {...tabBarProps} />`.

When `renderTabBar` replaces the bar entirely, the `aria-label` and `aria-labelledby` of Tabs are in `tabBarProps` and do not reach your own element automatically: put the accessible name on your own `role="tablist"` element. `activeKey` is used with `v-model:activeKey`. `aria-label` and `aria-labelledby` land on the `role="tablist"` element; `class`, `style` and other native attributes land on the root element.

**PlainTab**

The data item of `tabList`; it holds data only.

| Property | Description                                        | Type             | Default Value |
| -------- | -------------------------------------------------- | ---------------- | ------------- |
| itemKey  | Unique key of the tab, matched against `activeKey` | string           | None          |
| tab      | Tab text; the `#tab` slot takes precedence         | string \| number | None          |
| disabled | Whether the tab is disabled                        | boolean          | None          |
| closable | Whether the tab can be closed                      | boolean          | None          |

**TabsMore**

The shape of `more` when it is an object.

| Property      | Description                                  | Type                  | Default Value |
| ------------- | -------------------------------------------- | --------------------- | ------------- |
| count         | Number of Tabs moved into the drop-down menu | number                | None          |
| dropdownProps | Dropdown props passed through to the menu    | TabsDropdownItemProps | None          |

`TabsDropdownItemProps` is the props of Dropdown plus `class`, `style` and `onVisibleChange`. The `start` and `end` of `dropdownProps` use the same type.

**TabBarProps**

The `tabBarProps` of the `#tabBar` slot, the data of the default tab bar.

| Property           | Description                                                                | Type                                    |
| ------------------ | -------------------------------------------------------------------------- | --------------------------------------- |
| activeKey          | The active itemKey; null for a controlled empty value                      | string \| null                          |
| list               | Tab data; `tab` is present only when the `#tab` of a TabPane is plain text | PlainTab[]                              |
| type               | Style of the tab bar                                                       | 'line' \| 'card' \| 'button' \| 'slash' |
| size               | Size                                                                       | 'small' \| 'medium' \| 'large'          |
| tabPosition        | Position                                                                   | 'top' \| 'left'                         |
| collapsible        | Whether collapsible                                                        | boolean \| 'auto'                       |
| showRestInDropdown | In collapsible mode, whether collapsed tabs are listed in a dropdown       | boolean                                 |
| more               | Configuration of the More menu                                             | number \| TabsMore                      |
| arrowPosition      | Position of the arrows in collapsible mode                                 | 'both' \| 'start' \| 'end'              |
| visibleTabsStyle   | Style of the whole scrolling area in collapsible mode                      | StyleValue                              |
| dropdownProps      | Dropdown props of the arrow menus in collapsible mode                      | TabsDropdownProps                       |
| class              | tabBarClassName                                                            | string                                  |
| style              | tabBarStyle                                                                | StyleValue                              |

</Framework>

## Accessibility

### ARIA

- About role
    - The element in TabBar that holds only the Tabs has a role of `tablist`; the scroll arrows, the "more" trigger and `tabBarExtraContent` sit outside it
    - Tab in TabBar has a role of `tab`
    - TabPane has a role of `tabpanel`
- aria-label, aria-labelledby: When passed to Tabs they land on the `role="tablist"` element and name the tab bar
- aria-orientation: Indicates TabBar's orientation, can be `vertical` or `horizontal`. When tabPosition is `left`,aria-orientation will be `vertical`, when tabPosition is `top`, aria-orientation will be `horizontal`.
- aria-disabled: When TabPane is disabled, the related Tab's aria-disabled will be set to true.
- aria-selected: Indicates whether the Tab is selected.
- aria-controls: Indicates the TabPane controlled by the Tab; when only the active tab's panel is in the document (with `tabList`, or with `keepDOM` set to false), only the selected Tab carries it
- aria-labelledby: Indicates the element labels the TabPane

### Keyboard and Focus

WAI-ARIA: https://www.w3.org/WAI/ARIA/apg/patterns/tabpanel/

- Tabs can be given focus, except for disabled tabs
- Keyboard users can use the `Tab` key to move the focus to the tab panel of the selected tab element
- Use `left and right arrows` to toggle options when focus is on a tab element in a horizontal tab list (the two arrows swap in an RTL page)
- Use `up and down arrows` to toggle options when focus is on a tab element in a vertical tab list
- When the focus is on an inactive tab element in the tab list, the `Space` or `Enter` keys can be used to activate the tab
- When keyboard users want to focus directly on the last tab element in the tab list:
    - Mac users: `fn` + `right arrow`
    - Windows users: `End`
- When keyboard users want to focus directly on the first tab element in the tab list:
    - Mac users: `fn` + `left arrow`
    - Windows users: `Home`
- With `more`, the default "More" trigger is a native `button`: focus it with `Tab`, open the dropdown with `Enter` or `Space`; it carries `aria-haspopup="menu"` and `aria-expanded`
- When a tab is allowed to be deleted:
    - Users can use the `Delete` or `Backspace` key to delete a tab, except a disabled one
    - After deletion, the focus is transferred to the next element of the deleted tab element; if the deleted element has no subsequent element, it is transferred to the previous element

## FAQ

- **Why typography with ellipses in Tabs doesn't work?**

    Because when Tabs renders TabPane, the default is to render display: none. At this point these components cannot get the correct width or height values. It is recommended to enable lazyRender in or disable keepDOM.

- **Why are the height or width values ​​wrong when using components such as Collapse/Collapsible/Resizable Table in Tabs?**

    The reason is the same as above. In addition, if the collapse does not need animation, you can also turn off the animation effect by setting its `motion` to false. There is no need to get the height of the component at this point。
