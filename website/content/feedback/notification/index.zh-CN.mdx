### 如何引入

<Framework only="react">

```jsx
import { Notification } from '@fibrae/semi-ui-react';
```

</Framework>

<Framework only="vue">

```vue
<script setup lang="ts">
    import { Notification } from '@fibrae/semi-ui-vue';
</script>
```

静态方法在组件树之外渲染。可选 `app.use(Notification)`：安装后静态通知用该 app 的上下文渲染，可以读到 `app.provide()` 的值和全局注册的组件；Toast、Notification、Modal 的静态方法共用这一记录，安装其中任何一个即对三者生效，多个 app 都安装时以最后一次为准。

</Framework>

<Framework only="solid">

```jsx
import { Notification } from '@fibrae/semi-ui-solid';
```

静态方法在组件树之外渲染，读取 `Notification.config()` 与全局默认值以及默认语言包，不继承所在位置的 ConfigProvider 与 LocaleProvider；需要读取时改用 `Notification.useNotification()`。

</Framework>

### 消费 Context

<Framework only="react">

通过 `Notification.useNotification` 创建支持读取 context 的 contextHolder，通知渲染在 contextHolder 所在的节点处，进场、离场动画与静态方法相同。

</Framework>

<Framework only="vue">

通过 `Notification.useNotification()` 创建支持读取 context 的 Holder，通知渲染在 `<Holder />` 所在的节点处，继承该位置的 provide、ConfigProvider 和语言，进场、离场动画与静态方法相同。`content`、`icon`、`title` 传函数时，函数在通知内部作为函数式组件渲染，里面可以 `inject`。

</Framework>

<Framework only="solid">

通过 `Notification.useNotification()` 创建 `contextHolder`，并把它放在需要继承上下文的位置。hook 须在该位置的 Provider 之下调用：通知渲染在 `contextHolder` 所在的节点处，继承那里的 context、ConfigProvider 和语言，进场、离场动画与静态方法相同。`content`、`icon`、`title` 传函数时，函数在通知内部渲染，可以读取该位置的 context；事件处理函数中创建的 JSX 没有所属组件，读不到 context。

</Framework>

## API 参考

组件提供的静态方法，使用方式如下：

展示：可以直接传入 options 对象，返回值为`id`：`const id = Notification.open({ /*...options*/ })`

- `Notification.open({content: 'message', duration: 3})`
- `Notification.info({content: 'message', duration: 3})`
- `Notification.error({content: 'message', duration: 3})`
- `Notification.warning({content: 'message', duration: 3})`
- `Notification.success({content: 'message', duration: 3})`

手动关闭 （id 为展示方法的返回值）

- `Notification.close(id)`

<Framework only="react">

- `Notification.useNotification()`  
  当你需要使用 Context 时，可以通过 Notification.useNotification 创建一个 contextHolder 插入相应的节点中。此时通过 hooks 创建的 Notification 将会得到 contextHolder 所在位置的所有上下文。创建的 notification 对象拥有以下方法：`info`、`success`、`warning`、`error`、`open`、`close`；前五个接收不含 `type`、`id`、`zIndex`、`getPopupContainer` 的选项，返回通知 id。hooks 创建的通知使用内置默认值，不受 `Notification.config()` 影响；`close(id)` 播放离场动画后移除通知，不触发 `onClose`。contextHolder 外包一层带 `data-semi-keep-interactive` 的容器，模态层打开时 hook 通知仍可交互。

</Framework>

<Framework only="vue">

- `Notification.useNotification()`  
  返回元组 `[notification, Holder]`，把 `<Holder />` 放进相应的节点中。此时通过 hook 创建的通知将会得到 `<Holder />` 所在位置的所有上下文。notification 对象拥有以下方法：`info`、`success`、`warning`、`error`、`open`、`close`；前五个接收不含 `type`、`id`、`zIndex`、`getPopupContainer` 的选项，返回通知 id，`close(id)` 手动关闭。hook 创建的通知使用内置默认值，不受 `Notification.config()` 影响；`close(id)` 播放离场动画后移除通知，不触发 `onClose`。`<Holder />` 外包一层带 `data-semi-keep-interactive` 的容器，模态层打开时 hook 通知仍可交互。ConfigProvider、LocaleProvider 是组件级 provide，静态 `Notification` 读不到它们，需要时改用 `useNotification()`。

</Framework>

<Framework only="solid">

- `Notification.useNotification()`  
  返回元组 `[notification, contextHolder]`，把 `contextHolder` 放进相应的节点中，此时通过 hook 创建的通知将会得到 `contextHolder` 所在位置的所有上下文。notification 对象拥有以下方法：`info`、`success`、`warning`、`error`、`open`、`close`；前五个接收不含 `type`、`id`、`zIndex`、`getPopupContainer` 的选项，返回通知 id，`close(id)` 手动关闭。hook 创建的通知使用内置默认值与全局默认值，不受 `Notification.config()` 影响；`close(id)` 播放离场动画后移除通知，不触发 `onClose`。`contextHolder` 外包一层带 `data-semi-keep-interactive` 的容器，模态层打开时 hook 通知仍可交互。

## Accessibility

### ARIA

- 通知的 `role` 按类型区分：`warning`、`error` 为 `alert`，`info`、`success` 与 `open` 为 `status`
- `status` 类通知由列表常驻的 `aria-live="polite"` 播报区朗读，通知自身为 `aria-live="off"`，只播报标题与内容的文本；`warning`、`error` 仍由 `alert` 自行播报
- 通知的 `aria-labelledby` 标记为对应通知标题

### 键盘和焦点

- 关闭按钮是原生 `button`，可以用 `Tab` 聚焦，`Enter` 或 `Space` 触发关闭
- 通知出现时不会抢走焦点
- 指针或键盘焦点进入通知时暂停自动关闭的计时，并展开堆叠；移出后恢复计时

- 标题
    - 使用简洁明了的语言进行说明
    - 避免使用逗号，句号等标点符号
- 正文
    - 在信息传递完整的前提下，尽可能地将正文压缩至 1 -2 句话
    - 对标题进行详尽地描述或者解释，而不是对标题的重复说明
    - 使用正确的标点符号，句子内使用逗号，句子间使用句号
- 操作
    - 文案需要展示操作的具体含义
