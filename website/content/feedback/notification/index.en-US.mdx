## Demos

### How to import

<Framework only="react">

```jsx
import { Notification } from '@fibrae/semi-ui-react';
```

</Framework>

<Framework only="vue">

```vue
<script setup lang="ts">
    import { Notification } from '@fibrae/semi-ui-vue';
</script>
```

Static methods render outside the component tree. Optionally call `app.use(Notification)`: static notifications then render with that app's context, so they can read values from `app.provide()` and globally registered components. The static methods of Toast, Notification and Modal share this record, so installing any one of them applies to all three; when several apps install, the last one wins.

</Framework>

<Framework only="solid">

```jsx
import { Notification } from '@fibrae/semi-ui-solid';
```

Static methods render outside the component tree. They read `Notification.config()`, the global defaults and the default locale, and do not inherit the ConfigProvider or LocaleProvider of their position; use `Notification.useNotification()` when you need those.

</Framework>

### Consume Context

<Framework only="react">

Use `Notification.useNotification` to create a contextHolder that can access context. Notifications render where the contextHolder is placed and enter and leave with the same animations as the static methods.

</Framework>

<Framework only="vue">

Use `Notification.useNotification()` to create a Holder that can access context. Notifications render where `<Holder />` is placed, inherit the provides, ConfigProvider and locale there, and enter and leave with the same animations as the static methods. A function passed as `content`, `icon` or `title` is rendered as a functional component inside the notification, so it can `inject`.

</Framework>

<Framework only="solid">

Use `Notification.useNotification()` to create a `contextHolder` and place it where the context should be inherited. Call the hook below the Provider you need: notifications render where `contextHolder` is placed, inherit the context, ConfigProvider and locale there, and enter and leave with the same animations as the static methods. A function passed as `content`, `icon` or `title` is rendered inside the notification and can read the context of that position; JSX created in an event handler has no owner, so it cannot read context.

</Framework>

## API Reference

The static methods provided are as follows:

Display: You can pass in options object directly. Methods return the value of `id`: `const id = Notification.open({ /*...options*/ })`

- `Notification.open({content: 'message', duration: 3})`
- `Notification.info({content: 'message', duration: 3})`
- `Notification.error({content: 'message', duration: 3})`
- `Notification.warning({content: 'message', duration: 3})`
- `Notification.success({content: 'message', duration: 3})`

Close Manually (`id` is the return value of the display methods)

- `Notification.close(id)`

The global configuration is set before any method call, and takes effect only once:

- `Notification.config(config)`
- `Notification.resetConfig()` restores the global configuration to its defaults; only notifications shown afterwards are affected

`Notification.config` does not accept `direction`; text direction is an option of a single notification only.

Hook Notification

<Framework only="react">

- `Notification.useNotification()`  
  When you need access Context, you could use `Notification.useNotification` to create a `contextHolder` and insert to corresponding DOM tree. Notification created by hooks will be able to access the context where `contextHolder` is inserted. Hook Notification has following methods: `info`, `success`, `warning`, `error`, `open`, `close`; the first five take options without `type`, `id`, `zIndex` and `getPopupContainer`, and return the notification id. Notifications created by hooks use the built-in defaults and ignore `Notification.config()`; `close(id)` removes the notification after its leave animation without calling `onClose`. The contextHolder is wrapped in a container with `data-semi-keep-interactive`, so hook notifications stay interactive while a modal layer is open.

</Framework>

<Framework only="vue">

- `Notification.useNotification()`  
  Returns a tuple `[notification, Holder]`; place `<Holder />` in the corresponding node. Notifications created by the hook can access the context where `<Holder />` is placed. The notification object has the methods `info`, `success`, `warning`, `error`, `open` and `close`; the first five take the options without `type`, `id`, `zIndex` and `getPopupContainer` and return the notification id, and `close(id)` closes one manually. Notifications created by the hook use the built-in defaults and ignore `Notification.config()`; `close(id)` removes the notification after its leave animation without calling `onClose`. `<Holder />` is wrapped in a container with `data-semi-keep-interactive`, so hook notifications stay interactive while a modal layer is open. ConfigProvider and LocaleProvider are component-level provides that the static `Notification` cannot read; use `useNotification()` when you need them.

</Framework>

## Accessibility

### ARIA

- The `role` of a notification depends on its type: `warning` and `error` are `alert`; `info`, `success` and `open` are `status`
- `status` notifications are read by a persistent `aria-live="polite"` region owned by the list; the notification itself is `aria-live="off"`, and only the text of the title and content is announced. `warning` and `error` still announce themselves as `alert`
- The notification's `aria-labelledby` is marked as the corresponding notification title

### Keyboard and Focus

- The close button is a native `button`: focus it with `Tab`, and activate it with `Enter` or `Space`
- A notification does not take focus when it appears
- When the pointer or keyboard focus enters a notification, its auto-close timer pauses and a stack expands; both resume when it leaves

## Content Guidelines

- Title
    - Explain in clear and concise language
    - Avoid punctuation such as commas, periods, etc.
- Text
    - On the premise of complete information transmission, try to compress the text to 1-2 sentences
    - A detailed description or explanation of the title, rather than a repetition of the title
    - Use correct punctuation, commas within sentences and periods between sentences
- Operate
    - The copy needs to show the specific meaning of the operation
