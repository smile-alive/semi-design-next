### 消费 Context

<Framework only="react">

通过 Toast.useToast 创建支持读取 context 的 contextHolder。此时的 toast 会渲染在 contextHolder 所在的节点处。

`Toast.useToast()` 返回元组 `[toast, contextHolder]`：toast 对象的 `info`、`success`、`warning`、`error`、`open` 接收不含 `type`、`id`、`zIndex`、`getPopupContainer` 的 Options，返回 `toastId`；`close(toastId)` 手动关闭。

</Framework>

<Framework only="vue">

通过 `Toast.useToast()` 创建支持读取 context 的 Holder。此时的 toast 会渲染在 `<Holder />` 所在的节点处，继承该位置的 provide、ConfigProvider 和语言。

`Toast.useToast()` 返回元组 `[toast, Holder]`：toast 对象的 `info`、`success`、`warning`、`error`、`open` 接收不含 `type`、`id` 的 Options，返回 `toastId`；`close(toastId)` 手动关闭。`content`、`icon` 传函数时，函数在 Toast 内部作为函数式组件渲染，里面可以 `inject`。`top`、`zIndex`、`getPopupContainer` 等定位项在 hook 中不生效。ConfigProvider、LocaleProvider 是组件级 provide，静态 `Toast` 读不到它们，需要时改用 `useToast()`。

</Framework>

<Framework only="solid">

通过 `Toast.useToast()` 创建支持读取 context 的 `contextHolder`。此时的 toast 会渲染在 `contextHolder` 所在的节点处，继承该位置的 context、ConfigProvider 和语言；`contextHolder` 在调用 `useToast()` 的 owner 下创建，只放置一次。

`Toast.useToast()` 返回元组 `[toast, contextHolder]`：toast 对象的 `info`、`success`、`warning`、`error`、`open` 接收不含 `type`、`id`、`zIndex`、`getPopupContainer` 的 Options，返回 `toastId`；`close(toastId)` 手动关闭。`content`、`icon` 传元素时，元素在事件处理函数中创建，没有 owner，读不到 context；需要读取 context 时传函数，函数在 Toast 渲染处调用。ConfigProvider、LocaleProvider 的值静态 `Toast` 读不到，需要时改用 `useToast()`。

</Framework>

<Framework only="svelte">

在组件初始化时调用 `Toast.useToast()`，得到的 toast 会读取调用它的组件所在位置的 context、ConfigProvider 和语言，不需要放置 Holder。toast 挂载在 `document.body` 下，调用组件销毁时一并移除。

`Toast.useToast()` 返回 `toast` 对象：`info`、`success`、`warning`、`error`、`open` 接收不含 `type`、`id`、`top`、`bottom`、`left`、`right`、`zIndex`、`getPopupContainer` 的 Options，返回 `toastId`；`close(toastId)` 手动关闭。`content`、`icon` 传 snippet 时，snippet 里可以 `getContext` 读到调用组件的 context。ConfigProvider、LocaleProvider 的值静态 `Toast` 读不到，需要时改用 `useToast()`。

</Framework>

## API 参考

组件提供的静态方法，使用方式和参数如下：展示：可以直接传入 `options` 对象或 `string`：

**全局配置, 在调用前提前配置，全局一次生效**

- `Toast.config(config)`
- `Toast.resetConfig()` 将全局配置恢复为默认值，只影响之后弹出的 Toast。`ToastFactory.create(config)` 创建的实例恢复为创建时传入的 `config`

**直接展示 Toast**

- `Toast.info(options || string)`
- `Toast.error(options || string)`
- `Toast.warning(options || string)`
- `Toast.success(options || string)`

**`info` `error` `warning` `success` 返回值为`toastId`, 可用于手动关闭**

`const toastId = Toast.info({ /*...options*/ })`

- `Toast.close(toastId)` 手动关闭

## Accessibility

### ARIA

- Toast 的 role 按类型区分：`warning`、`error` 为 `alert`，`info`、`success` 与没有 `type` 的为 `status`
- `status` 类 Toast 由列表常驻的 `aria-live="polite"` 播报区朗读，Toast 自身为 `aria-live="off"`，只播报 `content` 的文本；`warning`、`error` 仍由 `alert` 自行播报

### 键盘和焦点

- 关闭按钮是原生 `button`，可以用 `Tab` 聚焦，`Enter` 或 `Space` 触发关闭
- Toast 出现时不会抢走焦点
- 指针或键盘焦点进入 Toast 时暂停自动关闭的计时，并展开堆叠；移出后恢复计时

| ✅ 推荐用法            | ❌ 不推荐用法                            |
| ---------------------- | ---------------------------------------- |
| Language added         | New language has been added successfully |
| Ticket transfer failed | Can't transfer ticket                    |

- 提供动作的提示消息
    - 只提供一个动作
    - 不使用类似于「已读」类的动作，例如 OK, Got it, Dismiss, Cancel

| ✅ 推荐用法                                                                  | ❌ 不推荐用法                                                                  |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
