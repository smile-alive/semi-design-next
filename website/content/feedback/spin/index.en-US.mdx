### useSpinDelay

`useSpinDelay` turns any loading flag into "show the loading effect or not": it shows only once loading has lasted `delay` (500ms by default), then stays for at least `minDuration` (200ms by default). Pass the result to Spin's `spinning`, or use it to switch a skeleton or any other loading UI. In the demo, the 200ms request shows nothing, and the 800ms one shows the spinner for at least 600ms.

<Framework only="react">

Import it from `@fibrae/semi-ui-react/hooks`. The signature is `useSpinDelay(loading, { delay, minDuration, ssr })` and it returns a `boolean`. `loading` can be `isPending` from `useTransition` or `useActionState`, or `pending` from `useFormStatus`.

</Framework>

<Framework only="vue">

Import it from `@fibrae/semi-ui-vue/composables`. The signature is `useSpinDelay(() => loading, () => ({ delay, minDuration, ssr }))` and it returns a readonly `Ref<boolean>`. With `<Suspense>`, record the loading state in its `@pending` and `@resolve` events and pass that in.

</Framework>

<Framework only="solid">

Import it from `@fibrae/semi-ui-solid/primitives`. The signature is `useSpinDelay(loading, () => ({ delay, minDuration, ssr }))` and it returns an `Accessor<boolean>`. `loading` can be the `pending` accessor from `useTransition` or `() => resource.loading`.

</Framework>

<Framework only="svelte">

Import it from `@fibrae/semi-ui-svelte/hooks`. The signature is `useSpinDelay(() => loading, () => ({ delay, minDuration, ssr }))`, and the returned object's `visible` property tells whether to show.

</Framework>

If loading is already true on the first render, the effect shows at once by default: the server cannot wait for `delay`, and hydration must match its output. Inside a Suspense fallback or an async component's loading component, every mount starts loading, so pass `ssr: false` to wait for `delay` there; the framework unmounts the fallback when loading ends, so `minDuration` has no effect in that case.

</Framework>

<Framework only="vue">

<SpinVueApi />

`class`, `style` and native attributes passed as attrs land on the root element.

</Framework>

<Framework only="solid">

<SpinSolidApi />

`class`, `style`, `ref` and native attributes and events land on the root `div` element.

</Framework>

<Framework only="svelte">

<SpinSvelteApi />

`class`, `style` and native attributes and events land on the root `div` element.

</Framework>

While a Spin that wraps content is loading, the wrapped content is `inert`: it cannot be focused or operated, and the root carries `aria-busy`. If focus was inside the wrapped content, it moves to the Spin root first and returns to the original element when loading ends.

## Content Guidelines

- Precisely state the loading status, using words such as "Loading", "Submitting", "Processing", etc.
- Use as few words as possible to describe the state

## FAQ

- **How to modify the color of the spin icon?**

    You can override the original color by adding the color property to the .semi-spin-wrapper class (it is recommended to override with a higher weight).

    ```
    .custom .semi-spin-wrapper {
      color: red;
    }
    ```
