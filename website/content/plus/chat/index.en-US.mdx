## When to use

The `Chat` component can be used in scenarios such as regular conversations or AI conversations.

<Framework only="react">

The rendering of the conversation content is based on the [MarkdownRender](/en-US/react/plus/markdown-render) component, which supports Markdown and MDX (Note: The default format mode of MarkdownRender in Chat is md. If you need to use MDX format, you can set it through the markdownRenderProps API). It allows for common rich text features such as images, tables, links, bold text, code blocks, and more. More complex and customized document writing and display requirements can be achieved using JSX. Register the languages of code blocks with `CodeHighlight.register` of [CodeHighlight](/en-US/react/plus/code-highlight) to highlight them.

</Framework>

The chats type is `Message[]`, where each `Message` contains various information about the conversation, such as role, content, attachment, status, unique identifier (id), creation time (createAt), and more. Each render function is called once per message, and again when the function is replaced. The fields of its argument are getters, so the returned JSX follows the message as it streams. The default nodes are render functions (`defaultTitle`, `defaultAvatar`, `defaultContent`, the items of `defaultNodes`, and the action bar buttons: the items of `defaultActions` and the values of `defaultActionsObj`). Each call creates the node, so call one only where it is inserted, and a node that is never called is never created, e.g. `{props.defaultTitle?.()}` or `<For each={props.defaultActions}>{(action) => action()}</For>`.

export interface RenderInputAreaProps {
    /* Default node */
    defaultNode?: ReactNode;
    /* If you customize the input box, you need to call it when sending a message. */
    onSend?: (content?: string, attachment?: FileItem[]) => void;

        clearContextNode?: ReactNode;
        /* upload button */
        uploadNode?: ReactNode;
        /* text input area */
        inputNode?: ReactNode;
        /* send button */
        sendNode?: ReactNode;
        /* The processing function that triggers the focus of the text input box after clicking */
        onClick?: () => void; // focuses the input

## Accessibility

### Keyboard and Focus

- In the input box, `Enter` or `Shift` + `Enter` sends the message, as decided by `sendHotKey`: with `enter`, `Enter` sends and `Shift` + `Enter` inserts a line break; `shift+enter` is the reverse.
- `Shift` + `Tab` in the input box returns to the upload button. The default upload button is a native button: `Enter` or `Space` opens the file dialog. When an upload tip is set, its text is the description of that button and is shown while the button has focus.
- The stop generation button only exists while generating. When generation ends and the button is unmounted, focus that was on it moves to the input box instead of falling to the start of the page.
- Except on the last finished message, the message action bar stays hidden while remaining in the `Tab` order, and shows when focus enters one of its buttons. The confirmation opened by the delete button closes with `Esc` and focus returns to the delete button; inside a Modal only the confirmation closes and the Modal stays open.
- The message list is a named `role="log"` region with `aria-busy="true"` while the last message is generating, so screen readers announce the reply once it completes rather than chunk by chunk.
