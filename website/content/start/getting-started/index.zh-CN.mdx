## 引入 token

组件会自己导入主题 token（`--semi-*` CSS 变量）与 base 规则，不引入也能正常显示。首个组件懒加载时，token 要等该组件的 chunk 加载后才生效；在应用入口文件最先导入 tokens 入口，token 就随入口的 CSS 一起加载，首屏的应用样式也能用上 `--semi-*` 变量。

<Framework only="react">

```ts
// main.tsx，放在其他导入之前
import '@fibrae/semi-ui-react/tokens';
```

</Framework>

<Framework only="vue">

```ts
// main.ts，放在其他导入之前
import '@fibrae/semi-ui-vue/tokens';
```

</Framework>

<Framework only="solid">

```ts
// index.tsx，放在其他导入之前
import '@fibrae/semi-ui-solid/tokens';
```

</Framework>

<Framework only="svelte">

Vite + Svelte 应用在入口文件导入：

```ts
// src/main.ts，放在其他导入之前
import '@fibrae/semi-ui-svelte/tokens';
```

SvelteKit 没有这样的入口文件，在根布局的脚本最前面导入：

```svelte
<!-- src/routes/+layout.svelte -->
<script lang="ts">
    import '@fibrae/semi-ui-svelte/tokens';

    let { children } = $props();
</script>

{@render children()}
```

</Framework>

tokens 入口是 JS 模块，导入的是组件所用的同一份 token，构建产物里只有一份，`prefixCls` 等构建插件选项对它同样生效。开启 `omitCss` 时它和组件样式一起被移除，token 由整包样式提供。

## 使用组件

<Framework only="react">

```jsx
import { Button, Toast } from '@fibrae/semi-ui-react';

export function App() {
    return <Button onClick={() => Toast.warning({ content: 'welcome' })}>Hello Semi</Button>;
}
```

也可以按目录深路径导入单个组件，路径写到 `/index`，如 `import Button from '@fibrae/semi-ui-react/button/index'`。

</Framework>

<Framework only="vue">

```vue
<script setup lang="ts">
    import { Button, Toast } from '@fibrae/semi-ui-vue';
</script>

<template>
    <Button @click="Toast.warning({ content: 'welcome' })">Hello Semi</Button>
</template>
```

也可以按目录深路径导入单个组件，路径写到 `/index`，如 `import Button from '@fibrae/semi-ui-vue/button/index'`。

</Framework>

<Framework only="solid">

```tsx
import { Button, Toast } from '@fibrae/semi-ui-solid';

export function App() {
    return <Button onClick={() => Toast.warning({ content: 'welcome' })}>Hello Semi</Button>;
}
```

也可以按目录深路径导入单个组件，路径写到 `/index`，如 `import Button from '@fibrae/semi-ui-solid/button/index'`。

</Framework>

<Framework only="svelte">

```svelte
<script lang="ts">
    import { Button, Switch, Toast } from '@fibrae/semi-ui-svelte';

    let checked = $state(false);
</script>

<Button theme="solid" type="primary" onclick={() => Toast.warning({ content: 'welcome' })}>Hello Semi</Button>
<Switch bind:checked aria-label="开关" />
```

受控值用 `bind:checked={value}` 双向绑定；只传 `checked` 时只作初值，没有 `defaultChecked` 一类的 `default*` 属性。单向传值时组件内交互改出的值是临时的：父级传入的值变化时以父级为准；同一组件上还有展开属性（`{...rest}`）时，展开对象换成新对象也会让父级的值重新生效。要保留交互结果，用 `bind:` 或在回调（如 `onChange`）里写回自己的状态。内容型属性（React 的 ReactNode 与 render 函数）是 snippet，写在组件标签内或用 `{#snippet}` 定义；`style` 只接受字符串，原生事件用小写名（`onclick`）。

也可以按目录深路径导入单个组件，路径写到 `/index`，如 `import { Button } from '@fibrae/semi-ui-svelte/button/index'`；组件文件是 `<目录>/<名>.svelte`，如 `@fibrae/semi-ui-svelte/button/button.svelte`。

</Framework>

样式与 token 随组件按需加载，只有用到的组件会被打包。Semi 自带 `box-sizing: border-box` 与滚动条基础样式，不需要 reset.css 一类的重置样式，额外的重置样式会改变组件尺寸。

## 构建插件

使用默认前缀 `semi`、分层样式且由组件各自导入样式时，webpack、rspack 不需要构建插件。组件导入的是预编译的 CSS，类名前缀为 `semi`，包在 `@layer semi` 中：需要有处理 `.css` 导入的规则，如 webpack 的 `css-loader` 加 `style-loader`（或 `mini-css-extract-plugin` 的 loader）、rspack 的 `type: 'css'`。Vite 的开发服务器可以不用插件，但 `vite build` 需要 `@fibrae/semi-vite-plugin`，原因见下。服务端渲染的宿主另见[服务端渲染](#服务端渲染)。

需要下列能力时，使用对应构建工具的插件：Vite 用 `@fibrae/semi-vite-plugin`，webpack 5 用 `@fibrae/semi-webpack-plugin`，rspack 2 用 `@fibrae/semi-rspack-plugin`。插件对组件库、图标包与 AI 包都生效。

| 选项        | 默认值   | 说明                                                                    |
| ----------- | -------- | ----------------------------------------------------------------------- |
| `prefixCls` | `'semi'` | 类名前缀，同时改写组件 JS 中的前缀与编译出的样式                        |
| `cssLayer`  | `true`   | 样式是否包在 `@layer semi` 中，`false` 输出不分层的样式                 |
| `omitCss`   | `false`  | 去掉 Semi 包内的样式导入，改由应用加载整包样式，见[整包样式](#整包样式) |

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import semi from '@fibrae/semi-vite-plugin';

export default defineConfig({
    plugins: [semi({ prefixCls: 'my' })],
});
```

```js
// webpack.config.mjs
import SemiWebpackPlugin from '@fibrae/semi-webpack-plugin';

export default {
    plugins: [new SemiWebpackPlugin({ prefixCls: 'my' })],
};
```

```js
// rspack.config.mjs，项目需要有把 .scss 当作 CSS 处理的规则
import { SemiRspackPlugin } from '@fibrae/semi-rspack-plugin';

export default {
    module: { rules: [{ test: /\.s?css$/, type: 'css' }] },
    plugins: [new SemiRspackPlugin({ prefixCls: 'my' })],
};
```

webpack 插件另有 `extractCssOptions`（如改用 `mini-css-extract-plugin` 的 loader）与 `overrideStylesheetLoaders`（在默认 loader 链上追加自己的 loader）。`vite dev` 中类名仍是 `semi-*` 时，预构建缓存来自修改前的配置，用 `vite --force` 重新预构建。

<Framework only="solid">

Solid 项目的构建配置有以下区别：

- Vite：开发服务器也需要 `@fibrae/semi-vite-plugin`，写成 `plugins: [solid(), semi()]`。vite-plugin-solid 把 Solid 包排除在预构建之外，foundation 的 CommonJS 依赖（如 `style-to-js`）原样进入浏览器，页面白屏，插件会把它们加入预构建。
- webpack 5、rspack 2：Semi 的 webpack、rspack 插件不处理 Solid 包，所以插件的选项（`prefixCls`、`cssLayer: false`、`omitCss`）对 Solid 包不起作用，只支持默认前缀与分层样式，不使用这两个插件。应用的 JSX 用 `babel-loader` 加 `babel-preset-solid` 编译（需要 `@babel/core` 7）；打包器不识别 `solid` 导出条件，取到 `default` 条件下已为 DOM 编译的 `dist/*.js`。样式由组件各自导入：webpack 用 `css-loader` 加 `style-loader`，rspack 用 `type: 'css'`。

</Framework>

<Framework only="svelte">

Svelte 项目的构建配置有以下区别：

- 只有 Vite 路线：Svelte 包由 `@sveltejs/vite-plugin-svelte`（SvelteKit 已内置）编译。`@fibrae/semi-webpack-plugin`、`@fibrae/semi-rspack-plugin` 不处理 Svelte 包，不要用于 Svelte 项目。
- `@fibrae/semi-vite-plugin` 对 `@fibrae/semi-ui-svelte`、`@fibrae/semi-ai-svelte` 与 `@fibrae/semi-icons-svelte` 生效，`prefixCls`、`cssLayer`、`omitCss` 的含义不变，写成 `plugins: [svelte(), semi()]`；SvelteKit 见[服务端渲染](#服务端渲染)。

</Framework>

Semi 发布的 `.scss` 使用普通 Sass 无法解析的 `semi:` 地址，请通过构建插件或 `@fibrae/semi-scss-compile` 编译。

## 整包样式

需要一次性加载全部组件样式时，导入整包样式并开启构建插件的 `omitCss`，否则组件自带的样式导入会被再打包一份，同一组件的样式出现两次。整包样式已含 token 与图标样式，类名前缀为 `semi`，包在 `@layer semi` 中。

<Framework only="react">

```ts
import '@fibrae/semi-ui-react/styles.css';
// 使用 AI 组件时，在其后导入
import '@fibrae/semi-ai-react/styles.css';
```

</Framework>

<Framework only="vue">

```ts
import '@fibrae/semi-ui-vue/styles.css';
// 使用 AI 组件时，在其后导入
import '@fibrae/semi-ai-vue/styles.css';
```

</Framework>

<Framework only="solid">

```ts
import '@fibrae/semi-ui-solid/styles.css';
// 使用 AI 组件时，在其后导入
import '@fibrae/semi-ai-solid/styles.css';
```

</Framework>

<Framework only="svelte">

```ts
import '@fibrae/semi-ui-svelte/styles.css';
// 使用 AI 组件时，在其后导入
import '@fibrae/semi-ai-svelte/styles.css';
```

</Framework>

`omitCss` 时插件不再编译样式，`cssLayer` 不起作用，webpack、rspack 插件同时传入会报错。需要自定义前缀或不分层的整包样式时，用 `@fibrae/semi-scss-compile` 生成：`--prefix` 与插件的 `prefixCls` 一致，`--no-layer` 输出不分层的样式。`-f`、`-i` 可省略，缺省使用 `@fibrae/semi-scss-compile` 自己依赖的 foundation 与 icons-core，所以它的版本要与组件库一致；版本不一致时用 `-f`、`-i` 指向应用里安装的 `@fibrae/semi-foundation`、`@fibrae/semi-icons-core` 的 `dist`，pnpm 下这两个包要加为直接依赖。`--ai` 必须给出路径，指向 `@fibrae/semi-ai-foundation` 的 `dist`，pnpm 下要把它加为直接依赖，版本与组件库相同。

```bash
pnpm add -D @fibrae/semi-scss-compile
pnpm exec semi-build-scss -o src/semi.css --min --prefix my
# 使用 AI 组件时另生成一份，在上面那份之后导入（需再安装 @fibrae/semi-ai-foundation）
pnpm add -D @fibrae/semi-ai-foundation
pnpm exec semi-build-scss --ai node_modules/@fibrae/semi-ai-foundation/dist -o src/semi-ai.css --min --prefix my
```

## 定制样式

样式定制不需要构建插件：在应用的样式中覆写 `--semi-*` CSS 变量即可改变全局的颜色、圆角、字号、间距等，变量清单见[设计变量](/zh-CN/react/basic/tokens)，暗色模式的取值见[暗色模式](/zh-CN/react/advanced/dark-mode)。Semi 的样式位于 `@layer semi` 中，应用中不分层的 CSS 规则总是优先，可以直接覆盖某个组件的具体样式，不需要 `!important`。

```css
:root {
    --semi-color-primary: var(--semi-violet-5);
}

.my-toolbar .semi-button {
    border-radius: 0;
}
```

与 Tailwind 同用时，层的声明顺序与原子类中使用 Semi token 的方式见 [Tailwind](/zh-CN/react/ecosystem/tailwind)。

## 服务端渲染

服务端渲染与 hydration 按下表配置宿主，多数宿主需要加上 Semi 的构建插件。默认按组件加载样式：组件 JS 自带样式导入，不导入 `styles.css`。整包样式是可选路线：构建插件开 `omitCss`，再导入一次 `styles.css`，见[整包样式](#整包样式)。两条路线不混用，混用时 CSS 体积约翻倍。

<Framework only="react">

| 宿主                                                          | 安装                                                   | 宿主配置                                       | 样式                                                |
| ------------------------------------------------------------- | ------------------------------------------------------ | ---------------------------------------------- | --------------------------------------------------- |
| Next.js 16 App Router，`--webpack`                            | `@fibrae/semi-ui-react`                                | 无                                             | 无                                                  |
| Next.js 16 默认的 Turbopack、Pages Router，或两种 Router 混用 | 另加 `-D @fibrae/semi-next`                            | `export default semiNext()({ ... })`           | 无                                                  |
| Next.js 自定义前缀                                            | 另加 `-D @fibrae/semi-next @fibrae/semi-scss-compile`  | `semiNext({ prefixCls: 'my', omitCss: true })` | 导入一次 `semi-build-scss --prefix my` 生成的样式表 |
| React Router 8 framework mode（含 `serverBundles`）           | `@fibrae/semi-ui-react`、`-D @fibrae/semi-vite-plugin` | `plugins: [semi(), reactRouter()]`             | 无                                                  |

```js
// next.config.mjs，Turbopack 与 Pages Router
import semiNext from '@fibrae/semi-next';

export default semiNext()({
    // 你的 Next.js 配置
});
```

```ts
// vite.config.ts，React Router
import { reactRouter } from '@react-router/dev/vite';
import { defineConfig } from 'vite';
import semi from '@fibrae/semi-vite-plugin';

export default defineConfig({
    plugins: [semi(), reactRouter()],
});
```

Next.js 自定义前缀时，`prefixCls` 必须配 `omitCss: true`，样式表用 `semi-build-scss` 生成，在根 layout（Pages Router 为 `pages/_app`）导入一次：

```js
// next.config.mjs
import semiNext from '@fibrae/semi-next';

export default semiNext({ prefixCls: 'my', omitCss: true })({});
```

```bash
pnpm add -D @fibrae/semi-next @fibrae/semi-scss-compile
pnpm exec semi-build-scss --prefix my -o app/semi-my.css --min
```

```jsx
// app/layout.jsx
import './semi-my.css';
```

React Router 的 RSC 模式同样只加这个插件：`plugins: [semi(), reactRouterRSC(), rsc()]`（`reactRouterRSC` 即 `@react-router/dev/vite` 的 `unstable_reactRouterRSC`，`rsc` 来自 `@vitejs/plugin-rsc`）。Server Component 中，Next.js App Router 与 React Router 的 RSC 模式可以直接导入扁平组件和少数子组件的命名导出（如 `TypographyTitle`，点语法 `Typography.Title` 在 Server Component 中是 `undefined`）。`semiGlobal`、Form 的 HOC 与 hooks，以及传给 `ConfigProvider` 的语言包只能在 `'use client'` 文件中使用或导入。

</Framework>

| 宿主   | 安装                                          | 宿主配置                                                   | 样式 |
| ------ | --------------------------------------------- | ---------------------------------------------------------- | ---- |
| Nuxt 4 | `@fibrae/semi-ui-vue`、`-D @fibrae/semi-nuxt` | `modules: ['@fibrae/semi-nuxt']`，选项写在 `semi: { ... }` | 无   |

```ts
// nuxt.config.ts
export default defineNuxtConfig({
    modules: ['@fibrae/semi-nuxt'],
});
```

模块不做组件自动导入，组件照常从 `@fibrae/semi-ui-vue` 导入。

`@fibrae/semi-nuxt` 在应用没有设置 `features.inlineStyles` 时把它设为 `false`，生产环境的 SSR 页面只用 `<link>` 加载样式。原因是 Nuxt 把页面 chunk 里的全部 CSS 都内联进该页的 HTML，而这份 CSS 同时仍以 `<link>` 加载：几个常用组件只被一个页面导入时，该页 HTML 从约 5KB 增至约 210KB。代价是应用自己的 SFC `<style>` 也不再内联。要保留 Nuxt 的内联，在 `nuxt.config.ts` 中显式设置，模块不覆盖：

```ts
// nuxt.config.ts
export default defineNuxtConfig({
    modules: ['@fibrae/semi-nuxt'],
    features: { inlineStyles: true },
});
```

</Framework>

SolidStart 选整包样式，是因为它的 dev 服务端默认不收集 `node_modules` 内组件导入的 CSS：按组件路线在生产环境正常，dev 首屏无样式。给 `solidStart()` 传 `css: { filter: { exclude: [/^(?!.*\/node_modules\/@fibrae\/semi-).*\/node_modules\//] } }` 后 dev 也收集 Semi 包的组件 CSS，代价是多一处宿主配置，且 dev 首屏的样式略大于整包样式（约多 20%），分成数十个 `<style>`。

## 同一页面挂载多个 Vue app

组件内部的 id 由 Vue 的 `useId` 生成，按 app 计数。同一页面挂载多个 app（微前端、Astro island 等）时，给每个 app 设置不同的 `app.config.idPrefix`，否则各 app 生成相同的 id，`aria-labelledby` 等引用会指向其他 app 里的元素。

```ts
const app = createApp(App);
app.config.idPrefix = 'checkout';
app.mount('#checkout');
```
