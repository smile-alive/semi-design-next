## Built-in languages

| Language           | Export  |
| ------------------ | ------- |
| Simplified Chinese | `zh_CN` |
| English (US)       | `en_US` |

Both packs come from the `/locale` entry of the UI package, for example `import { en_US } from '@fibrae/semi-ui-react/locale'`. For any other language, write your own pack; see [Custom locale packs](#custom-locale-packs).

## Components supported

Calendar、Cascader、Chat、DatePicker、Form、Image、List、Modal、Navigation、Nav、Pagination、Popconfirm、Select、Table、TimePicker、Transfer、Tree、TreeSelect、Typography、Upload

## How to use

<Framework only="react">

`LocaleProvider` uses the context feature of React, and you only need to wrap the periphery of the application once to take effect globally.  
When you need to switch the language, you can directly switch the locale passed in by the props.

```jsx
import { LocaleProvider } from '@fibrae/semi-ui-react';
import { en_US } from '@fibrae/semi-ui-react/locale';

() => {
    return (
        <LocaleProvider locale={en_US}>
            {/* eslint-disable-next-line react/jsx-no-undef */}
            <App />
        </LocaleProvider>
    );
};
```

</Framework>

<Framework only="vue">

`LocaleProvider` passes the locale pack to its descendants through provide/inject, and you only need to wrap the periphery of the application once to take effect globally.  
When you need to switch the language, change the value of the `locale` prop.

```vue
<script setup lang="ts">
    import { LocaleProvider } from '@fibrae/semi-ui-vue';
    import { en_US } from '@fibrae/semi-ui-vue/locale';
</script>

<template>
    <LocaleProvider :locale="en_US">
        <App />
    </LocaleProvider>
</template>
```

</Framework>

<Framework only="solid">

`LocaleProvider` passes the locale pack to its descendants through context, and you only need to wrap the periphery of the application once to take effect globally.  
When you need to switch the language, bind `locale` to a value that changes; the subtree updates automatically.

```jsx
import { LocaleProvider } from '@fibrae/semi-ui-solid';
import { en_US } from '@fibrae/semi-ui-solid/locale';

() => (
    <LocaleProvider locale={en_US}>
        <App />
    </LocaleProvider>
);
```

</Framework>

<Framework only="svelte">

`LocaleProvider` passes the locale pack to its descendants through context, and you only need to wrap the periphery of the application once to take effect globally.  
When you need to switch the language, bind `locale` to state that changes; the subtree updates automatically.

```svelte
<script lang="ts">
    import { LocaleProvider } from '@fibrae/semi-ui-svelte';
    import { en_US } from '@fibrae/semi-ui-svelte/locale';
</script>

<LocaleProvider locale={en_US}>
    <App />
</LocaleProvider>
```

</Framework>

When `locale` is omitted, LocaleProvider inherits the language of the outer LocaleProvider; without any outer provider, `zh_CN` is used. The `locale` of ConfigProvider takes precedence over LocaleProvider.

### date-fns locale of date components

DatePicker, TimePicker and Calendar format and parse dates with date-fns. Locale packs hold only text, not date-fns locale data: these components pick the built-in zh-CN or en-US by the current locale's `code`, and use enUS for other languages. For another language, import it from `date-fns/locale` and pass it to the `dateFnsLocale` of ConfigProvider, for example `ja` from `date-fns/locale/ja` alongside a Japanese locale pack. Only the imported languages reach the bundle, and server rendering and the first client render use the same locale object.

### Custom locale packs

For a language that is not built in, write your own pack after the `Locale` type and pass it to the `locale` of ConfigProvider or LocaleProvider. `locale` is typed `LocaleInput`, exported from the UI package alongside `Locale`: only `code` is required, so write just the components and keys you translate. Every text or `currency` the pack leaves out falls back to `en_US`.

- `code` picks the built-in date-fns locale of the date components, and is the `localeCode` that LocaleConsumer and `useLocale` read.
- The date-fns locale of the date components goes separately through the `dateFnsLocale` of ConfigProvider; see the previous section.
- Create the pack object once, at module level or memoized. Components cache the filled-in text per object, so mutating it in place has no effect; pass a new object instead.

The example translates only the page buttons and jump text of Pagination and the placeholder of DatePicker; the total, the page size and the text in the date panel fall back to English.

### Custom Internationalization Component

<Framework only="react">

When your custom component also wants to consume the localeCode in the Semi LocaleProvider Context or read the i18n text localeData of a specific component, you can use LocaleConsumer to get it

</Framework>

<Framework only="vue">

When your custom component also wants to consume the localeCode in the Semi LocaleProvider or read the i18n text of a specific component, use the default scoped slot of LocaleConsumer, which provides `locale`, `localeCode` and `currency`. Inside `<script setup>`, call `useLocale(componentName)` instead; it returns a computed with the same three fields. The language priority is ConfigProvider, LocaleProvider, then `zh_CN`. Custom namespaces (`ComponentA` in the example) extend the `Locale` type through declaration merging.

</Framework>

<Framework only="solid">

When your custom component also wants to consume the localeCode in the Semi LocaleProvider or read the i18n text of a specific component, use LocaleConsumer. Its child is a function receiving the namespace text (`locale`), `localeCode` and `currency`, in that order. Inside a component body, you can also call `useLocale(componentName)`, which returns an accessor; call it to read the same three fields. The language priority is ConfigProvider, LocaleProvider, then `zh_CN`. Custom namespaces (`ComponentA` in the example) extend the `Locale` type through declaration merging.

</Framework>

<Framework only="svelte">

When your custom component also wants to consume the localeCode in the Semi LocaleProvider or read the i18n text of a specific component, use LocaleConsumer. Its `children` snippet receives `{ locale, localeCode, currency }`. During component initialisation, you can also call `useLocale(componentName)`, which returns a getter; call it to read the same three fields. The language priority is ConfigProvider, LocaleProvider, then `zh_CN`. Custom namespaces (`ComponentA` in the example) extend the `Locale` type through declaration merging.

</Framework>

## API Reference

---

### LocaleProvider

<LocaleProviderVueApi />

LocaleProvider does not accept undeclared attributes; attrs such as `class` and `style` are not applied to the DOM.

### LocaleConsumer

<LocaleConsumerVueApi />

LocaleConsumer renders no element of its own and does not accept undeclared attributes.

### useLocale

`useLocale(componentName)` returns a `ComputedRef<LocaleResult>`. `componentName` can be a string, a ref or a getter.

| Field      | Description                                     | Type        |
| ---------- | ----------------------------------------------- | ----------- |
| locale     | Text of the namespace named by `componentName`  | `Locale[K]` |
| localeCode | Language code                                   | string      |
| currency   | ISO 4217 currency code of the language's region | string      |

</Framework>
