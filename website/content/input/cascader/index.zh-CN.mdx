## 使用场景

与 TreeSelect 组件的区别:

- TreeSelect: 核心价值在于**目标节点**，层级结构是为了方便用户快速筛选出目标选项，最终的节点才是用户想要的内容，常见于文件/文件夹选择、组织架构、权限分配等场景。
- Cascader: 核心价值在于**路径**，用户选择的不是一个孤立的点，而是一条从根到叶的完整路径，常用于地理位置，商品分类等场景。

    parent?: Entity; // 父节点数据

<Notice title='使用说明'>

搜索时建议自行处理以下几点：

- **防抖（debounce）**：避免每次按键都打请求，常见做法是用 `es-toolkit` 的 `debounce` 包裹搜索逻辑（如 200~300ms）。
- **竞态保护**：用一个递增 token 或 `AbortController` 丢弃过期请求结果，避免后发先到时旧响应覆盖新响应。
- **loading 提示**：在请求期间通过外层 `Spin` 或简单的提示元素告知用户「加载中」，否则用户会看到「暂无数据」误以为无结果。
- **初始 / 空输入处理**：输入被清空时把 `treeData` 还原为初始数据，避免空查询拉数据。

</Notice>

### 自定义 Trigger

<Framework only="react">

如果默认的触发器样式满足不了你的需求，可以用`triggerRender`自定义选择框的展示

triggerRender 入参如下

```typescript
interface TriggerRenderProps {
    /* Cascader 的 props */
    componentProps: CascaderProps;
    /* 是否禁用 Cascader */
    disabled: boolean;
    /**
     * 已选中的 node 在 treeData 中的层级位置，如下例子，
     * 当选中浙江省-杭州市-萧山区时，此处 value 为 '0-0-1'
     */
    value?: string | Set<string>;
    /* 展开时为搜索词；可搜索的单选收起时为已选路径的展示文本，设置 displayRender 时为其返回值 */
    inputValue: ReactNode;
    /**
     * 用于更新 input 框值的函数，当你在 triggerRender 自定义的
     * Input 组件值更新时，你应该调用该函数，用于向 Cascader 内部
     * 同步状态, 使用时需要设置 filterTreeNode 参数非 false
     */
    onSearch: (inputValue: string) => void;
    /* 用于清空值的函数，入参为点击事件 */
    onClear: (e: React.MouseEvent) => void;
    /* Placeholder */
    placeholder?: string;
    /* 用于删除单个 item，入参为该节点在 treeData 中的层级位置（与 value 的格式相同） */
    onRemove: (pos: string) => void;
}
```

</Framework>

## Methods

<Framework only="solid">

Cascader 的 `ref` 指向触发器元素，该元素上挂有 `open()`、`close()`、`focus()`、`blur()` 和 `search(value)` 方法，类型为 `CascaderElement`。`search` 按输入了该值来搜索，需同时设置 `filterTreeNode` 开启搜索，`searchPosition` 为 `custom` 时自定义展示搜索框。

```tsx
import { Cascader, type CascaderElement } from '@fibrae/semi-ui-solid';

let cascader: CascaderElement | undefined;
const open = () => cascader?.open();

<Cascader ref={(node) => (cascader = node)} treeData={treeData} />;
```

</Framework>

<Framework only="react">

通过 ref 拿到的 `CascaderHandle` 上挂有 open、close、focus、blur 与 search 方法，可以用来实现某些特殊交互，各方法的参数与说明见上方 API 参考。

</Framework>

<Framework only="vue">

Cascader 通过模板 ref 暴露 `open()`、`close()`、`focus()`、`blur()` 和 `search(value)`，类型为 `CascaderHandle`。`search` 按输入了该值来搜索，需同时设置 `filterTreeNode` 开启搜索，`searchPosition` 为 `custom` 时自定义展示搜索框。

```vue
<script setup lang="ts">
    import { useTemplateRef } from 'vue';
    import { Cascader } from '@fibrae/semi-ui-vue';
    import type { CascaderHandle } from '@fibrae/semi-ui-vue';

    const cascader = useTemplateRef<CascaderHandle>('cascader');
    const open = () => cascader.value?.open();
</script>

<template>
    <Cascader ref="cascader" :treeData="treeData" />
</template>
```

</Framework>

## Accessibility

### ARIA

- Cascader 支持传入 `aria-label`、`aria-describedby`、`aria-errormessage`、`aria-invalid`、`aria-labelledby`、`aria-required` 来表示该 Cascader 的相关信息;

<Framework only="vue">

- 这些 `aria-*` 属性落在当前的 combobox 上：不可搜索时是根元素（触发器），可搜索时是搜索框，多选且搜索框在触发器内时是标签输入框;

</Framework>

<Framework only="solid">

- 这些 `aria-*` 属性落在当前的 combobox 上：不可搜索时是根元素（触发器），可搜索时是搜索框，多选且搜索框在触发器内时是标签输入框;

</Framework>

- combobox 的名称按优先级取：`aria-labelledby`、`aria-label`、实际渲染出来的 insetLabel（combobox 的 `aria-labelledby` 指向它，未传 `insetLabelId` 时组件生成 id；有 prefix 时 insetLabel 不渲染，也不作名称），都没有时为语言包中的「级联选择」。下拉中的 tree 或搜索结果 listbox 使用同一个名称来源;
- 按 ARIA 1.2 的 combobox 写法，任一时刻只有一个元素是 combobox，`aria-controls` 指向下拉中的列表，下拉与 combobox 同名。不可搜索时触发器是 select-only combobox，已选路径是它的值；可搜索时搜索框本身是 combobox，带 `aria-autocomplete="list"`，触发器不再有角色和 Tab 停靠点。单选的搜索框只在搜索时出现，未搜索时触发器仍是 combobox；搜索框在输入前为空，已选路径以 `aria-describedby` 关联为它的描述；搜索中选中结果后焦点回到触发器;
- 各列合起来是一棵 `role="tree"`：选项为 `treeitem`，带 `aria-level`（所在列）、`aria-setsize`、`aria-posinset`、`aria-disabled`，可展开的选项带 `aria-expanded`；单选时用 `aria-selected`，多选时用 `aria-checked`（半选为 `mixed`）;

<Framework only="react">

- 搜索结果是 `role="listbox"`，选项为 `option`，用 `aria-selected` 表示选中，多选时表示勾选。`filterRender` 返回的元素会被加上 `id`、`role="option"` 和上述状态;

</Framework>

<Framework only="vue">

- 搜索结果是 `role="listbox"`，选项为 `option`，用 `aria-selected` 表示选中，多选时表示勾选。`#filterItem` 只渲染一个元素根时，该元素会被加上 `id`、`role="option"` 和上述状态，否则组件包一层带这些属性的 `li`;

</Framework>

<Framework only="solid">

- 搜索结果是 `role="listbox"`，选项为 `option`，用 `aria-selected` 表示选中，多选时表示勾选。`filterRender` 返回单个元素时，该元素会被加上 `id`、`role="option"` 和上述状态，否则组件包一层带这些属性的 `li`;

- 选项前的勾选图标和多选复选框只是状态的图示，对读屏软件隐藏，也不接收焦点。

### 键盘交互

Cascader 按 [WAI-ARIA Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) 处理键盘：焦点始终留在触发器或搜索框上，`aria-activedescendant` 指向当前选项，当前选项显示焦点环。下拉刚打开时没有当前选项。

- 下拉关闭时：`ArrowDown`、`ArrowUp`、`Enter` 打开下拉；不可搜索时，`Space` 也打开下拉，`Home`、`End` 打开下拉并移到第一列的第一个、最后一个选项。可搜索时，`Space`、`Home`、`End` 用于编辑文字
- `Enter`：有当前选项时等同点击它，多选时勾选或取消勾选；禁用选项不响应
- `ArrowDown`、`ArrowUp`：在当前选项所在的列（或搜索结果）中移到下一个、上一个选项，第一次按 `ArrowDown` 移到第一列的第一个选项；`Home`、`End`：移到这一列的第一个、最后一个选项
- `ArrowRight`：展开当前选项，显示它的下一列；已展开时移到下一列的第一个选项（RTL 下与 `ArrowLeft` 互换）
- `ArrowLeft`：收起展开的当前选项；否则移到上一列的父选项
- `Space`：有当前选项时与 `Enter` 相同（焦点在搜索框里时用于输入）
- 输入字符：下拉打开时，从当前选项往后，移到已显示的各列中第一个以输入内容开头的选项，各列保持不变；快速连续输入的字符合成一个搜索词。焦点在搜索框里时字符用于输入；下拉关闭时不响应
- `Esc`：关闭下拉

焦点在搜索框里且已输入文字时，只有 `ArrowDown`、`ArrowUp`、`Enter` 用于移动和选择，其余按键用于编辑文字。方向键只移动当前选项，不像悬停那样自动展开下一列，也不触发 `loadData`；`ArrowRight` 展开时才加载。

`showClear` 开启、有已选值或搜索文本且未禁用时，触发器内渲染清除按钮。它是原生 `button`，名称为语言包中的「清空已选值」，在 hover、下拉打开或焦点位于 Cascader 内时显示。从触发器或搜索框按 `Tab` 移到清除按钮，`Enter` 或 `Space` 清空，效果与鼠标点击相同，清空后焦点回到触发器或搜索框。多选时也可在搜索框中用 `Backspace` 删除标签。

## 文案规范

- 选择器选项
    - 如果没有默认选项，就使用 "Select" 做占位文案
    - 选项要按首字母顺序或者其他有逻辑的排列顺序，使用户更好地找到选项
    - 使用语句书写规范（首字母大写，其余小写），避免在句尾使用逗号和分号
    - 清晰表达出选项所表示的选择目的
