## Usage scenarios

Differences from TreeSelect component:

- TreeSelect: The core value lies in **target node**. The structure is to facilitate users to quickly filter out target options. The final node is what the user wants. It is commonly used in file/folder selection, organizational structure, permission allocation and other scenarios.
- Cascader: The core selection value lies in the **path**. What the user selects is not an isolated point, but a complete path from root to leaf, which is often used in scenarios such as geographical location and product classification.

</Framework>

<Framework only="svelte">

Cascader supports remote search. With `remote` enabled, search input no longer goes through local filtering; only the `onSearch` callback is called, and you are responsible for fetching `treeData` asynchronously based on the input. This mirrors Select's `remote` behavior.

</Framework>

<Notice title='Usage notes'>

You should typically handle the following yourself when using remote search:

- **Debounce**: avoid firing a request on every keystroke; wrapping the search handler with `debounce` from `es-toolkit` (e.g. 200~300ms) is the common approach.
- **Race-condition protection**: use an incrementing token or an `AbortController` to drop stale responses, otherwise an out-of-order earlier response may overwrite the latest one.
- **Loading hint**: show a loading state via an outer `Spin` or other indicator while the request is in flight, otherwise users may misread an in-flight state as "no data".
- **Empty / cleared input**: when the input is cleared, restore `treeData` to the initial state instead of querying with an empty keyword.

</Notice>

## Methods

<Framework only="solid">

The `ref` of Cascader points at the trigger element, which carries the `open()`, `close()`, `focus()`, `blur()` and `search(value)` methods, typed as `CascaderElement`. `search` searches as if the value were typed; set `filterTreeNode` to enable search, and `searchPosition` to `custom` to customize the display search box.

```tsx
import { Cascader, type CascaderElement } from '@fibrae/semi-ui-solid';

let cascader: CascaderElement | undefined;
const open = () => cascader?.open();

<Cascader ref={(node) => (cascader = node)} treeData={treeData} />;
```

</Framework>

<Framework only="react">

The `ref` of Cascader receives a `CascaderHandle`, which carries the `open()`, `close()`, `focus()`, `blur()` and `search(value)` methods, so that some special interactions can be implemented. See the API reference above for their parameters and descriptions.

</Framework>

<Framework only="vue">

Cascader exposes `open()`, `close()`, `focus()`, `blur()` and `search(value)` through a template ref, typed as `CascaderHandle`. `search` searches as if the value were typed; set `filterTreeNode` to enable search, and `searchPosition` to `custom` to customize the display search box.

### ARIA

- Cascader supports importing `aria-label`, `aria-describedby`, `aria-errormessage`, `aria-invalid`, `aria-labelledby`, `aria-required` to indicate the relevant information of the Cascader;

<Framework only="vue">

- These `aria-*` attributes fall on the current combobox: the root element (the trigger) without search, the search input with search, and the tag input in multiple mode when the search input is in the trigger;

</Framework>

<Framework only="solid">

- These `aria-*` attributes fall on the current combobox: the root element (the trigger) without search, the search input with search, and the tag input in multiple mode when the search input is in the trigger;

</Framework>

<Framework only="svelte">

- These `aria-*` attributes fall on the current combobox: the root element (the trigger) without search, the search input with search, and the tag input in multiple mode when the search input is in the trigger;

</Framework>

- The combobox takes its name from, in order: `aria-labelledby`, `aria-label`, the rendered insetLabel (the combobox's `aria-labelledby` points at it, with an id the component generates when `insetLabelId` is not given; with a prefix the insetLabel is not rendered and does not name it), and otherwise "Cascader" from the locale. The tree or the search-result listbox in the dropdown uses the same name source;
- Following the ARIA 1.2 combobox pattern, exactly one element is the combobox at any time; its `aria-controls` points at the list in the dropdown, and the dropdown has the combobox's name. Without search the trigger is a select-only combobox and the selected path is its value; with search the input itself is the combobox, with `aria-autocomplete="list"`, and the trigger has no role and no Tab stop. In single mode the input appears only while searching, so the trigger is the combobox otherwise; the input is empty until the user types, so the selected path is linked to it as its description with `aria-describedby`; picking a result returns focus to the trigger;
- The columns together are one `role="tree"`: options are `treeitem`s with `aria-level` (their column), `aria-setsize`, `aria-posinset` and `aria-disabled`, and `aria-expanded` on options that can expand; a single-choice Cascader uses `aria-selected`, a multi-choice one uses `aria-checked` (`mixed` when half checked);

</Framework>

### Keyboard Interaction

Cascader follows the [WAI-ARIA Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) pattern: focus always stays on the trigger or the search input, `aria-activedescendant` points at the current option, and the current option shows the focus ring. There is no current option when the dropdown opens.

- While the dropdown is closed: `ArrowDown`, `ArrowUp` and `Enter` open it; without search, `Space` also opens it, and `Home` and `End` open it and move to the first or last option of the first column. With search, `Space`, `Home` and `End` edit the text
- `Enter`: with a current option, act like a click on it, or check and uncheck it in a multi-choice Cascader; disabled options do not respond
- `ArrowDown`, `ArrowUp`: move to the next or previous option in the current option's column (or in the search results); the first `ArrowDown` moves to the first option of the first column; `Home`, `End`: move to the first or last option of that column
- `ArrowRight`: expand the current option, showing its column; once expanded, move to the first option of that column (swapped with `ArrowLeft` in RTL)
- `ArrowLeft`: collapse the expanded current option; otherwise move to the parent option in the previous column
- `Space`: with a current option, the same as `Enter` (it types a space in the search input)
- Typing characters: while the dropdown is open, move to the next option after the current one, across the shown columns, whose label starts with the typed text, leaving the columns as they are; characters typed in quick succession form one search string. In the search input the characters are typed as text; a closed dropdown ignores them
- `Esc`: close the dropdown

While focus is in the search input and text is typed, only `ArrowDown`, `ArrowUp` and `Enter` move and select; the other keys edit the text. The arrow keys only move the current option: unlike hovering, they do not expand the next column or trigger `loadData`, which loads when `ArrowRight` expands.

With `showClear`, a selected value or search text, and no `disabled`, the trigger renders a clear button. It is a native `button` named "Clear selection" from the locale, shown on hover, while the dropdown is open, or while focus is inside the Cascader. From the trigger or the search input, `Tab` moves to the clear button; `Enter` or `Space` clears, as a mouse click does, and the focus goes back to the trigger or the search input. In multiple mode `Backspace` in the search input also removes tags.

## Content Guidelines

- Selector options
    - If there is no default option, use "Select" as the placeholder text
    - Arrange options in alphabetical order or another logical order, so that users can find them more easily
    - Write in sentence case (capitalize the first letter, lowercase the rest) and avoid ending with commas or semicolons
    - Clearly express the purpose of the choice that each option represents
