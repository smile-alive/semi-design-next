## When to use

- When making multiple choices in a set of options;
- Use independently to select from different states, similar to the Switch component. The difference is that switching the Switch triggers a state change directly, while Checkbox is generally used for tagging status and works with the submission.

## API Reference

### Checkbox

<Framework only="react">

<CheckboxReactApi />

`className` and `style` land on the root `span`. `id`, `name`, `tabIndex`, `autoFocus`, `aria-label`, `aria-labelledby`, `aria-describedby`, `aria-errormessage`, `aria-invalid` and `aria-required` land on the inner native input; other native attributes and events (such as `role`, `onFocus`, `onBlur`, `onClick` and `data-*`) land on the root `span`.

</Framework>

<Framework only="vue">

<CheckboxVueApi />

`class` and `style` land on the root element. `id`, `name`, `tabindex`, `autofocus`, `aria-*` and focus and blur listeners passed as attrs land on the inner native input; other native attributes and listeners (such as `@mouseenter`) land on the root element. Inside a CheckboxGroup the group's `name` wins.

</Framework>

<Framework only="solid">

<CheckboxSolidApi />

`class`, `style` and `ref` land on the root `<span>`. `id`, `name`, `tabindex`, `autofocus`, `aria-*`, `onFocus` and `onBlur` land on the inner native input; other native attributes and events (such as `onMouseEnter` and `onClick`) land on the root element. Inside a CheckboxGroup the group's `name` wins.

</Framework>

<Framework only="svelte">

<CheckboxSvelteApi />

`class` and `style` (a string) land on the root `<span>`. `id`, `name`, `tabindex`, `autofocus`, `aria-*`, `onfocus` and `onblur` land on the inner native input; other native attributes and events (such as `onmouseenter`) land on the root element, and `onclick` is called before the toggle. Inside a CheckboxGroup the group's `name` wins.

</Framework>

### CheckboxGroup

<Framework only="react">

<CheckboxGroupReactApi />

Other native attributes (such as `aria-label` and `data-*`) land on the root `div` (`role="group"`). `onBlur` fires only when focus leaves the whole group, not when it moves between Checkboxes in it. `aria-invalid` and `aria-errormessage` are passed to the native input of every Checkbox in the group; `aria-required`, `tabIndex` and the `aria-expanded`, `aria-haspopup` and `aria-controls` injected by Tooltip are not rendered.

</Framework>

<Framework only="vue">

<CheckboxGroupVueApi />

Each item in `options` has the fields `label`, `value`, `disabled`, `extra` (`string | number`), `class` and `style`, and no `onChange`. Use the `#label` and `#extra` scoped slots for custom content. `class`, `style` and native attributes passed as attrs land on the root element. `aria-invalid` and `aria-errormessage` are passed to the native input of every Checkbox in the group; `aria-required`, `tabindex` and the `aria-expanded`, `aria-haspopup`, `aria-controls` injected by Tooltip are not rendered.

</Framework>

<Framework only="solid">

<CheckboxGroupSolidApi />

`class`, `style`, `ref` and native attributes and events land on the root `<div>`; `onBlur` is called when focus leaves the whole group, not when it moves between the checkboxes inside. `aria-invalid` and `aria-errormessage` are passed to the native input of every Checkbox in the group; `aria-required`, `tabindex` and the `aria-expanded`, `aria-haspopup`, `aria-controls` injected by Tooltip are not rendered.

</Framework>

<Framework only="svelte">

<CheckboxGroupSvelteApi />

Each item in `options` has the fields `label`, `value`, `disabled`, `extra` (`string | number`), `class` and `style` (a string), and no `onChange`. Use the `label` and `extra` snippets, with the parameter `{ option, index }`, for custom content. `class`, `style` (a string), native attributes and events land on the root `<div>`; `onBlur` is called when focus leaves the whole group, not when it moves between the checkboxes inside. `aria-invalid` and `aria-errormessage` are passed to the native input of every Checkbox in the group; `aria-required`, `tabindex` and the `aria-expanded`, `aria-haspopup`, `aria-controls` injected by Tooltip are not rendered.

</Framework>

## Accessibility

### ARIA

- The role of Checkbox is `checkbox`, the role of CheckboxGroup is `group`, and its children have no extra role
- `aria-label`: When using the Checkbox alone, if Children have no text, it is recommended to pass in the `aria-label` prop to describe the function of the Checkbox in one sentence, which will make the screen reader read out the content of this label
- The native input's `aria-labelledby` points to the `addon` node, used to explain the role of the current Checkbox; a passed `aria-labelledby` also lands on the input, placed before the `addon` id
- `aria-describedby` points to the `extra` node, which is used to supplement the explanation of the current Checkbox
- The checked and disabled states are expressed by the native input's `checked` and `disabled`; `aria-checked` and `aria-disabled` are not rendered

<Framework only="react">

- If you are using Form.Checkbox, you can use the label provided by Form without passing in `aria-label`; the label injected by Form also lands on the input's `aria-labelledby`, placed before the `addon` id

</Framework>

### Keyboard and focus

- Checkbox can be focused, keyboard users can use Tab and Shift + Tab to switch focus.
- The Checkbox that gets the focus can switch the selected and unselected states through Space.
- The click area of ​​Checkbox is larger than the box itself and contains the text behind the box; for checkboxes with auxiliary text, the auxiliary text is also included in the click area.
- Disabled Checkbox is not focusable.
