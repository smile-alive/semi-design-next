### Controlled Component

<Framework only="react">

You can use `value` along with `onChange` property if you want to use Input as a controlled component.

</Framework>

<Framework only="vue">

Bind the value with `v-model`. With one-way `:modelValue` the component does not change its own value: when the parent does not accept the new value from `change`, the input returns to `modelValue`.

</Framework>

<Framework only="svelte">

Bind the value with `bind:value`. A plain `value={x}` is only the initial content, which the component then maintains itself; to let the parent decide whether to accept a new value, use `bind:value={get, set}`: when `set` does not update the state, the input returns to the value of `get`.

</Framework>

<Framework only="solid">

The value of `Input` is entirely determined by the `value` prop. Use it together with the `onChange` callback.

</Framework>

### Custom calculated character string length

By setting the getValueLength property, you can customize the length of the character string. With maxLength and minLength (maxlength and minlength in Vue), you can support emoji length to calculate according to the visible length.

What is done inside Semi when getValueLength is passed in:

<Framework only="react">

- maxLength: maxLength is not passed directly to the native input. If the input length exceeds the maximum limit, the legal length character entered last time is used.
- minLength: dynamically switch the length of minLength, emoji is calculated according to a length.
- maxCount: compare the values obtained using getValueLength with maxCount

</Framework>

<Framework only="vue">

- maxlength: maxlength is not passed directly to the native input. If the input length exceeds the maximum limit, the legal length character entered last time is used.
- minlength: dynamically switch the length of minlength, emoji is calculated according to a length.
- maxCount: compare the values obtained using getValueLength with maxCount

</Framework>

<Framework only="svelte">

- maxlength: maxlength is not passed directly to the native input. If the input length exceeds the maximum limit, the legal length character entered last time is used.
- minlength: the length of minlength is switched dynamically, and an emoji counts as one length.
- maxCount: the value obtained by getValueLength is compared with maxCount

</Framework>

<Framework only="solid">

- maxLength: maxLength is not passed directly to the native input. If the input length exceeds the maximum limit, the legal length character entered last time is used.
- minLength: dynamically switch the length of minLength, emoji is calculated according to a length.
- maxCount: compare the values obtained using getValueLength with maxCount

</Framework>

<Demo id="value-length" />

Answers to some questions:

> Why not just import the `grapheme-splitter` package? The uncompressed size of this package is 200+ kB, which is a bit too large for users who do not need to calculate emoji according to the visible length. Therefore, Semi chose to use the length calculation function as an argument for users to pass in

> Why not modify maxLength (maxlength in Vue) dynamically? Modify maxLength dynamically after the input operation is completed, calculate the remaining character length that can be entered. If the maxLength is set to 1, you want to enter a '💖' with a length of 2, but due to the limitation of input maxLength, you can't enter it at all here, and you can't update maxLength.

## API Reference

### Input

<Framework only="react">

> Other attributes are same with html `<input>`

<InputReactApi />

`className` and `style` land on the outer wrapper `div`; other native attributes and events (such as `aria-*`, `id`, `name` and `onClick`) land on the native `input`. `onFocus` and `onBlur` are listened for on the outer `div`, so moving focus between the input and the buttons inside the component does not fire them. `onCompositionStart`, `onCompositionEnd` and `onCompositionUpdate` are called when an IME composition starts, ends and updates, with the native event.

</Framework>

<Framework only="vue">

> Apart from `class` and `style`, undeclared attributes and listeners (including `@click`) are same with html `<input>` and land on the native input; `aria-*`, `id`, `name` and so on are among them. The `focus` and `blur` events are listened for on the outer element, so moving focus between the input and the buttons inside the component does not fire them.

<InputVueApi />

</Framework>

<Framework only="svelte">

> `class` and `style` land on the outer wrapper; other undeclared attributes and events (such as `aria-*`, `id`, `name` and `onclick`) behave like those of the html input tag and land on the native input. `onFocus` and `onBlur` listen on the outer element and do not fire when focus moves between the input and the buttons inside the component.

<InputSvelteApi />

<InputSolidApi />

### InputGroup

<Framework only="react">

`size` and `disabled` reach controls at any depth in the group through context (Button and the Buttons inside a ButtonGroup included), not only direct children. A value a control sets itself takes precedence over the group's, `disabled={false}` included. Other attributes such as `data-*`, `aria-*` and `id` land only on the `role="group"` element and are not passed to the controls; a `role`, `aria-label`, `aria-labelledby` or `id` you pass overrides the built-in value. The inputs and buttons that Select, Cascader, TreeSelect, AutoComplete, DatePicker, TimePicker, InputNumber and TagInput render inside themselves, and the controls in their popups, do not inherit from the group. onFocus and onBlur are not passed down to the controls: InputGroup listens for focus events on its own root element, so when a control gains or loses focus, the handlers of InputGroup and of the control both fire and neither overrides the other.

<InputGroupReactApi />

</Framework>

<Framework only="vue">

`size` and `disabled` reach controls at any depth in the group through provide/inject (Button and the Buttons inside a ButtonGroup included); a value a control sets itself takes precedence over the group's, including the template shorthand `disabled` and `:disabled="false"`. `class`, `style`, `data-*`, `aria-*`, `id` and other attributes land only on the `role="group"` element and are not passed to the controls; a `role`, `aria-label`, `aria-labelledby` or `id` you pass overrides the built-in value. The inputs and buttons that Select, Cascader, TreeSelect, AutoComplete, DatePicker, TimePicker, InputNumber and TagInput render inside themselves, and the controls in their popups, do not inherit from the group. `focus` and `blur` are the group's own events and are not passed to the controls: when a control gains or loses focus, the listeners of the group and of the control both fire and neither overrides the other. With a `label`, the `$el` of the component ref is the outer wrapper.

<InputGroupVueApi />

</Framework>

<Framework only="svelte">

`size` and `disabled` reach controls at any depth in the group through context (Button and the Buttons inside a ButtonGroup included); a value a control sets itself takes precedence over the group's, `disabled={false}` included. `class`, `style`, `data-*`, `aria-*`, `id` and other attributes land only on the `role="group"` element and are not passed to the controls; a `role`, `aria-label`, `aria-labelledby` or `id` you pass overrides the built-in value. The inputs and buttons that Select, Cascader, TreeSelect, AutoComplete, DatePicker, TimePicker, InputNumber and TagInput render inside themselves, and the controls in their popups, do not inherit from the group. `onFocus` and `onBlur` are callbacks of the group itself and are not passed to the controls: when a control in the group gains or loses focus, the handlers of the group and of the control both run, neither overriding the other.

With `label` (put the text in `label.text`, or write node content with the `fieldLabel` snippet and extra content with the `labelExtra` snippet), the group gets an outer wrapper, and the label names the whole `role="group"` element.

## Methods

<Framework only="react">

The ref of Input and TextArea is an imperative handle (`InputHandle` and `TextAreaHandle`), not the native DOM node. Read a node from the handle's properties when you need one: each read returns the node mounted now, and `null` after unmount.

Members are listed in the **Methods** tables of Input and TextArea above.

</Framework>

<Framework only="vue">

The template ref of Input and TextArea is an imperative handle (`InputHandle` and `TextAreaHandle`); see the Exposes table of each component above for its members. `input`, `textarea` and `nativeElement` return the node mounted now on each read, and `null` after unmount.

</Framework>

<Framework only="svelte">

Input and TextArea expose methods through `export function`; get the instance with `bind:this` and call them. The members are in the **Methods** tables of each component above. `getInput`, `getTextarea` and `getNativeElement` return the currently mounted node on every call, and `null` after unmount.

</Framework>

<Framework only="solid">

The ref of Input and TextArea is the outer wrapper `div`, not an imperative handle. `focus()` and `blur()` act on the inner input or textarea. For `select()`, `setSelectionRange()` and other native methods, get the native element through `inputRef` or `textareaRef`, then call the method on it.

</Framework>

## Accessibility

### ARIA

- When validateStatus is error, the aria-invalid of the input box is true
- When used in Form, the input is associated with the Field label through aria-labelledby

### Keyboard and focus

- Input can be focused, keyboard users can use Tab and Shift + Tab to switch focus
- The password visibility toggle is a native `button` named by the locale's "Show password" or "Hidden password" for its state; it can be focused and toggled with Enter or Space, after which the focus goes back to the input
- With `showClear`, a value, and no `disabled` (or with `showClearIgnoreDisabled`), the clear button is a native `button` named "Clear input" from the locale. Input shows it on hover or while focus is inside; TextArea does the same unless it is not editable. From the input, Tab moves to the clear button; Enter or Space clears and the focus goes back to the input. A mouse click on the clear button leaves the focus where it is
