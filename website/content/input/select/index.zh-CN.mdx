### 多选

自 v2.28后，select 的选择器会自带 maxHeight 270，内容超出后可以通过垂直滚动查看。

配置`multiple`属性，可以支持多选

配置 `maxTagCount` 可以限制已选项展示的数量，超出部分将以+N 的方式展示

配置 `ellipsisTrigger` (>= v2.28.0) 对溢出部分的 tag 做自适应处理，当宽度不足时，最后一个tag内容作截断处理。开启该功能后会有一定性能损耗，不推荐在大表单场景下使用

配置 `expandRestTagsOnClick` (>= v2.28.0) 可以在设置 `maxTagCount` 情况下通过点击展示全剩余的tag

使用 `showRestTagsPopover` (>= v2.22.0) 可以设置在超出 `maxTagCount` 后，hover +N 是否显示 Popover，默认为 `false`。并且，还可以在 `restTagsPopoverProps` 属性中配置 Popover。

### 搜索框位置

默认搜索框展示于 Select 的 Trigger 触发器上。通过 `searchPosition` 可以指定不同的位置，可选 `dropdown`、`trigger`。 在 v2.61.0后提供若希望定制位于 dropdown 中的 Input 搜索框的 placeholder，可以通过 `searchPlaceholder` 控制  
若 `searchPosition` 值为 `trigger`，当showClear=true 时，点击Trigger区域的清空按钮，将同时清空已选项以及搜索框中的文本  
若 `searchPosition` 值为 `dropdown`，当showClear=true 时，点击Trigger区域清空按钮，仅清空已选项。点击搜索框中的清空按钮，仅清空搜索文本

### 自定义已选项标签渲染

<Framework only="react">

默认情况下，选中选项后会将 option.label 或 option.children 的内容回填到选择框中  
但你可以通过 `renderSelectedItem` 自定义选择框中已选项标签的渲染结构

- 单选时 `renderSelectedItem(optionNode:object) => content:ReactNode`
- 多选时 `renderSelectedItem(optionNode:object, { index:number, onClose:function }) => { isRenderInTag:bool, content:ReactNode }`
    - isRenderInTag 为 true 时，会自动将 content 包裹在 Tag 中渲染（带有背景色以及关闭按钮）
    - isRenderInTag 为 false 时，将直接渲染返回的 content

</Framework>

<Framework only="vue">

默认情况下，选中选项后会将选项的 label 或默认插槽的内容回填到选择框中  
但你可以通过作用域插槽自定义选择框中已选项的渲染结构，参数为 `{ option, index, disabled, onClose }`

- `#selectedItem`：单选时替换选择框中显示的内容；多选时只替换内置标签里的内容，标签仍带有背景色以及关闭按钮
- `#tag`：多选时替换整个标签，同时提供时优先于 `#selectedItem`
- 调用 `onClose` 移除该选项，单选时清空选中值

</Framework>

<Framework only="solid">

默认情况下，选中选项后会将 Option 的 children 回填到选择框中，没有 children 时回填 label  
但你可以通过 `renderSelectedItem` 自定义选择框中已选项标签的渲染结构

- 单选时 `renderSelectedItem(optionNode:object) => content:JSX.Element`
- 多选时 `renderSelectedItem(optionNode:object, { index:number, disabled:boolean, onClose:function }) => { isRenderInTag:bool, content:JSX.Element }`
    - isRenderInTag 为 true 时，会自动将 content 包裹在 Tag 中渲染（带有背景色以及关闭按钮）
    - isRenderInTag 为 false 时，将直接渲染返回的 content
- 写在 `Select.Option` 上的其他属性（如示例中的 `email`）会随 optionNode 一起传入

</Framework>

### 虚拟化

传入`virtualize`时开启列表虚拟化，用于大量 Option 节点的情况优化性能  
virtualize 是一个包含下列值的对象：

- height: Option 列表高度值，默认 270 (v2.20.8 前为 300)
- width: Option 列表宽度值，默认 100%
- itemSize: 每行 Option 的高度，必传

<Notice title="关于高度设置">当 virtualize.height 大于默认值 270px 时，为了避免出现双滚动条问题，需要将 maxHeight 属性设置为与 virtualize.height 相同的值。 例如：当设置 virtualize.height 为 400px 时，应同时将 maxHeight 设置为 400。</Notice>

### 自定义触发器

<Framework only="react">

如果 Select 默认的触发器样式满足不了你的需求，可以用`triggerRender`自定义选择框的展示

```typescript
    onClear: () => void; // 用于清空值的函数
    disabled: boolean; // 是否禁用Select
    placeholder: ReactNode; // Select的placeholder
    componentProps: object; // 所有用户传给Select的props
}
```

</Framework>

```typescript
    placeholder?: string; // Select 的 placeholder
    disabled: boolean; // 是否禁用 Select
    componentProps: Record<string, unknown>; // 所有传给 Select 的 props
    onSearch: (inputValue: string) => void; // 更新搜索关键字，用于把自定义 Input 的值同步给 Select 内部。需同时设置 filter
    onClear: (event?: MouseEvent) => void; // 清空已选值。绑在触发器内的控件上时传入点击事件，避免这次点击重新打开下拉列表
```

### 自定义候选项渲染

<Framework only="react">

- 简单的自定义：通过 Option 的 label 属性或者 children 传入 ReactNode，你可以控制候选项的渲染，此时内容会自动带上内边距、背景色等样式
- 完全自定义：通过传入`renderOptionItem`，你可以完全接管列表中候选项的渲染，并且从回调入参中，获取到相关的状态值。实现更高自由度的结构渲染  
  注意事项：
    1. props 传入的 style 需在 wrapper dom 上进行消费，否则在虚拟化场景下会无法正常使用
    2. props 传入的 className、onMouseEnter 需在 wrapper dom 上进行消费，否则上下键盘操作时显示会有问题
    3. 选中(selected)、聚焦(focused)、禁用(disabled)等状态的样式需自行加上，你可以从 props 中获取到相对的 boolean 值

## Accessibility

### ARIA

- 按 ARIA 1.2 的 combobox 写法，任一时刻只有一个元素是 combobox，弹出层的 role 为 listbox，可选项的 role 为 option：
    - 不可搜索，或搜索框在下拉内（`searchPosition="dropdown"`）时，Select trigger 是 select-only combobox，选中的内容是它的值
    - 搜索框在 trigger 内时，搜索框本身是 combobox，带 `aria-autocomplete="list"`，trigger 不再有角色和 Tab 停靠点。单选的搜索框只在搜索时出现，未搜索时 trigger 仍是 combobox；搜索框在输入前为空，已选文本以 `aria-describedby` 关联为它的描述。多选的搜索框一直存在
    - 下拉内的搜索框保持文本框角色，带 `aria-controls`、`aria-autocomplete`、`aria-activedescendant`，名称与 combobox 相同
- combobox 的名称按优先级取：`aria-labelledby`、`aria-label`、实际渲染出来的 insetLabel（combobox 的 `aria-labelledby` 指向它，未传 `insetLabelId` 时组件生成 id；有 prefix 时 insetLabel 不渲染，也不作名称），都没有时为语言包中的「选择」。建议传入与表单标签一致的名称。listbox 与下拉内的搜索框使用同一个名称来源，不指向 combobox 自身。选中的内容是 combobox 的值，不计入名称
- combobox 具有 aria-haspopup、aria-expanded、aria-controls 属性，表示它与弹出层的关系
- 多选时，listbox aria-multiselectable 为 true，表示当前可以多选
- Option 选中时，aria-selected 为 true；当 Option 禁用时，aria-disabled 为 true
- 带 label 的 OptGroup 中的选项位于 `role="group"` 内，以分组标题为名称（`aria-labelledby`），读屏会读出选项所属的分组；虚拟列表不显示分组标题，不包分组
- 下拉打开时，属性 aria-activedescendant 指向键盘聚焦的 option，保证在朗读旁白时识别到当前的选择的 option；完全自定义候选项渲染时请把参数中的 `id` 写在 option 元素上(更多用法请参考[Managing Focus in Composites Using aria-activedescendant](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#kbd_focus_activedescendant))

### 键盘和焦点

**不带 Filter 功能，或搜索框在下拉内（`searchPosition="dropdown"`）的 Select：**

- Select 聚焦后，键盘用户可以通过 `空格`、`上箭头`、`下箭头`（含 `Alt` + `下箭头`）或 `Enter` 键打开下拉菜单。已有选中值时焦点落在第一个已选的选项上，直接按 Enter 不改变值；没有选中值时保留当前高亮，初始高亮为第一个未禁用的选项（`defaultActiveFirstOption` 默认为 true）
- `Home`、`End` 打开下拉菜单，并把焦点移到第一个、最后一个可用选项
- 输入字符打开下拉菜单，并把焦点移到下一个以该字符开头的选项；快速连续输入时按整串匹配，重复输入同一字符时在以它开头的选项间轮换
- 当下拉菜单打开时：
    - 使用 `Esc` 键或 `Tab` 键可以关闭菜单
    - 使用 `上箭头` 或 `下箭头` 可以切换选项，`Home`、`End` 移到首尾，输入字符移到以它开头的选项
    - 被聚焦的选项可以通过 `Enter` 或 `空格` 选中：单选选中后收起面板，多选切换选中状态并保持打开。快速连续输入字符的过程中，`空格` 计入匹配的字符串，不选中选项。焦点在下拉内的搜索框时，`Home`、`End`、`空格` 与字符用于编辑搜索内容，不移动选项焦点
- 多选时焦点在已选标签上，按键只作用于标签：`Backspace`、`Delete` 删除标签，`Enter`、`空格` 不打开下拉菜单、不改变选中值
- 当焦点在下拉菜单中，且用户使用的 `innerBottomSlot` 或 `outerBottomSlot` 属性的自定义 slot 中含有可交互元素时：
    - 可以使用 `Tab` 键切换到这些可交互元素上
    - 当焦点在自定义 slot 的首个可交互元素上时，使用 `Shift` + `Tab` ，焦点回到 Select 框上

**带 Filter 功能的 Select：**

- Select 聚焦后，键盘用户可以通过 `上箭头` 或 `下箭头` 或 `Enter` 键打开下拉菜单。此时焦点仍然处于 Select 框，用户可以输入内容，同时也能使用 `上箭头` 或 `下箭头` 切换选项
- 当下拉菜单打开时：使用 `上箭头` 或 `下箭头` 切换选项；`Enter` 选中被聚焦的选项，单选选中后收起面板，多选切换选中状态并保持打开；`Esc` 或 `Tab` 关闭菜单。`Home`、`End`、`空格` 与字符留给 Select 框内的输入框，用于编辑搜索内容，不移动选项焦点
- 当焦点在 Select 框上，且用户使用的 `innerBottomSlot` 或 `outerBottomSlot` 属性的自定义 slot 中含有可交互元素时：
    - 可以使用 `Tab` 键切换到这些可交互元素上
    - 当焦点在自定义 slot 的首个可交互元素上时，使用 `Shift` + `Tab` ，焦点回到 Select 框上

**清除按钮：**

- `showClear` 开启、有已选值或搜索文本且未禁用时，trigger 内渲染清除按钮。它是原生 `button`，名称为语言包中的「清空已选值」，在 hover、下拉打开或焦点位于 Select 内时显示
- 焦点在 Select 框上时按 `Tab` 移到清除按钮，`Enter` 或 `Space` 清空，效果与鼠标点击相同；清空后焦点回到 Select 框

## 文案规范

- 选择器标签
    - 用 1-3 个词描述需要用户所做的输入
    - 使用语句书写规范（首字母大写，其余小写）
    - 避免使用标点符号和介词（“the”, “an”, “a”）
    - 标签需是独立语句。不要让标签是前半句语句，选项是后半句语句。
    - 使用描述性语句，而不是指示性语句。如果选项需要更多解释，可以在选择框下使用帮助文本。
- 选择器选项
    - 如果没有默认选项，就使用“Select”做占位文案
    - 选项要按首字母顺序或者其他有逻辑的排列顺序，使用户更好地找到选项
    - 使用语句书写规范（首字母大写，其余小写），避免在句尾使用逗号和分号
    - 清晰表达出选项所表示的选择目的

## TypeScript 泛型支持

<Framework only="vue">

`Select` 是泛型组件，有两个泛型参数：`T` 是选项 value 的类型（设置 `changeWithObject` 时是 option 对象的类型），`Multiple` 是 `multiple` 属性的类型。单选时 `change` 与 `update:modelValue` 的载荷为 `T | undefined`，多选时为 `T[]`；`multiple` 是 `boolean` 变量时为 `T | T[] | undefined`。`select`、`deselect` 的载荷是选项的原始 value（`string | number`），不随 `T` 变化。两个参数通常由 `modelValue` 与 `multiple` 推断；全局默认值不能设置 `multiple`，因为给它一个默认值会破坏这一推断。

```vue
<script setup lang="ts">
    import { ref } from 'vue';
    import { Select } from '@fibrae/semi-ui-vue';

    // 由 modelValue 推断 T 为 string
    const value = ref<string | undefined>();
    // 多选时 modelValue 为 string[]
    const values = ref<string[]>([]);
</script>

<template>
    <Select v-model="value">
        <Select.Option value="option1">选项 1</Select.Option>
        <Select.Option value="option2">选项 2</Select.Option>
    </Select>
    <Select v-model="values" multiple>
        <Select.Option value="option1">选项 1</Select.Option>
        <Select.Option value="option2">选项 2</Select.Option>
    </Select>
</template>
```

</Framework>

`Select` 有两个泛型参数：`T` 是选项 value 的类型（设置 `onChangeWithObject` 时是 option 对象的类型），`Multiple` 是 `multiple` 属性的类型。单选时 `onChange` 的入参为 `T | undefined`，多选时为 `T[]`；`multiple` 是 `boolean` 变量时为 `T | T[] | undefined`。`onSelect`、`onDeselect` 的入参是选项的原始 value（`string | number`），不随 `T` 变化。两个参数通常由 `value` 与 `multiple` 推断；多选时显式写 `T` 需要同时写 `Multiple`。

```jsx
import { Select } from '@fibrae/semi-ui-solid';

// 由 value 推断 T 为 string，value 为 string | undefined
<Select value={selectedValue()} onChange={(value) => setSelectedValue(value)}>
    <Select.Option value="option1">选项 1</Select.Option>
    <Select.Option value="option2">选项 2</Select.Option>
</Select>

// 多选时 value 为 string[]
<Select multiple value={selectedValues()} onChange={(value) => setSelectedValues(value)}>
    <Select.Option value="option1">选项 1</Select.Option>
    <Select.Option value="option2">选项 2</Select.Option>
</Select>

// 多选时显式写泛型参数
<Select<string, true> multiple onChange={(value) => setSelectedValues(value)}>
    <Select.Option value="option1">选项 1</Select.Option>
    <Select.Option value="option2">选项 2</Select.Option>
</Select>
```

## FAQ

- **可搜索的 Select，使用远程数据动态更新`optionList`，为什么在异步请求完成之前有时候会出现暂无数据？**  
   请检查是否开启了 `remote`，不开启 remote 的情况下，默认会将 input 框输入值与当前的 optionList 进行一次对比筛选，如果无匹配时，就会显示暂无数据。  
   可以通过开启 remote 关闭对本地当前数据的匹配筛选。

- **Select 会自动限制下拉菜单的宽度吗？**

    - 会给 minWidth，但不会写死 width。如果有需要的话，可以自己通过 dropdownStyle 来添加。

- **为什么单选选择选项后没有触发 blur 事件？**
    - 在 V2.17.0 前，Select 单选选择后，会触发 Select 的 blur 事件。
    - 在 V2.17.0 后，Select 增加了 A11y 支持，不会触发 Select 的 blur 事件。
        - 单选选择中，Select 浮层关闭，依然保持焦点在 trigger（此时可以通过 Enter 回车键再次打开 Select 浮层）
        - 无论单选或多选，按下 Esc，仅 Select 浮层关闭，trigger 保持焦点（此时可以通过 Enter 回车键再次打开 Select 浮层）
