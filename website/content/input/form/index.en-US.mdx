## Form

- **Rerender on demand**, avoids unnecessary full-volume rendering, higher performance
- Easy to use, **simple structure**, avoids unnecessary hierarchical nesting
- Perfect accessibility support
- FormState / FieldState can also be easily obtained from outside the Form Provides an external method to operate inside the form: formApi / fieldApi
- Support for encapsulating custom components into form controls, and you can quickly access your team's components through the extension mechanism provided by Form (through `withField`)
- Support Form level / Field level assignment, verification (synchronous / asynchronous)

## Field

<Framework only="react">

Semi encapsulates all form field component (Input、Select、Checkbox、DatePicker etc.) with `withField` once.  
Taking over their data flow (`props.value` & `props.onChange`)  
When in use, you need to use the components whose names start with Form (note: only these components have data synchronization). They are named exports and are not mounted under Form.

### Supported Field Component

- Fields: `FormInput`, `FormInputNumber`, `FormTextArea`, `FormSelect`, `FormCheckbox`, `FormCheckboxGroup`, `FormRadio`, `FormRadioGroup`, `FormSwitch`, `FormDatePicker`, `FormTimePicker`, `FormSlider`, `FormTreeSelect`, `FormCascader`, `FormTransfer`, `FormRating`, `FormAutoComplete`, `FormUpload`, `FormPinCode`, `FormTagInput`
- Other parts: `ArrayField`, `FormInputGroup`, `FormLabel`, `FormErrorMessage`, `FormSection`, `FormSlot`

```jsx
// A field takes over its data flow when used inside <Form>
import { Form, FormInput, FormSelect } from '@fibrae/semi-ui-react';
// A plain Input is left untouched by the Form
import { Input } from '@fibrae/semi-ui-react';
```

The Field level component provided by Form, its `value` (or other properties specified by `valueKey`), onChange (or other callback functions specified by `onKeyChangeFnName`) Properties are hijacked by Form, so

<Notice type="primary" title="Notice">

1. No longer need to manually bind the onChange event and update the value as controlled component. But you can continue to listen onChange events for the latest values if you want
2. You cannot set the state of component with attributes such as `value`, `defaultValue`, `checked`, `defaultChecked`, etc. The default value can be set by Field's `initValue` or Form's `unitValues`
3. You should not modify the value of Form State directly, all changes to the data in the Form should be done by providing `formApi`, `fieldApi`

</Notice>

</Framework>

### Remove automatically added Label

Form will automatically insert `Label` for Field control. If you don't need to automatically insert the Label module, you can turn off the automatic label insertion function by setting `noLabel=true` in the Field (at this time, the Field still has the ability to automatically display ErrorMessage, so the DOM structure is still different from the original component)

At this time, the DOM structure will not change except that the data flow is taken over (you need to be responsible for the rendering of ErrorMessage, and it cannot be used by formProps.wrapperCol property impact)

### Embedded Label

A Label can be inlined in a field control by setting labelPosition to `inset`. Components currently supporting this feature include `Input`, `InputNumber`, `DatePicker`, `TimePicker`, `Select`, `TreeSelect`, `Cascader`, `TagInput`, `AutoComplete`. With labelPosition `inset`, the other fields are laid out as `top` and warn in development mode.

<Framework only="vue">

A component that does not declare it is laid out as `top` too.

</Framework>

<Framework only="solid">

</Framework>

<Framework only="svelte">

### Configure initial values and verification rules

- You can configure check rules for each Field through `rules`. Rules are run by Semi's built-in rule engine, see the table below
- You can uniformly set the initial value for the entire form through the `initValues` of form, or you can set the initial value through `initValue` in each field (the latter has a higher priority)
- You can configure different verification trigger timings for each Field through `trigger`, and the default is `change` (that is, the verification is performed automatically when the value changes). Also supports `change`, `blur`, `mount`, `custom` or a combination of the above. It also supports unified configuration through FormProps. If both are configured, FieldProps shall prevail
- You can use the `stopValidateWithError` switch to decide whether to continue to trigger the validation of subsequent rules when the first rule that fails the validation is encountered. Unified configuration through FormProps is also supported. If both are configured, FieldProps shall prevail

<Demo id="rules" />

Each rule (`RuleItem`) is checked from top to bottom in the table below, and the message of the first failing check becomes the error of that rule. When the value is empty (`undefined`, `null`, `''`, `[]`) and not required, the built-in checks are skipped and only `validator` runs.

| Property      | Description                                                                                                                                                                                                                                          |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| transform     | `(value) => any`, converts the value before validation, affecting this rule only                                                                                                                                                                     |
| required      | Fails when the value is empty; with `whitespace: true`, a string containing only whitespace also counts as empty                                                                                                                                     |
| type          | Value type: `string`, `number`, `integer`, `float`, `boolean`, `array`, `object`, `date`, `email`, `url`, `regexp`, `method`                                                                                                                         |
| len, min, max | Compares the character count of a string, the value of a number, and the item count of an array                                                                                                                                                      |
| pattern       | A RegExp or a regex string; only checks strings                                                                                                                                                                                                      |
| enum          | The value must be one of the items in the array                                                                                                                                                                                                      |
| validator     | `(value, values) => string \| string[] \| boolean \| Promise<...>`, runs after the built-in checks pass. Fails when it returns `false` or throws; a non-empty string or string array is used as the error message; any other result counts as passed |
| message       | Replaces the default message of any check in this rule; pass `''` to fail without showing text                                                                                                                                                       |

Default messages come from the `Form` section of the locale and follow LocaleProvider (for example "This field is required" and "At least 3 characters").

### Validate with a Schema

`schema` accepts any validation library that implements [Standard Schema](https://standardschema.dev), such as [Zod](https://zod.dev), [Valibot](https://valibot.dev) and [ArkType](https://arktype.io). You install the library yourself; Semi does not depend on it.

Fields validate on their own `trigger` as usual, and submit validates all of them. Once all fields pass, the submit callback and `formApi.validate()` receive the schema's output (trimmed or coerced values, for example) while `formState.values` keeps what the user typed. `formApi.validate(['fieldA'])` validates only some fields and resolves with the raw values.

<Demo id="schema-validate" />

Where validation comes from and where errors go:

- A Form validates from one source. With a `schema`, the `validator` and `rules` of the fields no longer run, and the Form warns in development; a field sits on another component, so TypeScript cannot catch this combination. Passing both the Form `validator` and `schema` is a TypeScript error; past the types, the Form warns in development and uses only `validator`.
- One validation round runs the schema once. Asynchronous checks in the schema, such as a uniqueness request, run every round. To limit requests, set `schemaDebounce` (in milliseconds) on the Form: validation triggered by a value change waits until input pauses, while validation triggered by submit, `formApi.validate()` or blur does not wait. You can also set the field's `trigger` to `blur`.
- Write errors returned by a server after submit with `formApi.setError`; the schema's result replaces them the next time that field validates.
- Changing a field shows errors only on that field and on touched fields, so a cross-field error needs a `path` pointing at the field that shows it, like the password confirmation in the demo.
- An error whose path points inside a field (`tags[0]` of a TagInput, for example) shows on the field holding that value. An error without a matching field is not displayed and stays in `formState.errors`; root-level schema errors go to `errors['']`.

When using Zod:

- With `allowEmpty` off, a field left blank or cleared holds `undefined`, not an empty string. Write a required field as `z.string({ error: 'Please enter a name' })`; `.min(1, '...')` alone shows Zod's type error.
- While a field is blank, Zod does not run an object-level `refine`, so a cross-field error appears only after the related fields have values.
- `z.object` drops undeclared keys by default, so those fields are missing from the values the submit callback receives. Use `z.looseObject` to keep them.
- Zod decides the error language; Semi's locale does not affect it. Call `z.config(z.locales.en())`, or write your own messages as in the demo.
- Write `import * as z from 'zod'` so the bundler can drop the parts you do not use.

With a `schema`, the required asterisk and `aria-required` are decided only by `required: true` in the field's `label` config; they do not read `rules` and are not derived from the schema. A field's `transform` does not change the value the schema receives.

### Render a form from a Schema

SchemaForm renders a whole form directly from a schema. With the Form `schema` passed in, SchemaForm derives a JSON Schema from it and renders a field for each property in property order. Deriving requires the validation library to implement [Standard JSON Schema](https://standardschema.dev/json-schema) (such as Zod 4); a JSON Schema from any other source can be passed directly to `jsonSchema`, which takes precedence over the derived result. SchemaForm accepts all Form props, and renders children after the fields, which suits a submit button.

<Demo id="schema-form" />

How JSON Schema maps to controls:

| JSON Schema                                                 | Control                                                                                                                                                     |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `string`                                                    | Input; TextArea when `maxLength` is greater than 160                                                                                                        |
| `number`, `integer`                                         | InputNumber; only integers can be entered for `integer`                                                                                                     |
| `boolean`                                                   | Switch                                                                                                                                                      |
| `enum`, or `oneOf` / `anyOf` where every item has a `const` | Select; option text comes from the `title` of each item                                                                                                     |
| `array` whose items are options                             | Multi-select Select                                                                                                                                         |
| `object` with `properties`                                  | Section; the heading comes from `title`                                                                                                                     |
| Any other `array`                                           | ArrayField; each row has move up, move down and remove buttons, with an add button below the list; the row count is fixed when `minItems` equals `maxItems` |

The label comes from `title` (the property name when absent), the help text from `description`, the initial value from `default`, and properties listed in `required` show the required asterisk. A node that maps to no control is not rendered, and a warning is shown in development.

SchemaField renders part of a schema inside an existing Form: `field` sets the path (the root by default), and it can be mixed with hand-written fields. Both can be customized with `widgets` and `renderField`:

- `widgets`: the key is a JSON Schema `format` (such as `uri`, `email`) or a control kind (`input`, `textarea`, `number`, `switch`, `select`), and the value is a field component (such as FormInput, or a component wrapped with withField). `format` is looked up first, then the control kind.
- `renderField`: the key is a field path, with array rows written as `[]` (such as `contacts[].email`); when it matches, it renders that node and its children.

## Accessibility

### ARIA

- [aria-labelledby](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-labelledby)、for
    - Field component will automatically add label DOM. The id of the control is `props.id`, generated when omitted; the for attribute of label is the same as this id; the `id` attribute of label is `${control id}-label`;
    - When the props.labelPosition of the Form or Field is set to `inset`, there is no label tag at this time, but a div tag. The div tag corresponding to insetLabel will be automatically appended with `id`, the value is the same as the id of the above label, corresponding to the `aria-labelledby` of the Field component. A field that does not support the inset label is laid out as `top`, and its `aria-labelledby` points to the label actually rendered
    - The Field component will be automatically appended with `aria-labelledby`, the value is the same as the id of the above label; the `aria-labelledby` passed by the caller comes first and the two are merged instead of overwritten
- [aria-required](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Techniques/Using_the_aria-required_attribute)
    - When the Field is configured with required fields (that is, props.rules contains required: true or props.label is configured with required: true without optional: true; with a Form `schema`, only label is read), the Field component will be automatically appended with `aria-required = true` (except CheckboxGroup, Slider, Upload and a single Radio); an aria-required passed on the Field takes precedence
- [aria-invalid](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Techniques/Using_the_aria-invalid_attribute) 、[aria-errormessage](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-errormessage)
    - When the Field check fails, or validateStatus is error, the Field component will be automatically added with the `aria-invalid` = true attribute.
    - When the Field check fails, the Field component will be automatically appended with the `aria-errormessage` attribute, the value of which is the id of the DOM element corresponding to the errorMessage (format like: `${control id}-errormessage`); for CheckboxGroup it is set on every checkbox in the group.
- [aria-describedby](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Techniques/Using_the_aria-describedby_attribute)
    - When the Field is configured with `helpText` or `extraText`, the Field component will be automatically added with the `aria-describedby` attribute, whose value is the id of the DOM element corresponding to helpText and extraText (format like: `${control id}-helpText` , `${control id}-extraText`); the `aria-describedby` passed by the caller comes first and the two are merged instead of overwritten

## Content Guidelines

- Form title
    - The title of the form needs to follow the writing specification of the title
- Form label
    - The label is a short description of the input box. The label is not a help text, so it should not be a description of the input
    - Labels must:
        - Place it above or below the input box
        - Short (1-3 words)
        - Use case conventions for statements (first letter uppercase, others lowercase)
- Help text
    - Help text use statement writing conventions, capitalized
- Form button
    - For the content Guidelines of the form button, refer to [Button component](/en-US/react/basic/button)

## FAQ

- **Why did I declare the form, modify the value, and the data is not automatically mapped to formState.values?**  
  Check that the field has been passed correctly, and the `field` attribute on the Field component is a must-fill property !

- **Why doesn't the passed `defaultValue` or `defaultChecked` take effect?**  
  Refer to the beginning of the document [Field](#Field). The Field component unifies the default value. You should pass the default value using `initValue` or `initValues`

- **Why did the component not change and the value not take effect after `initValue` and `initValues` were updated asynchronously?**  
  `initValue`, `initValues` are only consumed once when Field and Form mount, and subsequent asynchronous updates will not take effect.  
  If your initial value needs to be taken remotely, you can update it using `formApi.setValue / setValues` after you get the value  
  Or send a new `key` directly to Form or Field to force it to remount.

- **Why is the error message not shown when the validator in rules fails?**

    `rules[].validator` fails when it returns `false` or throws, and shows the `message` of the rule (the default message or the message of the error when there is none); when it returns a string or an array of strings, that is used directly as the error message. Any other return value, such as `true`, `undefined` or an empty string, counts as passed. Also, when `message` is an empty string, the field is only marked red and no text is shown.

- **Why can't getValues get a certain field?**

    If the field has no initial value, `getValues` cannot get this item. You can set `initValues`/`initValue` or set the `allowEmpty` attribute to the form.

- **Why does hitting enter on the input box trigger the form's submit?**

    This is standard HTML behavior. We do not plan to intervene and we will remain the same as the HTML. If there is really only one input element in the form, and you don't want to trigger the submit callback when you press Enter, it is recommended to use preventDefault for the enter of the keydown event of input to prevent the default behavior.

    Click <a href="https://github.com/DouyinFE/semi-design/issues/767" target="_blank">#767</a> for background and content.

- **The form will automatically save the historical input items, what should I do if I don't want this function?**  
  Before v2.3, Form did not configure `for`, `name`, `id` and other attributes for input controls strictly according to the A11y accessibility standard, so this function was not available in previous versions. After v2.3, we implemented it strictly according to the W3C standard. If you don't want the browser to automatically save history input items, you can also turn it off by setting `autoComplete=off` at the Form level or Field level
