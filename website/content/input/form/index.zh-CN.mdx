## 表单(Form)

- **按需重绘**，避免了不必要的全量渲染, 性能更高
- 简单易用，**结构极简**，避免了不必要的层级嵌套
- 完善的无障碍支持
- 在 Form 外部可方便地获取 formState / fieldState  
  提供在外部对表单内部进行操作的方法：formApi / fieldApi
- 支持将自定义组件封装成表单控件，你可以通过 Form 提供的扩展机制（withField）快捷接入自己团队的组件
- 支持 Form level / Field level 级别的赋值、校验（同步/异步）

## 表单控件(Field)

<Framework only="react">

Semi 将所有自带的输入控件（文本输入框、下拉选择、复选框、单选框等）都使用 withField 封装了一次。接管了他们的数据流（value & onChange）  
使用的时候，需要使用以 Form 开头的控件（注意：只有这些控件才具有数据同步功能），它们是具名导出，不挂载在 Form 上

### 目前 Form 提供了如下表单控件

- 表单控件：`FormInput`、`FormInputNumber`、`FormTextArea`、`FormSelect`、`FormCheckbox`、`FormCheckboxGroup`、`FormRadio`、`FormRadioGroup`、`FormSwitch`、`FormDatePicker`、`FormTimePicker`、`FormSlider`、`FormTreeSelect`、`FormCascader`、`FormTransfer`、`FormRating`、`FormAutoComplete`、`FormUpload`、`FormPinCode`、`FormTagInput`
- 其他部件：`ArrayField`、`FormInputGroup`、`FormLabel`、`FormErrorMessage`、`FormSection`、`FormSlot`

```jsx
// 具有数据同步功能的表单控件，在 <Form> 内使用时，数据流会被 Form 自动接管
import { Form, FormInput, FormSelect } from '@fibrae/semi-ui-react';
// 普通 Input，在 <Form> 内部使用时，Form 不会对其做任何处理
import { Input } from '@fibrae/semi-ui-react';
```

Form 提供的 Field 级别组件，它的 value（或者 valueKey 指定的其他属性）、onChange（或 onKeyChangeFnName 指定的其他回调函数）属性都会被 Form 劫持，所以

<Notice type="primary" title="注意事项">

1. 你不需要也不应该用 onChange 来作同步，当然你可以继续监听 onChange 事件获取最新的值
2. 你不能再用控件的 `value`、`defaultValue`、`checked`、`defaultChecked` 等属性来设置表单控件的值，默认值可以通过 Field 的 `initValue` 或者 Form 的 `initValues` 设置
3. 你不应该直接修改 FormState 的值，所有对 Form 内数据的修改都应该通过提供的 formApi、fieldApi 来完成

</Notice>

</Framework>

### 表单控件值的绑定

每个表单控件都需要以`field`属性绑定一个字段名称，用于将表单项的值正确映射到`FormState` values / errors / touched 中  
字段可以是简单的字符串，可以是包含`.`或者`[]`的字符串, 支持多级嵌套  
下面是字段名称以及他们在 FormState 中的映射路径的示例

| Field                  | Resolution                         |
| ---------------------- | ---------------------------------- |
| username               | formState.values.username          |
| user\[0\]              | formState.values.user\[0\]         |
| siblings.1             | formState.values.siblings\[1\]     |
| siblings\['2'\]        | formState.values.siblings\[2\]     |
| parents\[0\].name      | formState.values.parents\[0\].name |
| parents\[1\]\['name'\] | formState.values.parents\[1\].name |

### 隐藏Label

Form 会自动为 Field 控件插入 Label。如果你不需要自动插入 Label 模块, 可以通过在 Field 中设置`noLabel=true`将自动插入 Label 功能关闭（此时 Field 仍然具备自动展示 ErrorMessage 的能力，因此 DOM 结构与原始控件依然会有区别）  
如果你希望与原始控件保持 DOM 结构一致，可以使用 pure=true，此时除了数据流被接管外，DOM结构不会有任何变化（你需要自行负责 ErrorMessage的渲染，同时它也无法被 formProps.wrapperCol 属性影响）

### 内嵌 Label

通过将 labelPosition 设为`inset`，可以将 Label 内嵌在表单控件中。目前支持这项功能的组件有`Input`、`InputNumber`、`DatePicker`、`TimePicker`、`Select`、`TreeSelect`、`Cascader`、`TagInput`、`AutoComplete`。其余字段在 labelPosition 为`inset`时按`top`布局，并在开发模式下给出警告。

<Framework only="vue">

用 `withField` 封装的自定义组件，声明了 `insetLabelId` 属性才会按内嵌标签布局：此时组件通过 `#insetLabel` 插槽收到标签内容，并把 `insetLabelId` 写到承载标签的元素上；没有声明的组件同样按 `top` 布局。

</Framework>

<Framework only="solid">

用 `withField` 封装的自定义组件在 labelPosition 为`inset`时会收到 `insetLabel` 与 `insetLabelId` 两个 props：组件需要自行渲染内嵌标签，并把 `insetLabelId` 写到承载标签的元素上；不渲染内嵌标签的组件不应使用`inset`。

### 配置初始值与校验规则

- 你可以通过`rules`为每个 Field 表单控件配置校验规则，规则由 Semi 自带的规则引擎执行，见下表
- 你可以通过 form 的`initValues`为整个表单统一设置初始值，也可以在每个 field 中通过`initValue`设置初始值（后者优先级更高）
- 可以通过 trigger 为每个 Field 配置不同的校验触发时机，默认为 change（即值变化时，自动进行校验）。还支持 change、blur、mount、custom 或以上的组合。也支持通过 FormProps 统一配置，若都配置时，以 FieldProps 为准
- 可以通过 stopValidateWithError 开关，决定使用 rules 校验时，当碰到第一个检验不通过的 rules 后，是否继续触发后续 rules 的校验。也支持通过 FormProps 统一配置，若都配置时，以 FieldProps 为准

<Demo id="rules" />

每条规则（`RuleItem`）按下表从上到下检查，遇到第一个失败的检查就以它的文案作为这条规则的错误。值为空（`undefined`、`null`、`''`、`[]`）且不要求必填时，跳过内置检查，只运行 `validator`。

| 属性          | 说明                                                                                                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| transform     | `(value) => any`，校验前转换值，只影响本条规则                                                                                                                            |
| required      | 值为空时失败；`whitespace: true` 时只含空白的字符串也算空                                                                                                                 |
| type          | 值的类型：`string`、`number`、`integer`、`float`、`boolean`、`array`、`object`、`date`、`email`、`url`、`regexp`、`method`                                                |
| len、min、max | 字符串比较字符数，数字比较数值，数组比较项数                                                                                                                              |
| pattern       | 正则或正则字符串，只检查字符串                                                                                                                                            |
| enum          | 值必须是数组中的一项                                                                                                                                                      |
| validator     | `(value, values) => string \| string[] \| boolean \| Promise<...>`，内置检查通过后运行；返回 `false` 或抛错时失败，返回非空字符串或字符串数组时作为错误信息，其余视为通过 |
| message       | 替换本条规则任一检查的默认文案；传 `''` 时失败但不显示文字                                                                                                                |

默认文案来自语言包的 `Form` 部分（如「此项为必填项」「至少 3 个字符」），随 LocaleProvider 切换语言。

### 使用 Schema 校验

`schema` 接受实现了 [Standard Schema](https://standardschema.dev) 的校验库，如 [Zod](https://zod.dev)、[Valibot](https://valibot.dev)、[ArkType](https://arktype.io)。这些库由你自己安装，Semi 不依赖它们。

字段照常按自己的 `trigger` 校验，提交时校验全部字段。校验全部字段通过后，提交回调和 `formApi.validate()` 拿到 schema 的输出（如 trim、类型转换后的值），`formState.values` 仍是用户输入的原值；`formApi.validate(['fieldA'])` 只校验部分字段，拿到的也是原值。

<Demo id="schema-validate" />

校验的来源与错误的归属：

- 一个 Form 只有一个校验来源。配置了 `schema` 后，字段的 `validator`、`rules` 不再运行，开发模式下警告；字段在另一个组件上，TypeScript 查不到这种组合。同时传 Form 的 `validator` 和 `schema` 时 TypeScript 报错，绕过类型时开发模式下警告，并且只用 `validator`。
- 同一轮校验只运行一次 schema，schema 里的异步校验（如查重）每轮都会运行。要控制请求次数，可以给 Form 设置 `schemaDebounce`（毫秒），值变化触发的校验等输入停顿后才运行；submit、`formApi.validate()`、blur 触发的校验不等待。也可以把字段的 `trigger` 设为 `blur`。
- 提交后服务端返回的错误用 `formApi.setError` 写入，这个字段下一轮校验时错误会被 schema 的结果替换。
- 修改某个字段时，只显示这个字段和已经 touched 的字段的错误，所以跨字段校验的错误要用 `path` 指向显示错误的字段，如示例中的确认密码。
- 错误路径指向字段内部时（如 TagInput 的 `tags[0]`），错误显示在持有这个值的字段上。找不到对应字段的错误不显示，只留在 `formState.errors` 里，schema 根级的错误写在 `errors['']`。

使用 Zod 时要注意：

- `allowEmpty` 关闭时，没填或清空的字段值是 `undefined`，不是空字符串。必填要写 `z.string({ error: '请输入姓名' })`，只写 `.min(1, '...')` 时显示的是 Zod 的类型错误。
- 有字段没填时，Zod 不运行 object 级的 `refine`，跨字段错误要等相关字段都有值才出现。
- `z.object` 默认丢掉没有声明的键，这些字段不会出现在提交回调的值里。要保留它们就用 `z.looseObject`。
- 错误语言由 Zod 决定，Semi 的语言包不影响它。可以调用 `z.config(z.locales.zhCN())`，或者像示例那样写自己的文案。
- 写 `import * as z from 'zod'`，打包时才能摇掉用不到的部分。

配置了 `schema` 后，必填星号和 `aria-required` 只由字段 `label` 配置里的 `required: true` 决定，不读 `rules`，也不从 schema 推导。字段的 `transform` 不影响 schema 收到的值。

### 自定义校验(Field 级别)

你可以通过 `validator` 指定单个表单控件的自定义校验，支持同步、异步校验（通过返回 promise）

- 传函数时签名为 `(fieldValue, values) => string | string[] | Promise<string | string[]>`，返回空字符串、空数组或空值表示通过，否则作为错误信息。

### 按 Schema 渲染表单

SchemaForm 按 schema 直接渲染整个表单。传入 Form 的 `schema` 后，SchemaForm 从中导出 JSON Schema，按属性顺序为每个属性渲染字段。导出要求校验库实现了 [Standard JSON Schema](https://standardschema.dev/json-schema)（如 Zod 4）；其他来源的 JSON Schema 可以直接传给 `jsonSchema`，它优先于导出的结果。SchemaForm 接受 Form 的全部属性，children 渲染在字段之后，适合放提交按钮。

<Demo id="schema-form" />

JSON Schema 与控件的对应：

| JSON Schema                                      | 控件                                                                                              |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `string`                                         | Input；`maxLength` 大于 160 时为 TextArea                                                         |
| `number`、`integer`                              | InputNumber；`integer` 时只能输入整数                                                             |
| `boolean`                                        | Switch                                                                                            |
| `enum`，或 `oneOf`、`anyOf` 的每一项都有 `const` | Select，选项文字取各项的 `title`                                                                  |
| 元素是选项的 `array`                             | 多选 Select                                                                                       |
| 带 `properties` 的 `object`                      | Section，标题取 `title`                                                                           |
| 其他 `array`                                     | ArrayField，每行有上移、下移、删除按钮，列表下方有添加按钮；`minItems` 等于 `maxItems` 时行数固定 |

标签取 `title`（没有时取属性名），说明文字取 `description`，初值取 `default`，列在 `required` 中的属性显示必填星号。对应不上控件的节点不渲染，开发模式下警告。

SchemaField 在已有的 Form 里渲染 schema 的一部分：`field` 指定路径（默认为根），可以和手写的字段混用。两者都可以用 `widgets` 和 `renderField` 定制：

- `widgets`：键是 JSON Schema 的 `format`（如 `uri`、`email`）或控件种类（`input`、`textarea`、`number`、`switch`、`select`），值是字段组件（如 FormInput 或用 withField 包装的组件）。先按 `format` 查找，再按种类查找。
- `renderField`：键是字段路径，数组的行写作 `[]`（如 `contacts[].email`），命中时由它渲染这个节点和它的子节点。

## FormApi

<Notice title="关于作用域隔离">为了防止用户在读取 formState、values 等内部状态后，意外操作直接了修改 Form 组件的内部状态等情况，Semi 对于 formApi.setValue、setValues的入参、formApi.getFormState、getValue、getValues的返回结果都会自动进行 deepClone</Notice>

组件自身的其他属性（如 Input 的 `size`、`placeholder`）与上面的属性平级一并写在 Field 上，**Field 会将其透传至被包装的组件本身**，而不是 fieldWrapper。`disabled` 取 Form 的值，写在 Field 上的 `disabled` 优先。

| ---------- | ----------------------------------------------------------------------------------------------- | ----------- |
| fieldLabel | label 内容，优先于 label 属性中的文本                                                           |             |
| labelExtra | 跟随在 label 文本后的内容                                                                       |             |
| helpText   | 自定义提示信息，与校验信息公用同一区块展示，两者均有值时，优先展示校验信息                      |             |

### ARIA

- [aria-labelledby](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-labelledby)、for
    - Field 组件，会自动添加 label DOM。控件的 id 取 `props.id`，未传入时自动生成；label 的 `for` 属性与该 id 相同；label 的 id 属性为 `${控件 id}-label`;
    - 当 Form 或者 Field 的 props.labelPosition 设置为 inset时，此时不存在 label 标签，而是 div 标签。insetLabel 对应的 div 标签会被自动追加 id，值与上述 label 的 id 相同，对应 Field 组件的 `aria-labelledby`。不支持内嵌标签的字段按 top 布局，`aria-labelledby` 指向实际渲染的 label
    - Field 组件会被自动追加 `aria-labelledby`，值与上述 label 的id 相同；使用方传入的 `aria-labelledby` 排在前面，两者合并而不是覆盖
- [aria-required](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Techniques/Using_the_aria-required_attribute)
    - 当 Field 配置了必填时（即 props.rules 中包含 required: true 或 props.label 配置了 required: true 且没有 optional: true；Form 配置了 schema 时只看 label），Field 组件会被自动追加 aria-required = true（CheckboxGroup、Slider、Upload 和单个 Radio 除外）；字段上显式传入的 aria-required 优先
- [aria-invalid](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Techniques/Using_the_aria-invalid_attribute) 、[aria-errormessage](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-errormessage)
    - 当 Field 校验未通过，或 validateStatus 为 error 时，Field 组件会被自动添加 `aria-invalid` = true 属性。
    - 当 Field 校验未通过时，Field 组件会被自动追加 `aria-errormessage` 属性，值为 errorMessage 所对应DOM元素的 id （格式: `${控件 id}-errormessage`）；CheckboxGroup 落在组内每个 checkbox 上。
- [aria-describedby](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/ARIA_Techniques/Using_the_aria-describedby_attribute)
    - 当 Field 配置了 `helpText` 或 `extraText` 时，Field 组件会被自动添加 `aria-describedby` 属性，值为 helpText、extraText 所对应DOM元素的 id （格式：`${控件 id}-helpText` 、`${控件 id}-extraText`）；使用方传入的 `aria-describedby` 排在前面，两者合并而不是覆盖

## 文案规范

- 表单标题
    - 表单标题需要跟随标题的书写规范
- 表单标签
    - 标签是输入框的简短描述。标签不是注释信息（help text），因此不应该是输入框的填写说明
    - 标签必须要：
        - 放在输入框的上方或下方
        - 简短（1-3个词）
        - 使用语句的大小写规范（首字母大写，其他小写）
- 帮助文本
    - 帮助文本使用语句书写规范，首字母大写
- 表单按钮
    - 关于表单按钮的文案规范，参考[按钮Button组件的文案规范](/zh-CN/react/basic/button#%E6%96%87%E6%A1%88%E8%A7%84%E8%8C%83)

## FAQ

- **为什么我声明了表单，对值进行了修改，数据没有自动映射到 formState.values 中？**  
   请检查是否正确传入了 field，Field 上的`field`属性是必填项！！！

- **为什么传入了 defaultValue、defaultChecked 不生效？**  
   请参考文档开头[表单控件](#声明表单的多种写法)，Field 组件对默认值做了统一处理，你应该使用`initValue`或者`initValues`来传入默认值

- **为什么异步更新了 initValue、initValues 后，组件没有发生变化，值没有生效？**  
   `initValue`、`initValues`只在 Field、Form mounted 时进行消费，后续做的异步更新并不会起效。  
   如果你的初始值需要从远程取，那么你可以在获取到值之后，使用`formApi.setValue/setValues`进行更新。  
   或者直接给 Form、Field 传入一个新的`key`强制它重新挂载

- **为什么调用了 formApi.setValues 更新 fields 的值，但是实际渲染并没有更新？**

    setValues 默认情况下对尚未存在的 field 进行赋值不会生效。如果你的 fields 是动态加载的话，请检查在 setValues 时，该 field 是否已 mounted。  
     如有需要，可以使用 override 模式 `formApi.setValues(newValue, { isOverride: true })`

- **为什么 rules 中的 validator 校验失败，但是对应的错误信息没有被展示？**

    `rules[].validator` 返回 `false` 或抛错时失败，显示规则的 `message`（没有时显示默认文案或错误的 message）；返回字符串或字符串数组时直接作为错误信息。返回 `true`、`undefined`、空字符串等其他值都视为通过。另外 `message` 为空字符串时只标红、不显示文字。

- **为什么 getValues 拿不到某个 field？**

    field 没有初始值的话，`getValues` 获取不到这一项。可以设置 `initValues`/`initValue` 或者给 form 设置 `allowEmpty` 属性。

- **为什么在输入框（如 Input）上敲击 enter 回车键会触发了 Form 的 submit？**

    这个是标准 HTML 行为，我们不计划进行干预，会与原生保持一致。如果表单内确实只有一个 Input 元素，又不想回车时触发 submit 回调，建议对 Input 的 keydown 事件的 enter 采取 preventDefault 阻止默认行为。

    点击 <a href="https://github.com/DouyinFE/semi-design/issues/767" target="_blank">#767</a> 查看相关背景和内容。

- **表单会自动保存历史输入项，不想要这个功能怎么办？**  
  在 v2.3 之前，Form 并没有严格按照 A11y 无障碍标准为输入控件配置`for`、`name`、`id` 等属性，因此在之前的版本并没有该功能。v2.3 后我们严格按照 W3C 标准进行了实现。如果你不希望浏览器自动保存历史输入项，也可以通过在 Form 级别或者 Field 级别设置 `autoComplete=off` 关掉
