### 自定义筛选逻辑，自定义选项数据渲染

使用`filter`自定义搜索逻辑，返回 true 时表示当前项符合筛选规则，保留当前项在列表中的显示，返回 false 则表示不符合，当前项会被隐藏。  
当 type 为 `treeList`时，如需要自定义搜索逻辑，需设置 `filter` 为 true，并通过 `treeProps` 的 `filterTreeNode` 设置自定义的搜索函数。

### 左侧分页

当左侧选项较多时，可以通过 `pagination` 属性开启分页功能。

`pagination` 接收一个对象，包含以下属性：

- `pageSize`: 每页显示的条数，默认为 10
- `currentPage`: 当前页码（受控模式）
- `defaultCurrentPage`: 默认当前页码（非受控模式）
- `onPageChange`: 页码变化时的回调

### 完全自定义渲染

<Framework only="react">

Semi 提供了 `renderSourcePanel`、`renderSelectedPanel` 入参，允许你完全自定义左右侧两个面板的渲染结构  
通过该功能，你可以直接复用 Transfer 内部的逻辑能力，实现高度自定义样式结构的`Transfer`组件 `renderSourcePanel: (sourcePanelProps: SourcePanelProps) => ReactNode`  
`SourcePanelProps`包含以下参数，你可以从中获取数据来渲染出你的 Panel 结构

```ts
interface SourcePanelProps {
    value: Array<string | number>; // 所有选中项的 value
    loading?: boolean; // 是否加载中
    noMatch: boolean; // 是否没有符合当前搜索值匹配的项
    filterData: Array<Item>; // 匹配当前搜索值的项
    sourceData: Array<Item>; // 所有项
    propsDataSource: Array<Item> | Array<GroupItem> | Array<TreeItem>; // Transfer 的 dataSource
    allChecked: boolean; // 是否全部选中
    showNumber: number; // 筛选结果数量
    inputValue: string; // input搜索框的值
    onSearch: (searchString: string) => void; // 搜索框变化时应调用的函数，入参为搜索值
    onAllClick: () => void; // 左侧全部按钮点击时应调用的函数
    onSelectOrRemove: (item: Item) => void; // 选择、删除单个选项时应调用的函数，入参应为当前操作item
    onSelect: (value: Array<string | number>) => void; // 受控批量选中，入参为选中项的 value
    selectedItems: Map<string | number, Item>; // 所有已选项的集合，Map 的键是 item.key
}
```

`renderSelectedPanel: (selectedPanelProps: SelectedPanelProps) => ReactNode`  
`SelectedPanelProps`包含以下参数

```ts
interface SelectedPanelProps {
    length: number; // 已选项的数量
    onClear: () => void; // 点击清空时应调用的回调函数
    onRemove: (item: Item) => void; // 删除单个选项时应调用的函数
    onSortEnd: ({ oldIndex, newIndex }) => void; // 对结果重新排序时应调用的函数
    selectedData: Array<Item>; // 所有已选项集合
}
```

### 完全自定义渲染 、 拖拽排序

在完全自定义渲染的场景下，由于拖拽区的渲染也已由你完全接管，因此你不声明 draggable 亦可。但你需要自行实现拖拽逻辑，你可以借助社区中的拖拽工具库 [dnd-kit](https://github.com/clauderic/dnd-kit) 快速实现功能。

另外，要支持拖拽排序，你需要在拖拽排序结束后，将 oldIndex、newIndex 作为入参，调用 onSortEnd

<Framework only="react">

使用 dnd-kit 的示例如下，需要用到的核心依赖有 @dnd-kit/react，其中 `DragDropProvider` 提供拖拽上下文，核心 hook 为 `@dnd-kit/react/sortable` 导出的 useSortable，使用说明如下

```
1. 作用：通过唯一标志 id 与当前位置 index 获取拖拽过程中必要信息
2. 核心输入参数：
    - id: 唯一标识，数字或者字符串
    - index: 该项在列表中的当前位置
    - handle: 可选，拖拽手柄的元素，不传时整个节点都可拖拽
3. 核心返回值说明:
	- ref: 关联 dom 节点，使其成为一个可拖拽的项
	- handleRef: 关联拖拽手柄的 dom 节点
	- isDragging: 该节点是否正在被拖拽
```

拖拽结束后，在 `DragDropProvider` 的 `onDragEnd` 中，用 `event.operation.source` 的 `initialIndex` 与 `index` 得到拖拽前后的位置；`event.canceled` 为 true 表示拖拽已取消。

</Framework>

<Framework only="vue">

使用 dnd-kit 的示例如下，需要用到的核心依赖有 @dnd-kit/dom：`DragDropManager` 提供拖拽上下文，每个已选项对应一个 `@dnd-kit/dom/sortable` 导出的 `Sortable`，参数如下（项目使用 @dnd-kit/vue 时，它的 `useSortable` 接收同样的 id、index、element、handle）

```
1. 作用：通过唯一标志 id 与当前位置 index 获取拖拽过程中必要信息
2. 核心输入参数：
    - id: 唯一标识，数字或者字符串
    - index: 该项在列表中的当前位置，列表变化后需同步更新
    - element: 可拖拽的 dom 节点
    - handle: 可选，拖拽手柄的元素，不传时整个节点都可拖拽
3. 第二个参数是 DragDropManager 实例，卸载组件时需要调用各 Sortable 与 manager 的 destroy
```

拖拽结束后，在 `manager.monitor` 的 `dragend` 事件中，用 `event.operation.source` 的 `initialIndex` 与 `index` 得到拖拽前后的位置；`event.canceled` 为 true 表示拖拽已取消。

示例用 `v-model` 保存已选值，拖拽结束后直接把调整后的顺序写回 `v-model`；不自己保存值时，也可以在 `#selectedPanel` 的参数里取 `onSortEnd` 调用。

</Framework>

<Framework only="solid">

使用 dnd-kit 的示例如下，需要用到的核心依赖有 @dnd-kit/solid：`DragDropProvider` 提供拖拽上下文，`@dnd-kit/solid/sortable` 导出的 `useSortable` 接收 `id` 与 `index`，两者都以 getter 传入，列表重排后读取到的 `index` 随之更新。

```
1. 作用：通过唯一标志 id 与当前位置 index 获取拖拽过程中必要信息
2. 核心输入参数：
    - id: 唯一标识，数字或者字符串
    - index: 该项在列表中的当前位置
3. 核心返回值说明:
    - ref: 绑定可拖拽项的 dom 节点，以 ref={(node) => ref(node)} 的形式使用
    - handleRef: 绑定拖拽手柄的 dom 节点，只有手柄可以拖拽
    - isDragSource: 该节点是否正在被拖拽
```

拖拽结束后，在 `DragDropProvider` 的 `onDragEnd` 中，用 `event.operation.source` 的 `initialIndex` 与 `index` 得到拖拽前后的位置；`event.canceled` 为 true 表示拖拽已取消。

</Framework>

## Accessibility

### ARIA

- 搜索框所在的容器是原生 `search` 元素（search 地标），名称取自语言包
- 根元素带 `aria-label` 或 `aria-labelledby` 且未指定 `role` 时，自动加 `role` `group`
- 左侧选项列表添加 `role` `list`，选项为 `listitem`；`groupList` 的每个分组是外层列表的一个 `listitem`，其中分组标题命名嵌套的 `list`，选项在嵌套列表里
- 右侧选中列表添加 `role` `list`，选中项添加 `role` `listitem`；自定义渲染的左右条目外会包一层 `role` `listitem` 的元素

### 键盘交互

- 默认过滤不区分大小写
- 禁用时左右两个列表是 Tab 停靠点，用来用键盘滚动其中内容
- `draggable` 的拖拽句柄是带名称的原生 `button`：Tab 聚焦句柄，空格拿起，方向键移动，空格放下；排序过程会通过读屏播报。鼠标拖拽不变
- 拖拽排序所需的 dnd-kit 加载完成前，句柄是带 `aria-disabled="true"` 的占位
