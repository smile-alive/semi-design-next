### Custom filtering logic, custom option data rendering

Use `filter` to customize the search logic. When it returns true, it means that the current item meets the filter rules and keeps the display of the current item in the list. If it returns false, it means it does not match, and the current item will be hidden.  
When type is `treeList`, if you need to customize search logic, you need to set `filter` to true and set a custom search function through `filterTreeNode` of `treeProps`.

### Left panel pagination

When there are many options on the left, you can enable pagination through the `pagination` prop.

`pagination` accepts an object with the following properties:

- `pageSize`: Number of items per page, default is 10
- `currentPage`: Current page number (controlled mode)
- `defaultCurrentPage`: Default current page number (uncontrolled mode)
- `onPageChange`: Callback when page changes

### Fully custom rendering

<Framework only="react">

Semi provides `renderSourcePanel` and `renderSelectedPanel` input parameters, allowing you to completely customize the rendering structure of the left and right panels. With this function, you can directly reuse the logic capabilities inside the Transfer to implement the `Transfer` component with a highly customized style structure `renderSourcePanel: (sourcePanelProps: SourcePanelProps) => ReactNode` `SourcePanelProps` contains the following parameters, from which you can get data to render your Panel structure

```ts
interface SourcePanelProps {
    value: Array<string | number>; // value of all selected items
    loading?: boolean; // Whether loading
    noMatch: boolean; // Whether there is no matching item that matches the current search value
    filterData: Array<Item>; // items that match the current search value
    sourceData: Array<Item>; // All items
    propsDataSource: Array<Item> | Array<GroupItem> | Array<TreeItem>; // The dataSource of Transfer
    allChecked: boolean; // Whether to select all
    showNumber: number; // Filter the number of results
    inputValue: string; // the value of the input search box
    onSearch: (searchString: string) => void; // The function that should be called when the search box changes, the input parameter is the search value
    onAllClick: () => void; // The function that should be called when all the buttons on the left are clicked
    onSelectOrRemove: (item: Item) => void; // The function that should be called when selecting or deleting a single option, the input should be the current operation item
    onSelect: (value: Array<string | number>) => void; // controlled batch selection, the input is the values of the selected items
    selectedItems: Map<string | number, Item>; // collection of all selected items, the key of the Map is item.key
}
```

`renderSelectedPanel: (selectedPanelProps: SelectedPanelProps) => ReactNode` `SelectedPanelProps` contains the following parameters

```ts
interface SelectedPanelProps {
    length: number; // number of selected options
    onClear: () => void; // The callback function that should be called when clicking to clear
    onRemove: (item: Item) => void; // The function that should be called when deleting a single option
    onSortEnd: ({ oldIndex, newIndex }) => void; // The function that should be called when reordering the results
    selectedData: Array<Item>; // All selected items collection
}
```

</Framework>

### Fully custom rendering, drag and drop sorting

In a completely custom rendering scene, since the rendering of the drag area has also been completely taken over by you, you do not need to declare draggable. But you need to implement the drag and drop logic yourself, You can use the drag-and-drop tool library [dnd-kit](https://github.com/clauderic/dnd-kit) to quickly realize the function.

Besides, To support drag sorting, you need to call onSortEnd with oldIndex and newIndex as the input parameters after the drag sorting is over

<Framework only="react">

Example using dnd-kit，The core dependency that needs to be used is @dnd-kit/react. `DragDropProvider` provides the drag and drop context, and the core hook is useSortable exported from `@dnd-kit/react/sortable`. The usage instructions of useSortable are as follows

```
1. Function: Obtain the necessary information during the drag and drop process through the unique id and the current index
2. Core input parameters:
    - id: unique identifier, which can be a number or a string
    - index: the current position of the item in the list
    - handle: optional, the drag handle element; the whole node is draggable when omitted
3. Core return value description:
    - ref: Associate the dom node to make it a draggable item
    - handleRef: Associate the dom node of the drag handle
    - isDragging: whether the node is being dragged
```

After dragging ends, in the `onDragEnd` of `DragDropProvider`, use `initialIndex` and `index` of `event.operation.source` to get the positions before and after the drag; `event.canceled` being true means the drag was canceled.

</Framework>

<Framework only="vue">

Example using dnd-kit，The core dependency that needs to be used is @dnd-kit/dom. `DragDropManager` provides the drag and drop context, and every selected item gets a `Sortable` exported from `@dnd-kit/dom/sortable`. Its parameters are as follows (with @dnd-kit/vue, its `useSortable` takes the same id, index, element and handle)

```
1. Function: Obtain the necessary information during the drag and drop process through the unique id and the current index
2. Core input parameters:
    - id: unique identifier, which can be a number or a string
    - index: the current position of the item in the list; keep it up to date when the list changes
    - element: the draggable dom node
    - handle: optional, the drag handle element; the whole node is draggable when omitted
3. The second argument is the DragDropManager instance; call destroy on every Sortable and on the manager when the component unmounts
```

After dragging ends, in the `dragend` event of `manager.monitor`, use `initialIndex` and `index` of `event.operation.source` to get the positions before and after the drag; `event.canceled` being true means the drag was canceled.

The example keeps the selected values in `v-model` and writes the new order back to it once a drag ends. Without a value of your own, take `onSortEnd` from the parameters of `#selectedPanel` and call it instead.

</Framework>

<Framework only="svelte">

Example using dnd-kit. The core dependencies that need to be used are @dnd-kit/svelte and @dnd-kit/dom. `DragDropProvider` provides the drag and drop context, and every selected item gets a `Sortable` exported from `@dnd-kit/dom/sortable`. Its parameters are as follows

```
1. Function: Obtain the necessary information during the drag and drop process through the unique id and the current index
2. Core input parameters:
    - id: unique identifier, which can be a number or a string
    - index: the current position of the item in the list; keep it up to date when the list changes
    - element: the draggable dom node
    - handle: optional, the drag handle element; the whole node is draggable when omitted
3. The second argument is the DragDropManager instance; call destroy on every Sortable when the component unmounts
```

The example creates the `Sortable` of each row with `{@attach}`, destroys it in the cleanup function, and keeps the selected values in `bind:value`. The order shown during a drag is driven by the example's own `preview` state, so the `OptimisticSortingPlugin` is removed: it moves DOM nodes itself, which collides with the keyed each of Svelte.

In `onDragOver` of `DragDropProvider` the preview order is adjusted from `source` and `target`; in `onDragEnd` the positions before and after the drag are worked out from the id of `event.operation.source`, then `onSortEnd` from the parameters of `selectedPanel` is called; `event.canceled` being true means the drag was canceled.

</Framework>

<Framework only="solid">

The dnd-kit example is as follows. The core dependency is @dnd-kit/solid: `DragDropProvider` provides the drag context, and `useSortable` exported from `@dnd-kit/solid/sortable` takes `id` and `index`. Both are passed as getters, so the `index` read after the list is reordered is up to date.

```
1. Purpose: get the information needed during dragging from the unique id and the current position index
2. Core input parameters:
    - id: unique identifier, a number or a string
    - index: the current position of the item in the list
3. Core return values:
    - ref: binds the dom node of a draggable item, used as ref={(node) => ref(node)}
    - handleRef: binds the dom node of the drag handle; only the handle drags
    - isDragSource: whether this node is being dragged
```

After dragging ends, in the `onDragEnd` of `DragDropProvider`, use `initialIndex` and `index` of `event.operation.source` to get the positions before and after the drag; `event.canceled` being true means the drag was canceled.

</Framework>

### Tree Transfer

The input type is `treeList`, and the [`Tree`](/en-US/react/navigation/tree) component is used as a custom rendering list.

The properties of the default tree can be overridden by treeProps([TreeProps](/en-US/react/navigation/tree)). The default properties of the tree on the left are

<Framework only="react">

```
{

    defaultExpandAll:true,
    searchRender:false,
}
```

</Framework>

<Framework only="vue">

```
{
    multiple:true,
    disableStrictly:true,
    leafOnly:true,
    filterTreeNode:true,
    defaultExpandAll:true,
}
```

The Tree's own search box is hidden with an empty `#search` slot, and the search box of Transfer drives the filtering. Of the Tree slots only `#label` is forwarded, through the `#label` slot of Transfer, and it applies to both the tree rows on the left and the selected items on the right; the `#icon`, `#expandIcon` and `#fullLabel` slots of the Tree are not available.

</Framework>

Of the Tree snippets only `label` is forwarded, through the `label` snippet of Transfer, and it applies to both the tree rows on the left and the selected items on the right. A leaf node writes `children: []`.

## Accessibility

### ARIA

- The container of the search box is a native `search` element (the search landmark), named from the locale
- When the root element has `aria-label` or `aria-labelledby` and no `role`, it gets `role` `group`
- Add `role` `list` to the option list on the left and `listitem` to its options; in `groupList` every group is a `listitem` of the outer list, and its title names the nested `list` that holds the options
- Add `role` `list` to the selected list on the right, add `role` `listitem` to the selected item; custom rendered items on either side are wrapped in an element with `role` `listitem`

### Keyboard

- The default filter ignores case
- When disabled, the two lists are Tab stops so the keyboard can scroll their content
- With `draggable`, the drag handle is a native `button` with a name: Tab focuses the handle, Space picks up, the arrow keys move, Space drops; the sort is announced to screen readers. Mouse dragging is unchanged
- Until the dnd-kit needed for sorting has loaded, the handle is a placeholder with `aria-disabled="true"`

## Methods

Transfer exposes `search` through `export function`; get the instance with `bind:this` and call it. Its type is `TransferHandle`.

```svelte
<script lang="ts">
    import { Transfer, type TransferHandle } from '@fibrae/semi-ui-svelte';

    let transfer = $state<TransferHandle>();
```
