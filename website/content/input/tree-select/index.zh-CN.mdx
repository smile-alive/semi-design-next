## 使用场景

当需要选择的选项为树形结构时，可以使用树选择器，例如部门层级、学科体系、分类目录等。

### 搜索框位置

可以使用 `searchPosition` 来设置搜索框的位置，可选: `dropdown`(默认)、`trigger`。

当输入框位于 trigger 时:

1. 搜索框占位符由 `placeholder` 控制；
2. `showClear=true` 时，点击输入框的清空按钮，将同时清空 inputValue 和 value。

### 虚拟化

列表虚拟化，用于大量树节点的情况。开启后，动画效果将被关闭。

`virtualize` 是一个包含下列值的对象：

- height: 高度值，如果为 string 必须有计算高度才能被渲染出来，即其父节点有 offsetHeight。建议传入数值。
- width: 宽度值，默认 100%
- itemSize: 每行的treeNode的高度，必传

如果带搜索框，建议开启 `showFilteredOnly` 减少多余节点的渲染。

<Framework only="react">

triggerRender 入参如下:

</Framework>

<Framework only="vue">

如果默认的触发器样式满足不了你的需求，可以用 `#trigger` 插槽自定义选择框的展示。

`#trigger` 的插槽参数如下，类型为 `TreeSelectTriggerSlotProps`:

```typescript
interface TreeSelectTriggerSlotProps {
    componentProps: TreeSelectProps; // 所有用户传给 TreeSelect 的 props
    disabled: boolean; // 是否禁用 TreeSelect
    value: TreeNodeData[]; // 已选中的 node 的数据
    inputValue: string; // 当前 input 框的输入值
    placeholder?: string; // placeholder
    // 用于清空值的函数；绑定在触发器内的控件上时传入点击事件，避免这次点击同时打开下拉
    onClear: (event?: MouseEvent) => void;
    // 删除单个 item 时调用的函数，以 item 的 key 作为入参
    onRemove: (key: string) => void;
    // 用于在 Input 框值更新时启动搜索，需要设置 filterTreeNode 非 false，
    // searchPosition 为 'trigger'
    onSearch: (inputValue: string) => void;
}
```

</Framework>


### 自定义渲染已选项

<Framework only="react">

你可以通过 renderSelectedItem 自定义选择框中已选项标签的渲染结构。

- 单选时 `renderSelectedItem(treeNode: TreeNodeData) => content:ReactNode`
- 多选时 `renderSelectedItem(treeNode: TreeNodeData, { index:number, onClose:function }) => { isRenderInTag:bool, content:ReactNode }`
    - isRenderInTag 为 true 时，会自动将 content 包裹在 Tag 中渲染（带有背景色以及关闭按钮）
    - isRenderInTag 为 false 时，将直接渲染返回的 content

</Framework>

<Framework only="vue">

你可以通过 `#selectedItem` 和 `#tag` 插槽自定义选择框中已选项的渲染结构，两个插槽的参数相同，类型为 `TreeSelectSelectedItemSlotProps`：`item`（节点数据）、`index`、`disabled` 和 `onClose`（移除该标签，单选时清除选中值）。

- 单选时 `#selectedItem` 的内容就是选择框中显示的内容；内容为空时显示 `placeholder`
- 多选时 `#selectedItem` 的内容会放进内置的 Tag 中渲染（带有背景色以及关闭按钮）；`#tag` 替换整个 Tag，优先于 `#selectedItem`，需要关闭按钮时把 `onClose` 绑定到自己的 Tag 上
- 多选时两个插槽的内容为空，都不渲染该标签

</Framework>

<Framework only="solid">

你可以通过 renderSelectedItem 自定义选择框中已选项标签的渲染结构。

- 单选时 `renderSelectedItem(treeNode: TreeNodeData) => content: JSX.Element`
- 多选时 `renderSelectedItem(treeNode: TreeNodeData, { index: number | string, onClose: (tagContent, e?) => void }) => { isRenderInTag: boolean, content: JSX.Element }`
    - isRenderInTag 为 true 时，会自动将 content 包裹在 Tag 中渲染（带有背景色以及关闭按钮）
    - isRenderInTag 为 false 时，将直接渲染返回的 content

</Framework>

<Framework only="svelte">

你可以通过 `selectedItem` 和 `tag` snippet 自定义选择框中已选项的渲染结构，两个 snippet 的参数相同，类型为 `TreeSelectSelectedItemSnippetProps`：`item`（节点数据）、`index`、`disabled` 和 `onClose`（移除该标签，单选时清除选中值）。

- 单选时 `selectedItem` 的内容就是选择框中显示的内容；内容为空时显示 `placeholder`
- 多选时 `selectedItem` 的内容会放进内置的 Tag 中渲染（带有背景色以及关闭按钮）；`tag` 替换整个 Tag，优先于 `selectedItem`，需要关闭按钮时把 `onClose` 接到自己的 Tag 上（见 demo，在 Tag 的 `onClose` 里调用它）
- 多选时两个 snippet 的内容为空，都不渲染该标签

</Framework>

## API参考

### TreeSelect

<Framework only="react">

<TreeSelectReactApi />

`aria-label`、`aria-labelledby`、`aria-describedby`、`aria-errormessage`、`aria-invalid` 与 `aria-required` 落在当前的 combobox 上：不可搜索时是触发器，搜索框在触发器内时是搜索框的输入框。其他原生属性（如 `id`、`data-*`、`onClick`）落在触发器元素上。

</Framework>

<Framework only="vue">

<TreeSelectVueApi />

Vue 版的 TreeSelect 没有 `className` 属性：`class`、`style` 和 `data-*` 等未声明的属性落在根元素上，`aria-label`、`aria-labelledby`、`aria-describedby`、`aria-errormessage`、`aria-invalid`、`aria-required` 落在当前的 combobox 上（见 [ARIA](#aria)）。`focus`、`blur`、`change`、`select`、`keydown` 是组件的事件，会遮住根元素上同名的原生事件。

</Framework>

<Framework only="solid">

<TreeSelectSolidApi />

`class`、`style` 与原生属性（如 `id`、`data-*`）落在根元素（触发器）上。`aria-label`、`aria-labelledby`、`aria-describedby`、`aria-errormessage`、`aria-invalid` 与 `aria-required` 落在当前的 combobox 上：不可搜索时是根元素，搜索框在触发器内时是搜索框的 `input`。`onFocus`、`onBlur`、`onChange` 与 `onSelect` 是组件自己的回调，不会作为原生事件绑定到根元素。

</Framework>

<Framework only="svelte">

<TreeSelectSvelteApi />

Svelte 版的 TreeSelect 没有 `className` 属性：`class`（字符串、数组或对象）、`style`（字符串）、`data-*` 与其他未声明的属性和事件处理（例如 `onclick`）落在根元素（触发器）上，`onkeydown` 在组件处理完按键之后调用。`aria-label`、`aria-labelledby`、`aria-describedby`、`aria-errormessage`、`aria-invalid`、`aria-required` 落在当前的 combobox 上（见 [ARIA](#aria)）。小写的 `onchange`、`onselect`、`onload`、`onfocus`、`onblur` 不是原生透传，请使用回调 `onChange`、`onSelect`、`onLoad`、`onFocus`、`onBlur`。`dropdownStyle`、`optionListStyle` 是样式字符串。`value`、`expandedKeys`、`loadedKeys` 可绑定，没有 `defaultValue`、`defaultExpandedKeys`；`multiple` 默认值可以由全局默认值设置。

</Framework>

### TreeNodeData

<Framework only="react">

> **不同 `TreeNodeData` 的 key 值要求必填且唯一。**`label` 允许重复。value 值非必填。此时 onChange, value, defaultValue 及 onChangeWithObject 中所取的 value 属性值将改为 key 值。为了保证行为的符合预期，treeData 中的 value 值或者全部不填写，或者全部填写且唯一，不建议混写。

</Framework>

<Framework only="vue">

> **不同 `TreeNodeData` 的 key 值要求必填且唯一。**`label` 允许重复。value 值非必填。此时 `v-model`、`defaultValue`、`change` 事件及 `changeWithObject` 中所取的 value 属性值将改为 key 值。为了保证行为的符合预期，treeData 中的 value 值或者全部不填写，或者全部填写且唯一，不建议混写。

</Framework>

## Accessibility

### ARIA

- 按 ARIA 1.2 的 combobox 写法，任一时刻只有一个元素是 combobox。它的名称按优先级取：`aria-labelledby`、`aria-label`、实际渲染出的 insetLabel（Vue 为 `#insetLabel`，未传 `insetLabelId` 时组件生成 id；有 prefix 时 insetLabel 不渲染，也不作名称来源），都没有时取语言包中的名称:
    - 不可搜索或 `searchPosition="dropdown"` 时，触发器是 select-only combobox；下拉内的搜索框保持文本框角色，带 `aria-controls`、`aria-autocomplete`、`aria-activedescendant`
    - `searchPosition="trigger"` 时，搜索框是 combobox 和唯一的 Tab 停靠点，带 `aria-autocomplete="list"`，触发器不再有角色。单选时搜索框在输入前为空，已选文本以 `aria-describedby` 关联为它的描述。点击触发器任意位置会把焦点交给搜索框;
- TreeSelect 允许用户设置 `aria-describedby`、`aria-errormessage`、`aria-invalid`、`aria-labelledby`、`aria-required`，另外，Form 会为 Form.TreeSelect 自动设置这些属性;
- 下拉中 `role="tree"` 的列表与 combobox 使用同一个名称来源：同一组 `aria-labelledby`、同一个 `aria-label` 或同一个 insetLabel；都没有时与 combobox 一样取语言包中的名称;

<Framework only="react">

- 下拉中的节点与 [Tree](/zh-CN/react/navigation/tree#accessibility) 相同：`role="treeitem"`，带 `aria-level`、`aria-setsize`、`aria-posinset`、`aria-disabled`，可展开的节点带 `aria-expanded`；单选时用 `aria-selected`，多选时用 `aria-checked`（半选为 `mixed`）;

</Framework>

<Framework only="vue">

- `aria-label`、`aria-labelledby`、`aria-describedby`、`aria-errormessage`、`aria-invalid`、`aria-required` 落在当前的 combobox 上：不可搜索时是根元素，单选且搜索框在触发器内时是搜索框的 `input`，多选且搜索框在触发器内时是标签输入框。设置了 `aria-labelledby` 时，combobox 不再补默认的 `aria-label`；只有 `#insetLabel` 时 combobox 的 `aria-labelledby` 指向它;
- 下拉中的节点与 [Tree](/zh-CN/react/navigation/tree#accessibility) 相同：`role="treeitem"`，带 `aria-level`、`aria-setsize`、`aria-posinset`、`aria-disabled`，可展开的节点带 `aria-expanded`；单选时用 `aria-selected`，多选时用 `aria-checked`（半选为 `mixed`）。`#fullLabel` 的内容由带 `id`、`role="treeitem"` 和这些状态的 `li` 包住;

</Framework>

<Framework only="solid">

- 下拉中的节点与 [Tree](/zh-CN/react/navigation/tree#accessibility) 相同：`role="treeitem"`，带 `aria-level`、`aria-setsize`、`aria-posinset`、`aria-disabled`，可展开的节点带 `aria-expanded`；单选时用 `aria-selected`，多选时用 `aria-checked`（半选为 `mixed`）。

</Framework>

<Framework only="svelte">

- 节点前的展开箭头和多选复选框只是状态的图示，对读屏软件隐藏，也不接收焦点。

### 键盘交互

TreeSelect 按 [WAI-ARIA Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) 处理键盘，弹出层是一棵树：焦点始终留在触发器或搜索框上，`aria-activedescendant` 指向当前节点，当前节点显示焦点环。下拉刚打开时没有当前节点。

- 下拉关闭时：`ArrowDown`、`ArrowUp`、`Enter`、`Space` 打开下拉；`Home`、`End` 打开下拉并移到第一个、最后一个可见节点
- `ArrowDown`、`ArrowUp`：移到下一个、上一个可见节点，第一次按 `ArrowDown` 移到第一个节点；`Home`、`End`：移到第一个、最后一个可见节点
- `ArrowRight`：展开收起的节点；节点已展开时移到它的第一个子节点（RTL 下与 `ArrowLeft` 互换）
- `ArrowLeft`：收起展开的节点；否则移到父节点
- `Enter`、`Space`：选中当前节点，多选时勾选或取消勾选；禁用节点不响应
- 输入字符：下拉打开时，从当前节点往后，移到第一个以输入内容开头的可见节点；快速连续输入的字符合成一个搜索词。下拉关闭时不响应
- `Esc`：关闭下拉

焦点在搜索框里时，只有 `ArrowDown`、`ArrowUp`、`Enter` 用于移动和选择，其余按键（含字符、`Space`、`Home`、`End`、`ArrowLeft`、`ArrowRight`）用于编辑文字。

<Framework only="react">

自定义 `searchRender` 的参数里带有这组 ARIA 属性（`aria-activedescendant`、`aria-controls`、`aria-autocomplete`、名称；在触发器内时为整组 combobox 属性，含 `role`、`aria-expanded`），请把它们写在输入框上，否则读屏软件不会读出当前节点。参数里的 `ref` 也要写到输入框（Semi `Input`、原生 input 或 textarea）上，点击触发器内的已选文本时才能把焦点交给它。

</Framework>

<Framework only="vue">

`#search` 插槽的参数里带有这组 ARIA 属性（`aria-activedescendant`、`aria-controls`、`aria-autocomplete`、名称；在触发器内时为整组 combobox 属性，含 `role`、`aria-expanded`），请用 `v-bind` 把整个参数对象绑定到输入框（Semi `Input`）上，否则读屏软件不会读出当前节点。参数里的 `inputRef` 也必须绑定到输入框上，点击触发器内的已选文本时才能把焦点交给它。

</Framework>

<Framework only="svelte">

`search` snippet 的参数里带有这组 ARIA 属性（`aria-activedescendant`、`aria-controls`、`aria-autocomplete`、名称；在触发器内时为整组 combobox 属性，含 `role`、`aria-expanded`），请用 `{...props}` 把整个参数对象展开到 Semi 的 `Input` 上，否则读屏软件不会读出当前节点。组件会自己在 snippet 渲染的内容里找到文本框来聚焦，所以不需要传 ref。

</Framework>

`showClear` 开启、有已选值或搜索文本且未禁用时，触发器内渲染清除按钮。它是原生 `button`，名称为语言包中的「清空已选值」，在 hover、下拉打开或焦点位于 TreeSelect 内时显示。从触发器或搜索框按 `Tab` 移到清除按钮，`Enter` 或 `Space` 清空，效果与鼠标点击相同，清空后焦点回到触发器或搜索框。多选时也可在搜索框中用 `Backspace` 删除标签。

<Framework only="solid">

自定义 `searchRender` 的入参是活对象，其中带有这组 ARIA 属性（`aria-activedescendant`、`aria-controls`、`aria-autocomplete`、名称；在触发器内时为整组 combobox 属性，含 `role`、`aria-expanded`），请把它们展开到输入框上，否则读屏软件不会读出当前节点。入参里的 `ref` 是回调，同样要写到输入框（Solid `Input`、原生 input 或 textarea）上，点击触发器内的已选文本时才能把焦点交给它。

</Framework>
