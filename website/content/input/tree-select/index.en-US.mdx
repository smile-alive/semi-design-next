## When to Use

When the options to select is in tree structure, you could use TreeSelect, e.g. department hierarchy, subject system, category directory and etc.

### Search Box Position

You can use `searchPosition` to set the position of the search box, optional: `dropdown` (default), `trigger`.

When the input box is at trigger:

1. The placeholder of the search box is controlled by `placeholder`;
2. When `showClear=true`, click the clear button of the input box, the inputValue and value will be cleared at the same time.

In **multiple + searchable + searchPosition="trigger"** mode, if there are many selected items or the input is long, the trigger may prefer to keep a single-line layout by default.

### Virtualized TreeSelect

If you need to render large sets of tree structured data, you could use virtualized tree. In virtualized mode, animation / motion is disabled for better performance.

The property `virtualize` is an object consisting of the following values:

- height: Height of the dropDown, If passed in as a string, computed height should not be zero for render purpose, in other words, parent node should have offsetHeight. Pass in a number recommended.
- width: Width of the dropDown.
- itemSize: Height for each line of treeNode, required

If tree is searchable, you could also turn on `showFilteredOnly` to reduce time of rendering for results.

### Custom Rendering Selected Item

<Framework only="react">

You can use renderSelectedItem to customize the rendering structure of the selected item in the selection box.

- In not multiple mode: `renderSelectedItem(treeNode: TreeNodeData) => content: ReactNode`
- In multiple mode: `renderSelectedItem(treeNode: TreeNodeData, { index:number, onClose:function }) => { isRenderInTag: bool, content: ReactNode }`
    - When isRenderInTag is true, content wraps are automatically rendered in the Tag (with background color and close button)
    - When isRenderInTag is false, the returned content will be rendered directly

</Framework>

<Framework only="vue">

You can use the `#selectedItem` and `#tag` slots to customize the rendering structure of the selected items in the selection box. Both take the same parameters, typed as `TreeSelectSelectedItemSlotProps`: `item` (the node data), `index`, `disabled` and `onClose` (removes the tag, or clears the selection in single mode).

- In single mode the content of `#selectedItem` is what the select box shows; empty content shows the `placeholder`
- In multiple mode the content of `#selectedItem` is rendered inside the built-in Tag (with background color and close button); `#tag` replaces the whole Tag and takes precedence over `#selectedItem`, so bind `onClose` to your own Tag when it needs a close button
- In multiple mode, empty content from either slot leaves the tag out

</Framework>

<Framework only="solid">

- In not multiple mode: `renderSelectedItem(treeNode: TreeNodeData) => content: JSX.Element`

    - When isRenderInTag is false, the returned content will be rendered directly

## API Reference

### TreeSelect

<Framework only="react">

<TreeSelectReactApi />

`aria-label`, `aria-labelledby`, `aria-describedby`, `aria-errormessage`, `aria-invalid` and `aria-required` land on the current combobox: the trigger when it is not searchable, or the search input when the search box is in the trigger. Other native attributes (such as `id`, `data-*` and `onClick`) land on the trigger element.

</Framework>

<Framework only="vue">

<TreeSelectVueApi />

The Vue TreeSelect has no `className` property: undeclared attributes such as `class`, `style` and `data-*` land on the root element, while `aria-label`, `aria-labelledby`, `aria-describedby`, `aria-errormessage`, `aria-invalid` and `aria-required` land on the current combobox (see [ARIA](#aria)). `focus`, `blur`, `change`, `select` and `keydown` are events of the component and shadow the native events of the same name on the root element.

</Framework>

<Framework only="solid">

<TreeSelectSolidApi />

`class`, `style` and native attributes such as `id` and `data-*` land on the root element (the trigger). `aria-label`, `aria-labelledby`, `aria-describedby`, `aria-errormessage`, `aria-invalid` and `aria-required` land on the current combobox: the root element when the TreeSelect is not searchable, or the search input when it is in the trigger. `onFocus`, `onBlur`, `onChange` and `onSelect` are the component's own callbacks and are not bound to the root element as native events.

</Framework>

<Framework only="svelte">

<TreeSelectSvelteApi />

The Svelte TreeSelect has no `className` property: `class` (a string, an array or an object), `style` (a string), `data-*` and other undeclared attributes and event handlers (such as `onclick`) land on the root element (the trigger), and `onkeydown` is called after the component has handled the key. `aria-label`, `aria-labelledby`, `aria-describedby`, `aria-errormessage`, `aria-invalid` and `aria-required` land on the current combobox (see [ARIA](#aria)). The lowercase `onchange`, `onselect`, `onload`, `onfocus` and `onblur` are not passed through as native listeners; use the callbacks `onChange`, `onSelect`, `onLoad`, `onFocus` and `onBlur`. `dropdownStyle` and `optionListStyle` are style strings. `value`, `expandedKeys` and `loadedKeys` are bindable, and there is no `defaultValue` or `defaultExpandedKeys`; the default of `multiple` can be set through the global defaults.

</Framework>

```vue
    import type { TreeSelectHandle } from '@fibrae/semi-ui-vue';

    const treeSelect = useTemplateRef<TreeSelectHandle>('treeSelect');
    const search = (value: string) => treeSelect.value?.search(value);
</script>

<template>
    <TreeSelect ref="treeSelect" filterTreeNode :treeData="treeData" />
</template>
```

</Framework>

## Accessibility

### ARIA

- Following the ARIA 1.2 combobox pattern, exactly one element is the combobox. Its name comes from, in order of priority: `aria-labelledby`, `aria-label`, the rendered insetLabel (`#insetLabel` in Vue; without `insetLabelId` the component generates the id; with a prefix the insetLabel is not rendered and does not name it), and otherwise the name in the locale:
    - Without search, or with `searchPosition="dropdown"`, the trigger is a select-only combobox. The search input in the dropdown stays a text box with `aria-controls`, `aria-autocomplete` and `aria-activedescendant`
    - With `searchPosition="trigger"`, the search input is the combobox and the only Tab stop, with `aria-autocomplete="list"`; the trigger has no role. In single mode the input is empty until the user types, so the selected text is linked to it as its description (`aria-describedby`). Clicking anywhere on the trigger moves focus to the input;
- TreeSelect allows users to set `aria-describedby`, `aria-errormessage`, `aria-invalid`, `aria-labelledby`, `aria-required`, in addition, Form will automatically set these properties for Form.TreeSelect;
- The `role="tree"` list in the dropdown uses the same name source as the combobox: the same `aria-labelledby` ids, the same `aria-label` or the same insetLabel; with none of them it takes the name in the locale, like the combobox;

<Framework only="react">

- The nodes in the dropdown are the same as in [Tree](/en-US/react/navigation/tree#accessibility): `role="treeitem"` with `aria-level`, `aria-setsize`, `aria-posinset` and `aria-disabled`, and `aria-expanded` on nodes that can expand; a single-choice TreeSelect uses `aria-selected`, a multi-choice one uses `aria-checked` (`mixed` when half checked);

</Framework>

<Framework only="vue">

### Keyboard Interaction

TreeSelect follows the [WAI-ARIA Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) pattern with a tree popup: focus always stays on the trigger or the search input, `aria-activedescendant` points at the current node, and the current node shows the focus ring. There is no current node when the dropdown opens.

- While the dropdown is closed: `ArrowDown`, `ArrowUp`, `Enter` and `Space` open it; `Home` and `End` open it and move to the first or last visible node
- `ArrowDown`, `ArrowUp`: move to the next or previous visible node; the first `ArrowDown` moves to the first node; `Home`, `End`: move to the first or last visible node
- `ArrowRight`: expand a collapsed node; on an expanded node, move to its first child (swapped with `ArrowLeft` in RTL)
- `ArrowLeft`: collapse an expanded node; otherwise move to the parent
- `Enter`, `Space`: select the current node, or check and uncheck it in a multi-choice TreeSelect; disabled nodes do not respond
- Typing characters: while the dropdown is open, move to the next visible node after the current one whose label starts with the typed text; characters typed in quick succession form one search string. A closed dropdown ignores them
- `Esc`: close the dropdown

While focus is in a search input, only `ArrowDown`, `ArrowUp` and `Enter` move and select; the other keys (including characters, `Space`, `Home`, `End`, `ArrowLeft` and `ArrowRight`) edit the text.

<Framework only="react">

The props passed to a custom `searchRender` include these ARIA attributes (`aria-activedescendant`, `aria-controls`, `aria-autocomplete` and the name; on the trigger, the whole set of combobox attributes including `role` and `aria-expanded`); spread them onto the input, or screen readers do not announce the current node. Put the `ref` on the input too (a Semi `Input`, a native input or a textarea); it lets a click on the selected text inside the trigger move focus to it.

</Framework>

With `showClear`, a selected value or search text, and no `disabled`, the trigger renders a clear button. It is a native `button` named "Clear TreeSelect value" from the locale, shown on hover, while the dropdown is open, or while focus is inside the TreeSelect. From the trigger or the search input, `Tab` moves to the clear button; `Enter` or `Space` clears, as a mouse click does, and the focus goes back to the trigger or the search input. In multiple mode `Backspace` in the search input also removes tags.
