### 自定义显示格式与解析方式

> formatter 和 parser 一对方法，一般需要同时设置，否则无法正确解析值

<Notice type="info" title="行为调整">

- **调整前**：当 InputNumber 处于**受控模式**（传入 `value`，Vue 为 `modelValue`）且 `value` 为 **number** 时，首次渲染阶段输入框的展示值可能不会先经过 `formatter` 处理，组件会在 mount 后（或后续更新）再应用 `formatter/parser`，从而出现首帧展示与后续不一致的现象。
- **调整后**：受控模式下当 `value`（Vue 为 `modelValue`）为 **number** 时，首次渲染也会应用 `formatter`（并与 `parser` 配合得到内部数值），保证首帧展示与后续一致。例如百分比场景：`value=1` 且 `formatter/parser` 使展示乘以 100 时，首帧将直接展示 `100`。

</Notice>

## API 参考

<Framework only="react">

<InputNumberReactApi />

其他原生属性（如 `id`、`name`、`tabindex`、`title`、`data-*`）落在原生 `input` 上。

</Framework>

<Framework only="vue">

<InputNumberVueApi />

`v-model` 绑定 `modelValue`（`number | string`），不支持 `.number`、`.trim` 修饰符；非受控初值用 `defaultValue`。`change` 与 `update:modelValue` 同时发出，载荷一致。回调改为同名事件：`@change`、`@numberChange`、`@upClick`、`@downClick`、`@focus`、`@blur`、`@keydown`。`focus`、`blur` 来自 Input 外层的 `focusin`、`focusout`；步进按钮不可聚焦，本身不触发这两个事件。

`prefix`、`suffix`、`insetLabel`、`clearIcon`、`addonBefore`、`addonAfter` 是同名插槽，例如 `prefix="$"` 写成 `<template #prefix>$</template>`。

没有 `prefixCls`、`className`；`class`、`style` 落在外层 `.semi-input-number`，其余属性（`id`、`name`、`tabindex`、`title`、`aria-*`、`data-*`、`role`）落在原生 input。上表未声明的 Input 事件（`enterPress`、`clear`、`input`、`keyup`、`compositionstart` 等）经 attrs 交给内部 Input，直接写 `@enterPress` 等即可。

</Framework>

<Framework only="solid">

<InputNumberSolidApi />

`class`、`style` 与 `ref` 落在外层 `.semi-input-number` 根元素上；其余原生属性和事件（`id`、`name`、`aria-*`、`data-*`、`onInput`、`onKeyUp` 等）落在原生 `input` 上。

</Framework>

<Framework only="svelte">

<InputNumberSvelteApi />

`class`、`style`（字符串）落在外层 `.semi-input-number` 上；其余未声明属性（`id`、`name`、`tabindex`、`title`、`aria-*`、`data-*`、`role`）落在原生 input。`prefix`、`suffix`、`insetLabel`、`clearIcon`、`addonBefore`、`addonAfter` 是 snippet。放在 InputGroup 里时跟随分组的 `size`、`disabled`。

</Framework>

## Methods

<Framework only="vue">

`ref` 拿到 `InputNumberHandle`，成员见上方 API 参考的 Exposes。

</Framework>

<Framework only="react">

InputNumber 的 ref 是命令式句柄（类型为 `InputNumberHandle`），不是原生 DOM 节点。需要节点时读取句柄上的属性，属性每次读取都返回当前挂载的节点，卸载后为 `null`。句柄的方法与属性见 API 参考。

</Framework>

<Framework only="solid">

`ref` 拿到的是根元素（`HTMLDivElement`），不是句柄。根元素的 `focus()` 与 `blur()` 作用于输入框，`focus()` 未传参数时遵循 `preventScroll` 属性。`select()`、`setSelectionRange()` 等原生方法，通过 `inputRef` 取得 `input` 元素后调用。

</Framework>

<Framework only="svelte">

通过 `bind:this` 取得组件实例后调用 `focus(options)`、`blur()`、`select()`、`setSelectionRange()`、`getInput()`、`getNativeElement()`，说明见上方 Methods；`focus()` 未传参数时遵循 `preventScroll` 属性。

</Framework>

## Accessibility

参考标准：https://www.w3.org/WAI/ARIA/apg/patterns/spinbutton/

### ARIA

- 数字输入框具有 spinbutton role
- spinbutton 使用 aria-valuenow 表示当前值，aria-valuemax 表示可以接受的最大值，aria-valuemin 表示可以接受的最小值
- 当 InputNumber 在 Form 中使用时，输入框的 aria-labelledby 指向 Field label

### 键盘和焦点

- InputNumber 可被获取焦点，键盘用户可以使用 Tab 及 Shift + Tab 切换焦点（增加/减少按钮不可以被键盘聚焦）
- 键盘用户可以按上键 ⬆️ 或下键 ⬇️ ，输入值将增加或减少 step（默认值为 1）
- 按住 Shift + 上键 ⬆️ 或下键 ⬇️ ，输入值将增加或减少 shiftStep（默认值为 10）
- 设置了 `min` 时按 Home 跳到最小值，设置了 `max` 时按 End 跳到最大值；未设置对应边界时，两个键照常移动光标
- 值已在边界、按键后数值不变时，不会触发 `onChange`（Vue 为 `change` 事件）
