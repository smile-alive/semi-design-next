### Input in Panel

Use `insetInput` to control whether the date panel is inset with the input box, the default is `false`. Supported since `v2.7.0`. Inset input boxes are suitable for the following scenarios:

- Date and time selection, you can directly input the time through the embedded input box, no need to select the time through the scroll wheel
- With a custom trigger and range selection, use the inset input box to modify the start and end dates independently

After `insetInput` is turned on, it includes the following functions:

- After clicking the trigger, the panel will pop up in the original position by default. You can customize the popup position by `position`
- Click the embedded date input box, the panel switches to date selection; click the embedded time input box, the panel switches to time selection
- Consistent with the external input box, if an illegal date is entered, the date will return to the previous legal date after the panel is closed

<Notice type="primary" title="Notes">

Note that some adjustments and restrictions will be made to the components after opening insetInput:

1. Trigger style: the trigger is read-only when the panel is not open, and the trigger is disabled when it is open
2. Panel style: when type includes time, hide the toggle button at the bottom
3. After insetInput is enabled, the `format` API only supports the `dateFormat[ timeFormat]` format. Using other formats will affect the display of the inset input box placeholder and trigger text. When timeFormat is a 12-hour format (such as `hh:mm a`), the inset time input shows and accepts 24-hour time

</Notice>

<Framework only="vue">

By default we use the `Input` component as the trigger for the `DatePicker` component. You can customize this trigger with the `#trigger` scoped slot.

The custom trigger is a complete customization of the trigger, the default clear button will not take effect, if you need clear function, please customize a clear button that calls `onClear` from the slot props.

The slot props are `value`, `inputValue`, `placeholder`, `disabled`, `size`, `inputReadOnly`, `rangeInputFocus`, `type`, `format`, `multiple`, `autofocus` and `componentProps`, plus `onChange` (sets the input text, as typing does), `onEnterPress` (commits the input text) and `onClear` (reports a click on the clear button). `inputValue` is `null` until the user types; show the formatted `value` then. The slot props carry no `aria-*` attributes, so name the custom content yourself.

</Framework>

## API Reference

<Framework only="react">

<DatePickerReactApi />

Other native attributes (such as `id`, `title`, `data-*`, `aria-label` and `onClick`) land on the root element, except `tabIndex`, which lands on the input. Where `aria-labelledby`, `aria-describedby`, `aria-errormessage`, `aria-invalid` and `aria-required` land:

- A single input: all of them land on the input
- A range type: the root element is `role="group"` and takes `aria-labelledby`; the other four land on both inputs
- `triggerRender` content without a focusable element: `aria-labelledby`, `aria-describedby`, `aria-errormessage` and `aria-invalid` land on the wrapper with the role `button`; `aria-required` is not forwarded
- `triggerRender` content with its own focusable element: none of them is forwarded, so set them on the rendered content

</Framework>

<Framework only="vue">

<DatePickerVueApi />

`modelValue` with `update:modelValue` is `v-model`, and `open` with `update:open` is `v-model:open`. `autofocus` is lowercase; `triggerRender`, `renderDate`, `renderFullDate`, `rangeSeparatorNode` and the other ReactNode props are slots.

Undeclared attributes such as `class`, `style`, `id`, `title`, `data-*` and `aria-label` land on the root element, which is `role="group"` when it has an `aria-label`. Where `aria-labelledby`, `aria-describedby`, `aria-errormessage`, `aria-invalid` and `aria-required` land:

- A single input: all of them land on the input
- A range type: the root element is `role="group"` and takes `aria-labelledby`; the other four land on both inputs
- `#trigger` content without a focusable element: `aria-labelledby`, `aria-describedby`, `aria-errormessage` and `aria-invalid` land on the wrapper with the role `button`; `aria-required` is not forwarded
- `#trigger` content with its own focusable element: none of them is forwarded, so set them on the slot content

`change`, `focus` and `blur` shadow the native events of the same name bubbling from the root. A DatePicker deactivated inside `<KeepAlive>` closes its panel and emits only `update:open` and `openChange`.

## Methods

<Framework only="react">

The handle obtained through `ref` carries the `open()`, `close()`, `focus(focusType?)` and `blur()` methods, see the Methods table in the API Reference. `focus` focuses the input; a range type focuses the start input by default, or the end input with `'rangeEnd'`. With `insetInput` and the panel open, it focuses the input inside the panel.

</Framework>

<Framework only="vue">

A template ref exposes `open()`, `close()`, `focus(rangeEnd?)` and `blur()`. `focus` focuses the input; a range focuses its start input unless `rangeEnd` is given, and with insetInput the focus goes to the input in the panel. `blur` blurs the input. A controlled `open` wins: `open()` and `close()` do not change the visibility of the panel then.

</Framework>

A `ref` on the picker gets the root element, which carries the `open()`, `close()`, `focus(focusType?)` and `blur()` methods; the table is in the API Reference. `focus` focuses the input; a range focuses its start input unless `'rangeEnd'` is given, and with `insetInput` the focus goes to the input in the panel.

## Accessibility

### ARIA

- The input has the role `combobox` with `aria-haspopup="dialog"`, an `aria-expanded` that follows the panel, and `aria-controls` pointing at the panel; both inputs of a range do
- A single input is named `Choose date` while no date is selected and `Change date` once one is (an `aria-labelledby` you pass wins)
- When the content of a custom trigger (`triggerRender` in React, the `#trigger` slot in Vue) has no focusable element, the wrapper is the focus target with the role `button`, named as above
- The role of the month in the date panel is `grid`, named by the year and month title at the top of the panel; the role of the week is set to `row`, and the date cell is set to `gridcell`
- The year and month scroll columns are `listbox` lists named "year" and "month"
- `aria-disabled` is true for the corresponding option when date and time are disabled
- With multiple or range selection, `aria-multiselectable` of month is true, and `aria-selected` of date grid is true when selected
- Some decorative icons in the panel, their `aria-hidden` is true

### Keyboard and Focus

- `Down Arrow` in the input opens the panel; once the panel is open, `Down Arrow` moves focus into it
- The date grid is one Tab stop: the `arrow keys`, `Home`, `End`, `PageUp` and `PageDown` (by year with `Shift`) move the active date, and `Enter` or `Space` picks it
- The date and time switches at the bottom of a dateTime panel are buttons that `Enter` or `Space` activates
- With a range value, Tab reaches the clear button after the end input, and `Enter` or `Space` clears the range
- `Esc` closes the panel; focus inside the panel returns to the input, or to the custom trigger when there is one
- When the content of a custom trigger has no focusable element, Tab reaches the wrapper, and `Enter`, `Space` or `Down Arrow` opens the panel

## Date and Time Format

Adopted in the semi-ui component library [date-fns v4](https://date-fns.org/docs/Getting-Started) As a date and time engine, formatting token means the following:

- `"y"`: Year
- `"M"`: month
- `"d"`: day
- `"H"`: hours
- `"h"`: hours (12h)
- `"m"`: minutes
- `"s"`: seconds

The following uses `new Date('2023-12-09 08:08:00')` or `[new Date('2023-12-09 08:08:00'), new Date('2023-12-10 10 :08:00')]` as `value` to explain the impact of different types and different `format` values on the displayed value:

| type          | format              | display value                       |
| ------------- | ------------------- | ----------------------------------- |
| date          | yyyy-MM-dd          | 2023-12-09                          |
| dateTime      | yyyy-MM-dd HH:mm:ss | 2023-12-09 08:08:00                 |
| month         | yyyy-MM             | 2023-12                             |
| year          | yyyy                | 2023                                |
| dateRange     | yyyy-MM-dd          | 2023-12-09 ~ 2023-12-10             |
| dateTimeRange | yyyy-MM-dd HH:mm:ss | 2023-12-09 08:08 ~ 2023-12-10 10:08 |

Multiple dates or times are used by default `","` (English comma) separated.

> More token available [Date-fns official website](https://date-fns.org/docs/Unicode-Tokens)

## FAQ

- **Date time picker, when you choose time, minute and second, you don't want to scroll infinitely. How to achieve the effect?**  
  Starting from version V2.22.0, we changed the default mode of ScrollItem in TimePicker from wheel to normal. If you want to apply the infinite scrolling effect again, you can control this behavior through a specific switch in timePickerOpts, that is:

      <Framework only="react">

    timePickerOpts=\{\{ scrollItemProps: \{ mode: "wheel", cycled: true \} \}\}.

      </Framework>

      <Framework only="vue">

    `:timePickerOpts="{ scrollItemProps: { mode: 'wheel', cycled: true } }"`.

      </Framework>

      <Framework only="solid">

    `timePickerOpts={{ scrollItemProps: { mode: 'wheel', cycled: true } }}`.

      </Framework>

- **How to set the default display time when the panel is opened?**  
  You can use the defaultPickerValue property.

- **Date time selection, range date selection, after inputting some dates, the panel does not echo the date?**

    The input box needs to be entered completely before it is showed to the panel. For example, for `dateTime` type, the full requested date and time have been entered. For `dateRange` type, full requires start and end dates to be entered.

- **What is the displayed time at the bottom of the date time selection panel?**

    When no time is selected, it is the value of the time in `defaultPickerValue`, if not set it is the time when the panel was opened. After selecting a time, it is the selected time.

    Since it has two hidden meanings in design, which may lead to ambiguity, it is recommended to use inline styles and open them through `insetInput`. It is recommended to read the relevant <a href="#input-in-panel">Documentation</a> before use.
