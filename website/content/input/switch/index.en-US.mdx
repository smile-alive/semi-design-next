### Basic Usage

<Framework only="react">

You can monitor state changes through `onChange`, and set the selected state through `defaultChecked` or controlled `checked`.  
Use `aria-label` to describe the specific function of the Switch

</Framework>

<Framework only="vue">

You can monitor state changes through `@change`, and set the selected state through `defaultChecked` or `modelValue` (`v-model`).  
Use `aria-label` to describe the specific function of the Switch

</Framework>

<Framework only="solid">

You can monitor state changes through `onChange`, and set the selected state through `defaultChecked` or controlled `checked`.  
Use `aria-label` to describe the specific function of the Switch

</Framework>

<Framework only="svelte">

You can monitor state changes through `onChange`. A plain `checked` sets the initial state, which the user then toggles; to read and write the state, use `bind:checked` (see Controlled component).  
Use `aria-label` to describe the specific function of the Switch

</Framework>

### Controlled component

<Framework only="react">

Whether the component is selected depends entirely on the incoming checked value, used with `onChange`

</Framework>

<Framework only="vue">

Whether the component is selected depends entirely on the incoming `modelValue`, used with `v-model`. With a one-way `:modelValue` and no write-back, a click only notifies and the passed value decides what is shown.

</Framework>

<Framework only="solid">

Whether the component is selected depends entirely on the incoming `checked` value, used with `onChange`. With a one-way `checked` and no write-back in the callback, a click only notifies and the passed value decides what is shown.

</Framework>

<Framework only="svelte">

Use `bind:checked` to keep the checked state in sync with a `$state` variable. To reject or rewrite a toggle, use a function binding `bind:checked={() => value, (next) => { ... }}`; the switch shows what the getter returns. A plain `checked` without a binding is only the initial value: a click toggles it inside the component, and a new value from the parent wins again.

</Framework>

## API reference

<Framework only="react">

<SwitchReactApi />

`className`, `style`, `ref`, `onFocus`, `onBlur` and other native attributes (such as `data-*`) land on the root element; `onFocus` and `onBlur` receive the focus events bubbling up from the inner input. `autoFocus` and `aria-*` land on the inner native input.

</Framework>

<Framework only="vue">

<SwitchVueApi />

`class` and `style` land on the root element. `id`, `name`, `tabindex`, `autofocus`, `aria-*` and focus and blur listeners passed as attrs land on the inner native input; other native attributes and listeners (such as `@mouseenter`) land on the root element.

</Framework>

<Framework only="solid">

<SwitchSolidApi />

`class`, `style`, `ref` and other native attributes and listeners (such as `onMouseEnter`) land on the root element. `id`, `name`, `tabIndex`, `autofocus`, `aria-*`, and `onFocus` and `onBlur` land on the inner native input.

</Framework>

<Framework only="svelte">

<SwitchSvelteApi />

`class`, `style` and other native attributes and listeners (such as `onmouseenter`) land on the root element. `id`, `name`, `tabindex`, `autofocus`, `aria-*`, and `onfocus` and `onblur` land on the inner native input.

</Framework>

## Accessibility

### ARIA

- The inner input of Switch has a `switch` role, and its on or off state is expressed by the native checked state of the input.
- As a form field, it should have a Label.

<Framework only="react">

- The Label is added automatically when you use Form.Switch. If you use Switch alone, it is recommended to use `aria-label` to describe the current label function.

</Framework>

<Framework only="vue">

- It is recommended to use `aria-label` to describe the current label function, or `aria-labelledby` to point to a visible label on the page.

</Framework>

<Framework only="svelte">

- It is recommended to use `aria-label` to describe the current label function, or `aria-labelledby` to point to a visible label on the page.

</Framework>

<Framework only="solid">

- The Label is added automatically when you use `FormSwitch`. If you use Switch alone, it is recommended to use `aria-label` to describe the current label function, or `aria-labelledby` to point to a visible label on the page.

</Framework>

### Keyboard and Focus

- Keyboard users can use `Tab` and `Shift + Tab` to switch focus.
- When focusing, you can switch on or off by pressing the `Space` key.

## Content Guidelines

- Switch description
    - First letter is capitalized, no punctuation is required
    - Indirectly and explicitly state whether the setting is on or off
    - If needed, explain to the user what the on and off states represent
