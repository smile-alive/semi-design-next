## API参考

<Framework only="react">

<SliderReactApi />

其余原生属性（如 `data-*`）落在 `.semi-slider-wrapper` 上。`aria-describedby`、`aria-invalid`、`aria-errormessage` 与 `onKeyDown` 落在每个滑块的原生 input 上，`autoFocus` 作用于第一个滑块的 input。`onBlur` 挂在 `.semi-slider-wrapper` 上，在两个滑块之间移动焦点时不触发。`tabIndex`、`aria-required` 不输出。

## RTL/LTR

- Slider 的水平方向支持 RTL，可通过 [ConfigProvider](/zh-CN/react/other/config-provider) 配置 `direction="rtl"` 启用。
- RTL 模式下，Slider 水平方向的最小值在右侧，最大值在左侧，滑块拖动方向与 LTR 相反。
- 垂直方向（`vertical`）不受 RTL 影响。
- RTL 模式下，键盘方向键的行为会镜像：`左箭头` 增加值，`右箭头` 减少值。

## Accessibility

### ARIA

- 每个滑块内有一个视觉隐藏的原生 `<input type="range">`，它是真正的焦点和表单控件（隐式 role 为 `slider`），可见的滑块只负责绘制和拖动。查询控件时请使用 `getByRole('slider')` 或 `input[type="range"]`，不要查询 `.semi-slider-handle`。
- 当前值、最小值、最大值由 input 的 `value`、`min`、`max` 提供给辅助技术。`range` 模式下两个 input 的 `min`、`max` 都是整个滑条的范围，一个滑块移动到另一个滑块处即停止。
- 当 Slider 为纵向时，input 带 `aria-orientation="vertical"`，并以 `writing-mode: vertical-lr` 呈现纵向。
- 当值不容易被理解时，支持通过 API `aria-valuetext` 传递一个字符串使其更友好。也可以通过 API `getAriaValueText(value, index)` 方法得到 `aria-valuetext` 的值。
- 支持通过 API `aria-label` 或者 `aria-labelledby` 确定 slider 的标签，也可以用 `<label for>` 指向 `id`：`id` 落在第一个滑块的 input 上，点击 label 会聚焦该滑块。
- 禁用时（`disabled`）不会用语言包文案覆盖手柄的名称：禁用状态由原生 `disabled` 表达，`aria-label`、`aria-labelledby` 与 `<label for>` 给出的名称保持不变；没有任何命名时，禁用的手柄和可用的手柄一样没有名称。
- `range` 模式下两个滑块各有自己的名称：`aria-label` 之后追加语言包中的「起点」「终点」（如 `价格 起点`、`价格 终点`）；使用 `aria-labelledby` 时，每个滑块的名称是该标签加上「起点」或「终点」；都没有传时名称就是「起点」「终点」。外层 wrapper 没有角色，不再带 `aria-label`。
- 在 Form 中使用时，Form 注入的 `id`、`aria-labelledby`、`aria-describedby`、`aria-invalid`、`aria-errormessage` 落在 input 上；`aria-required` 不输出，因为 slider 角色不支持该属性。
- 传入 `name` 后，Slider 可以随原生 `<form>` 提交：单值提交一个值，`range` 模式下两个 input 使用同一个 `name`，依次提交两个值（`FormData.getAll(name)` 得到 `[最小值, 最大值]`）。禁用时与其他原生控件一样不参与提交。

### 键盘和焦点

- 方向键由组件处理，各浏览器行为一致；`Home`、`End`、`Page Up`、`Page Down` 由原生 range 处理。滑块可获取焦点，键盘聚焦时在可见滑块上绘制聚焦轮廓，并展示当前滑块的提示信息；用指针按下滑块时焦点同样落到该滑块，但不显示聚焦轮廓。
- `onKeyDown`（Vue 为 `onKeydown`）绑定在手柄的 input 上，每个按键都会先调用它再由滑块处理；取值键（方向键、`Home`、`End`、`Page Up`、`Page Down`）默认不冒泡到祖先元素，在回调中调用 `preventDefault` 可以拦截该键，滑块不再处理它。
- 当用户使用 `range` 属性时，可以使用 `Tab` 及 `Shift` + `Tab` 切换左右两个滑块的焦点。
- 方向键与滑块在屏幕上的移动方向一致：水平时 `右箭头`、`上箭头` 增加值，`左箭头`、`下箭头` 减少值（RTL 下左右镜像）；纵向时值从上往下增大，`下箭头` 增加值、`上箭头` 减少值；`verticalReverse` 时值从下往上增大，`上箭头` 增加值、`下箭头` 减少值；纵向时 `右箭头` 始终增加值，`左箭头` 始终减少值。
- 若想要滑块高于步长的变化量，`Page Up`、`Page Down` 每次变化整个范围的 10%（按步长取整）：
    - Windows 用户： `Page Up` 用于增加，`Page Down` 用于减少；
    - Mac 用户使用： `Fn` + `上箭头` 用于增加，`Fn` + `下箭头` 用于减少；
    - 当用户使用 `range` 属性时，前一个滑块的 `Page Up`(`Fn` + `上箭头`) 键仅支持到与后一个滑块相遇，重合后再对前一个滑块使用 Page Up 键则无响应。后一个滑块同理，相遇后，对`Page Down`(`Fn` + `下箭头`) 键无响应。
- 若想将滑块移动到滑杆的最小值处：
    - Windows 用户： `Home` ；
    - Mac 用户： `Fn` + `左箭头`；
    - 当用户使用 `range` 属性时，后一个滑块的 `Home`(`Fn` + `左箭头`) 键仅支持到与前一个滑块相遇，重合后再次使用 `Home`(`Fn` + `左箭头`) 键无响应。
- 若想将滑块移动到滑杆的最大值处：
    - Windows 用户：`End` ；
    - Mac 用户：`Fn` + `右箭头`；
    - 当用户使用 `range` 属性时，前一个滑块的 `End`(`Fn` + `右箭头`) 键仅支持到与后一个滑块相遇，重合后再次使用 `End`(`Fn` + `右箭头`) 键无响应。

## 设计变量

### 聚焦样式说明

Slider 组件有两个与聚焦相关的设计变量，分别对应不同的交互场景：

| 变量名                      | CSS 变量                            | 触发场景               | 说明                                                                                                                                    |
| --------------------------- | ----------------------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 圆形按钮轮廓 - 聚焦         | `--semi-color-primary-light-active` | 键盘导航（Tab 键聚焦） | 滑块内的 input 匹配 `:focus-visible` 时（`.semi-slider-handle:has(> input:focus-visible)`）在可见滑块上显示 outline，仅在键盘聚焦时显示 |
| 滑动条圆形描边颜色 - 激活态 | `--semi-color-focus-border`         | 鼠标点击/拖动          | 使用 `.semi-slider-handle-clicked` 类，在鼠标交互时显示 border                                                                          |

如果你希望在主题配置中修改圆形按钮的聚焦样式，请注意上述两个变量对应不同的交互场景。
