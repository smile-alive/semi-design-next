You can also define columns by writing `Table.Column` as children of Table: the column data goes on its props, and the custom content of cells and titles goes in its `#cell`, `#title` and other slots. ### Custom Rendering

<Framework only="solid">

Users can use Column.render to customize the rendering of a column of cells, which is suitable for rendering more complex cell content. `render` is called again whenever the row data or index changes; read the fields of `options` in the returned JSX to follow the row state, with no extra subscription needed.

The fourth parameter `options` of the `render` function is an object containing the following properties:

- `expandIcon`: Render function of the expand icon (when using tree data or expandable rows); call it where it is inserted, e.g. `{options.expandIcon?.()}`
- `selection`: Render function of the selection checkbox (when row selection is enabled)
- `indentText`: Render function of the indent content (when using tree data)
- `isHovering`: Whether the current row is in hover state

With the `isHovering` parameter, you can implement interaction effects such as displaying action buttons on mouse hover.

</Framework>

Users can use the `#cell` scoped slot to customize the rendering of cells, which is suitable for rendering more complex cell content. The `#cell` slot on Table is called for every data column; tell the columns apart with `column.dataIndex` or `column.key`. When the slot outputs nothing, the raw value is shown. To customize one column only, put `#cell` on that column's `Table.Column` instead, which takes precedence over the slot on Table.

The parameter of `#cell` is an object containing the following properties:

- `text`: the value at `column.dataIndex`, or the data item itself for a column without `dataIndex`

- `index`: the index of the data item among its siblings
- `column`: the configuration of the current column
- `expandIcon`: Expand icon (when using tree data or expandable rows)
- `isHovering`: Whether the current row is in hover state
- `selection`, `indentText`: the selection checkbox and the indent content, provided only when the column enables `useFullRender`, see [Fully custom rendering](#fully-custom-rendering)

With the `isHovering` parameter, you can implement interaction effects such as displaying action buttons on mouse hover.

### Table With Pagination

Table paging currently supports two modes: controlled and uncontrolled.

- In controlled mode, the paging state is passed entirely externally, depending on whether the pagination .currentPage field is passed. In general, the controlled mode is suitable for remotely pulling data and rendering.
- In uncontrolled mode, Table passes the incoming dataSource length as total to the Pagination component by default, and of course you can also pass a total field to overwrite the value of the Table component, but we do not recommend users to pass this field in uncontrolled paging mode.

> Note: The custom `pagination.total` field passed in uncontrolled conditions is supported.

### Pull Remote Data

Under normal circumstances, the data is often not obtained at one time. We will retrieve the data from the interface when clicking on the page number, filter or sort button. ### Fixed Column or Head

You can fix the column by setting the Fixed attribute of the column and scroll.x, and fix the header by setting scroll.y.

> - It is recommended to specify scroll.x as a **fixed value** or percentage greater than the width of the table. If it is a fixed value, set it to >= the sum of all fixed column widths + the sum of all table column widths.
> - Make sure that all elements inside the table do not affect the height of the cells after rendering (e.g. containing unloaded pictures, etc.). In this case, give the stator element a definite height to ensure that the left and right Fixed columns of cells are not deranged.
> - If the column header is not aligned with the content or there is a column duplication or when the fixed column fails, specify the width width of the fixed column, if still not effective, try to recommend leaving a column with no width to accommodate the elastic layout, or check for ultra-long continuous fields to destroy the layout.

<Demo id="fixed" />

The header can be fixed to the top of the page with the `sticky` property. When passing `top`, you can control the distance from the scroll container.

After turning on sticky, Table will automatically turn on the fixed layout, and the column width will be determined by `column.width`. Columns without a given width are automatically assigned by the browser.

```jsx
                console.log(`selectedRowKeys: ${selectedRowKeys}`, 'selectedRows: ', selectedRows);

                disabled: record.name === 'Michael James', // Column configuration not to be checked

        return data;
    };

    useEffect(() => {
        const data = getData();
        setData(data);
    }, []);

    return <Table sticky={{ top: 60 }} columns={columns} dataSource={dataSource} rowSelection={rowSelection} scroll={scroll} />;
}
```

### Table Header With Sorting and Filtering Function

Filters and sorting controls are integrated inside the table, and users can pass in the sorter display of the sorter open header by passing filters in Column and the filter control display of the onFilter open header.

> Note: Be sure to provide a "key" for each row of data that is different from other row values, or use the rowKey parameter to specify a property name as the primary key.

> Note: Sorting and filtering columns must set independent "dataIndex"

<Demo id="sort-filter" />

When sorter is a function type, the sortOrder status can be obtained through the third parameter of the function. The function type is `(a?: RecordType, b?: RecordType, sortOrder?: 'ascend' | 'descend') => number`.

You can control whether to display the sorting tip through the `showSortTip` attribute, which defaults to `false`. When the tip is turned on, when there is only sorting function, the sorting prompt will be displayed when the mouse is moved to the table header; in other cases, the sorting prompt will be displayed only when the mouse is moved to the sorting icon.

**Note**: When using the `sortOrder` attribute for controlled sorting, since the next sort order cannot be predicted, `showSortTip` does not take effect and the prompt will not be displayed.

### Custom Filter Rendering

<Framework only="react">

Use `renderFilterDropdown` to customize the render filter panel.

You can call `setTempFilteredValue` to store the filter value when the user enters the filter value, and call `confirm` to trigger the actual filtering after the filter value is entered. You can also filter directly through `confirm({ filteredValue })`.

The reason for setting `tempFilteredValue` is that in scenarios where temporary filtered values need to be stored, there is no need to declare a state to save this temporary filtered value.

```typescript
type RenderFilterDropdown = (props: RenderFilterDropdownProps) => React.ReactNode;
interface RenderFilterDropdownProps {
    /** Temporary filter value, the initial value is `filteredValue` or `defaultFilteredValue` */
    tempFilteredValue: any[];
    /** Set temporary filter value */
    setTempFilteredValue: (tempFilteredValue: any[]) => void;
    /** `confirm` will assign `tempFilteredValue` to `filteredValue` by default and trigger the `onChange` event. You can also set the filter value directly by passing in `filteredValue` */
    confirm: (props?: { closeDropdown?: boolean; filteredValue?: any[] }) => void;
    /** Clear filter values and temporary filter values */
    clear: (props?: { closeDropdown?: boolean }) => void;
    /** Close dropdown */
    close: () => void;
    /** Restore the temporary filter value to the applied filter value */
    reset: () => void;
    /** Filter configuration items, do not pass if not required */
    filters?: RenderDropdownProps['filters'];
}
```

</Framework>

<Framework only="vue">

Set `filterDropdown` of the column to `true`, then customize the filter panel with the `#filterDropdown` slot. The slot can be written on Table (called for every column whose `filterDropdown` is `true`, tell the columns apart with `column`) or on `Table.Column`; when the slot outputs nothing, the filter menu is shown.

You can call `onTempFilteredValueChange` to store the filter value when the user enters the filter value, and call `onConfirm` to trigger the actual filtering after the filter value is entered. You can also filter directly through `onConfirm({ filteredValue })`.

The reason for providing `tempFilteredValue` is that in scenarios where temporary filtered values need to be stored, there is no need to declare a ref to save this temporary filtered value.

```typescript
interface TableFilterDropdownSlotProps {
    /** The configuration of the current column */
    column: ColumnProps;
    /** Filter configuration items, `undefined` when the column has no `filters` */
    filters: TableFilter[] | undefined;
    /** Temporary filter value, the applied filter value when nothing is stored */
    tempFilteredValue: any[] | undefined;
    /** Set temporary filter value */
    onTempFilteredValueChange: (value: any[] | undefined) => void;
    /** `onConfirm` will assign `tempFilteredValue` to `filteredValue` by default and emit the `change` event. You can also set the filter value directly by passing in `filteredValue` */
    onConfirm: (options?: { closeDropdown?: boolean; filteredValue?: any[] }) => void;
    /** Clear filter values and temporary filter values */
    onClear: (options?: { closeDropdown?: boolean }) => void;
    /** Close dropdown */
    onClose: () => void;
```

## onRow/onHeaderRow Usage

> Also in `column.onCell` `column.onHeaderCell` Properties or events supported by td / th can also be returned.

The third parameter `rowStatus` of `onRow` can get the current row's status information, including `disabled` and `selected` properties. This is useful when you need to execute different logic based on the row's selected or disabled state, for example, determining whether to allow selection when clicking a row.

<Framework only="vue">

The listeners in the returned object use Vue's `onXxx` naming (`onClick`, `onMouseenter`, `onMouseleave`), and the style class is `class`.

## Accessibility

### ARIA

Table follows the [WAI-ARIA Table](https://www.w3.org/WAI/ARIA/apg/patterns/table/) pattern: it is a static table, arrow keys do not move between cells, and every interactive part (sort, filter, expand, select) is a native control reachable with Tab.

- The table's role is table, rows are row, header cells are columnheader and cells are cell. A tree table is a table too and does not expose row levels
- The sort button is a native `button` in the header cell, named by the column title. The sort direction is `aria-sort` on the header cell (`ascending` or `descending`); unsorted columns do not carry it. The `showSortTip` tip shows when the button is focused
- The expand button is a native `button` named "Expand this row", with `aria-expanded` telling whether the row is expanded
- The row selection checkboxes have accessible names such as "Select this row" and "Select all rows"
- With a fixed header (`scroll.y`, `sticky`) or virtualization, the header and the body render as two table elements; their common container has the table role and the inner tables have role none, so cells stay associated with their column headers
- In a virtualized table `aria-rowcount` is the header row count plus the total data row count, and data rows' `aria-rowindex` continues after the header rows, so screen readers announce rows that are not in the DOM

<Framework only="react">

- The default column filter icon is a native `button`: Tab focuses it, Enter, Space or Down Arrow opens the filter menu, and it carries `aria-haspopup="menu"` and `aria-expanded`. With a custom `filterIcon`, keeping it focusable is up to you

</Framework>

<Framework only="vue">

- The column filter button is a native `button`: Tab focuses it, Enter, Space or Down Arrow opens the filter menu, and it carries `aria-haspopup="menu"` and `aria-expanded`. Its name is "Filter data with this column", or "Filter this column, filter active" when a filter value is set. The `#filterIcon` slot only replaces the icon inside the button, and the name and keyboard behavior of the button stay the same

</Framework>

Known limitations:

- In a sortable column the `title` renders inside the sort button, so do not put buttons, links or other interactive content in it

<Framework only="solid">

- The default column filter icon is a native `button`. It can be focused with Tab, and Enter, Space or the down arrow opens the filter menu. It carries `aria-haspopup="menu"` and `aria-expanded`. When you customize `filterIcon`, the caller must make sure it is focusable.

</Framework>

## FAQ

- **Clicking the row selection button on the second page will jump to the first page?**

    After the Table's dataSource is updated, the page number will be reset to the initial state. Please check if the data source changed when the component was rendered.

      <Framework only="vue">

    The Table of Vue compares the old and new `dataSource` item by item: it is not reset when every item is still the original record, and it is reset when records are added or removed. Do not write a literal in the template, and do not regenerate the record objects on every render.

    ```vue
    <script setup lang="ts">
    ```

- **The number of filtered data is wrong?**

    Please check that your filter columns and data sources are configured correctly.

- **Why is the table data not updated?**

      <Framework only="react">

    At present, all parameters of the table component are shallow comparison. That is to say, if the parameter value type is an array or object, you need to manually change its reference to trigger the update. Similarly, if you don't want to trigger additional updates, try not to use literal values when passing parameters directly or define reference parameter values in the render process:

    ```text
    // ...render() {
        <Table dataSource={[/*...*/]} columns={[/*...*/]} />
    // }
    ```

    The above writing method will trigger the update of data in the table every time render (the current selected row will be cleared and the row key array will be expanded, etc.). In order to improve performance and avoid some exceptions, **please define some reference type parameters outside the render method as far as possible (if hooks are used, please use useMemo or useState for storage).**

      </Framework>

      <Framework only="vue">

    Vue tracks changes reactively: keep `dataSource` in a `ref` or `shallowRef`, and replacing the whole array or calling `push`, `splice` and similar methods triggers an update; with a `shallowRef`, changing a field of a record directly does not, so replace the whole array. The same goes for `columns`: use `computed` when it depends on reactive data, otherwise define it at the top level of `script setup`, and avoid literals written in the template.

      </Framework>

      <Framework only="solid">

    Table updates by where props are read. Reading signals such as `columns` and `dataSource` in JSX makes them follow changes. A `columns` array defined inside the component is created only once, so column configuration that depends on signals should use getters or be read inside `render`.

      </Framework>

- **Why can't my form line be selected and expanded?**

    Please specify a rowKey or set a different "key" attribute for each item of the dataSource. **All rows related operations in the table need to be used.**

- **How to implement custom sorting or pass parameters to the server for sorting when clicking the sort button?**

    The input parameters of the onChange method include pagination, filters, and sorter. Users can customize the sorting of the dataSource according to the sorter.

- **How to add className to a row?**

    Use onRow or onHeaderRow.

- **How to style the table cell?**

    It can be controlled by column.onHeaderCell and column.onCell.

- **Why cache the previously selected keys for the first parameter of `rowSelection` `onChange`?**

    This is for the scenario where the selected row keys are lost when data is selected on the first page during paging, and then the data is selected on the second page. If you don't want to use the cached keys, you can filter it from the current dataSource or use the second parameter of `rowSelection` `onChange`.

- **Does it support single row selection?**

    Table currently does not support single-row selection function, and users can implement single selection in a custom way.
