### Render in the specified container

You can specify the parent DOM of the preview component through `getPopupContainer` (you need to specify `position: relative`), and the image preview will be rendered into this DOM. This will change the DOM tree position, but not the view's rendering position.

When the container is not `document.body` (including a `getPopupContainer` set only on ConfigProvider), the preview is non-modal: it does not output `aria-modal`, does not trap Tab and does not lock page scrolling. Returning `document.body` from `getPopupContainer` is the same as not passing it.

<Framework only="react">

If you want to customize the preview bottom operation area based on the default bottom operation area, you can get the default ReactNodes through the menuItems of renderPreviewMenu. menuItems is an array of ReactNodes, and the order is consistent with the content order of the default bottom operation bar area.

</Framework>

<Framework only="vue">

Render them with `<component :is>`

</Framework>

<Framework only="solid">

To customize the bottom action area based on the default one, get the default JSX elements through the `menuItems` argument of `renderPreviewMenu`: an array in the order previous, page counter, next, zoom out, zoom slider, zoom in, original size / fit to page, rotate and download, which can be rendered in any position.

</Framework>

<Framework only="svelte">

### Customize the preview top display area

<Framework only="react">

You can customize the preview top display area through `renderHeader`

</Framework>

<Framework only="vue">

The `#title="{ title, index }"` slot replaces the content of the title section at the top of the preview. Use `#closeIcon` to replace the close icon, and `#leftIcon="{ index }"` and `#rightIcon="{ index }"` to replace the arrow icons

</Framework>

<Framework only="solid">

`renderHeader` customizes the top area of the preview; it receives the current title (a JSX element) and returns a new JSX element

</Framework>

<Framework only="svelte">

The `title` snippet, which receives `{ title, index }`, replaces the content of the title section at the top of the preview. When there is a title, the preview dialog is named by that section through `aria-labelledby`, so its name is the text the snippet renders; without a title the name is "Preview" from the locale. Use the `closeIcon` snippet to replace the close icon, and the `leftIcon` and `rightIcon` snippets, which receive `{ index }`, to replace the arrow icons

</Framework>

## API reference

### Image

<Framework only="react">

<ImageReactApi />

`onLoad` and `onError` are called when the image loads successfully or fails, with a `SyntheticEvent<HTMLImageElement>`; other native attributes (such as `data-*` and `aria-*`) pass through to the inner img node.

The `preview` object of a single Image accepts the ImagePreview props below, except `lazyLoad`, `lazyLoadMargin`, `children`, `className` and `style` (use `previewCls` and `previewStyle` to style the preview). When `preview.src` is an array, switching images returns to "fit to page".

</Framework>

<Framework only="vue">

<ImageVueApi />

A number for `width` or `height` is in px. `class` and `style` land on the root element; other undeclared native attributes and listeners land on the inner img. The `preview` object accepts the props and callbacks of ImagePreview (`onVisibleChange`, `onChange`, `onClose`, `onZoomIn`, `onZoomOut`, `onPrev`, `onNext`, `onRatioChange`, `onRotateLeft`, `onDownload`, `onDownloadError`), except `lazyLoad`, `lazyLoadMargin`, `class` and `style` (use `previewCls` and `previewStyle` to style the preview). Custom nodes do not go in `preview`; use the slots of Image. When `preview.src` is an array, switching images returns to "fit to page". An Image inside an ImagePreview ignores `#title`, `#previewMenu`, `#leftIcon`, `#rightIcon` and `#closeIcon`; the slots of the ImagePreview apply.

</Framework>

<Framework only="solid">

<ImageSolidApi />

`class` and `style` land on the thumbnail root element; `ref`, `id`, `aria-*` and native events (such as `onClick`) land on the inner img.

</Framework>

<Framework only="svelte">

<ImageSvelteApi />

A number for `width` or `height` is in px. `class` and `style` land on the root element; other undeclared native attributes and event handlers land on the inner img. The `preview` object accepts the props and callbacks of ImagePreview (`onVisibleChange`, `onChange`, `onClose`, `onZoomIn`, `onZoomOut`, `onPrev`, `onNext`, `onRatioChange`, `onRotateLeft`, `onDownload`, `onDownloadError`), except `lazyLoad`, `lazyLoadMargin`, `class` and `style` (use `previewCls` and `previewStyle` to style the preview). Custom nodes do not go in `preview`; use the snippets of Image. When `preview.src` is an array, switching images returns to "fit to page". An Image inside an ImagePreview ignores the `title`, `previewMenu`, `leftIcon`, `rightIcon` and `closeIcon` snippets; the snippets of the ImagePreview apply.

</Framework>

## Accessibility

### ARIA

- When rendered into `document.body` (the default), the preview is a modal dialog with `role="dialog"` and `aria-modal="true"`; rendered into a custom container (`getPopupContainer` returns another element, including a container set on ConfigProvider) it is a non-modal dialog and does not output `aria-modal`. It is named by its title (`previewTitle`, or `preview.previewTitle` of an image in a group) when there is one, otherwise by "Preview" from the locale
- Close, the left and right arrows, and the footer's previous, next, zoom out, zoom in, original size / adapt to the page, rotate and download controls are native `button` elements. Their accessible names come from the matching `prevTip`, `nextTip` and other tip props, or from the locale when those are not set. The zoom slider is named "Zoom" from the locale, with the current percentage as its `aria-valuetext`
- At the first or last image, or at a zoom limit, the matching footer button gets `aria-disabled="true"` and stays focusable, so focus is not lost. The download button is also disabled when there is no current image (an empty `src` list)
- The footer page counter has `aria-live="polite"`, so screen readers announce the new position when the image changes
- With the preview enabled and the image loaded, the root of an Image thumbnail is a focusable button (`role="button"`, `tabindex="0"`, `aria-haspopup="dialog"`) named by the `alt` of the image; with `preview` set to false, or before the image has loaded, it is not focusable. Closing the preview returns focus to the thumbnail. A thumbnail inside an ImagePreview group that opens with the mouse also opens with the keyboard: while loading or after a load error it still has the button role and is focusable, and Enter or Space opens the group preview
- The `alt` of the preview image is the `alt` of the thumbnail it shows (an `ImagePreview` `src` array has no alt, so it is an empty string)

### Keyboard interaction

- With focus on a thumbnail, Enter or Space opens the preview
- Opening the preview moves focus into it. In a modal preview, Tab and Shift + Tab cycle through its controls and closing it returns focus to the element focused before; a non-modal preview rendered into a custom container does not trap Tab, and on close focus returns to the element focused before only if it is still inside the preview or on body, and stays where it is when it has moved elsewhere on the page
- Enter or Space presses the focused button
- ← and → switch to the previous and next image, swapped in RTL (ConfigProvider `direction="rtl"`). At the first or last image they behave like the buttons: they wrap around when `infinite` is true and do nothing otherwise
- ← and → do not switch images while focus is in an input, textarea, select or editable element (such as an input in a custom footer), or while Alt, Ctrl, Meta or Shift is held; on the focused zoom slider they change the zoom
- Esc closes the preview (unless `closeOnEsc` is false)
- After the controls hide because of `viewerVisibleDelay`, a key press or focus on a control shows them again; they stay shown while focus is on one of them
