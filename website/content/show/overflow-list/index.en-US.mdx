### Collapse Mode - Simple

You could use `renderMode="collapse"` (default) to render items.

<Framework only="vue">

`items` holds data only, never nodes. Render each visible item with the `#item="{ item, index }"` slot and the overflowing items with the `#overflow="{ items, position }"` slot; in collapse mode it is called once, and `items` are the items that do not fit.

</Framework>

<Framework only="solid">

`items` holds data only, never nodes. Each visible item is rendered by the element `visibleItemRenderer` returns; overflowing items are rendered by `overflowRenderer`, and collapse mode renders one overflow node whose argument is the items that do not fit.

</Framework>

<Framework only="svelte">

`items` holds data, not nodes. Each visible item is rendered by the `item` snippet, with the parameter `{ item, index }`. The overflowing items are rendered by the `overflow` snippet, with the parameter `{ items, position }`; collapse mode renders it once, only when there are overflowing items, and `items` are the ones that do not fit.

</Framework>

### Scroll Mode

You could use `renderMode="scroll"` for a scrollable list.  
If you need certain element in the list to scrollIntoView, use ``document.querySelector(`.item-cls[data-scrollkey="${key}"]`` to select to corresponding DOM.

<Framework only="vue">

In scroll mode `#overflow` is called once per side, with `position` set to `start` or `end` and `items` being the items scrolled out on that side.

</Framework>

<Framework only="solid">

In scroll mode `overflowRenderer` receives `[start, end]`, the items scrolled out before and after the visible ones, and returns one node for each side.

</Framework>

<Framework only="svelte">

In scroll mode `overflow` is rendered once per side, with `position` set to `start` or `end` and `items` the items scrolled out on that side. Each item is wrapped in a `display: contents` span, and `data-scrollkey` is written on, and observed from, the first element the `item` snippet renders, so `item` must output an element or the item is skipped.

</Framework>

## API Reference

<Framework only="react">

<OverflowListReactApi />

Other native attributes such as `aria-*`, `id`, `data-*` and `onClick` land on the root element.

</Framework>

<Framework only="vue">

<OverflowListVueApi />

`class`, `style` and native attributes such as `aria-*` land on the root element through attrs; pass the scroll wrapper's class, style and other attributes with `wrapperClassName`, `wrapperStyle` and `wrapperProps`.

</Framework>

<Framework only="solid">

<OverflowListSolidApi />

`class`, `style`, `ref` and native attributes such as `aria-*` land on the root element; pass the scroll wrapper's class, style and other attributes with `wrapperClassName`, `wrapperStyle` and `wrapperProps`.

</Framework>

<Framework only="svelte">

<OverflowListSvelteApi />

`class`, `style` (a string) and native attributes such as `aria-*` land on the root element; pass the class, style and other attributes of the scroll wrapper with `wrapperClassName`, `wrapperStyle` and `wrapperProps`.

</Framework>

## Accessibility

### ARIA

- When `aria-label` or `aria-labelledby` is passed, the root element gets `role="group"` so the group of items has a readable name; without them the root has no role
