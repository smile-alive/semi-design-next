### Basic Usage

<Framework only="vue">

Use `v-model:visible` to control visibility. `v-model:visible` updates only on the cancel paths: the cancel button, the close button, the mask and Esc. When `onCancel` returns a Promise, it updates after the Promise fulfills, and a rejection keeps the modal open. Clicking the ok button only triggers `@ok`; the caller sets `visible` to `false`. While the `@cancel` callback runs, the parent's `visible` is still `true`.

</Framework>

<Framework only="solid">

Use `visible` to control visibility. `onOk` and `onCancel` never close the modal by themselves; the caller sets `visible` to `false`. When either returns a Promise, the matching button stays loading until the Promise settles.

</Framework>

<Framework only="svelte">

Use `bind:visible` to control visibility. `bind:visible` is written back with `false` only on the cancel paths: the cancel button, the close button, the mask and Esc. When `onCancel` returns a Promise, it is written back after the Promise fulfills, and a rejection keeps the modal open. Clicking ok only calls `onOk`; the caller sets `visible` to `false`. While `onCancel` runs, `visible` is still `true`.

</Framework>

## Accessibility

### ARIA

WAI-ARIA: https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/

- The Modal component has role `dialog`, following the [APG Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) pattern
- Confirm dialogs (`Modal.confirm`, `info`, `success`, `warning`, `error`, and the same-named `useModal` methods) have role `alertdialog`, and `aria-describedby` points to the message, following the [APG Alert Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/) pattern
- aria-modal is set to true when the dialog is modal. A dialog is modal when it has a mask (`mask`) and is mounted in the body (judged by the actual container, so the `getPopupContainer` of ConfigProvider counts) or has `maskFixed`. With `mask={false}`, or a mask confined to a custom container, the page behind stays usable and aria-modal is omitted
- aria-labelledby corresponds to the dialog title; it is not generated when `aria-label` or a custom header is given
- The Modal component does not set aria-describedby by default: when the body holds a form, a list or several paragraphs, reading it out whole gets in the way. Pass it yourself when needed
- `role` and every `aria-*` attribute passed by the caller land on the element that carries the role
- The close button's aria-label comes from the current locale ('Close' in English, '关闭' in Simplified Chinese)

### Keyboard and focus

- Modal automatically gets the focus when it is popped up. An element with `autoFocus` (`autofocus` in Vue and Svelte) inside the dialog gets the focus first; otherwise the cancel button does by default, which can be controlled by passing autoFocus in cancelButtonProps or okButtonProps. With `keepDOM`, opening it again gives the same result; with `keepDOM` and `lazyRender={false}` that starts hidden, an `autoFocus` element cannot take focus under `display: none`, so later openings land on the default button.
- When a modal dialog is closed, the focus automatically returns to the element before it was opened. Keyboard users can use the `Tab` key and `Shift + Tab` to move the focus in a loop within the Modal, including the Modal's own close button and OK cancel button. At this time, the page behind the Modal cannot be interacted with or tab-focused.
- A non-modal dialog (`mask={false}`, or a mask confined to a custom container without `maskFixed`) also takes focus when opened, but does not lock Tab and the rest of the page stays usable. When closed, focus is returned only if it is still inside the dialog or has fallen to the body; focus the user has moved elsewhere on the page stays. A Modal in the body with `mask={false}` does not lock body scrolling.
- Modify the default value of closeOnEsc to true, allowing users to directly close Modal through the keyboard for a better experience

## Content Guidelines

- Imperative Modal and Default Modal The title of the two modal dialogs uses the format of verb + noun, whether it is a declarative sentence or a question sentence

| ✅ Recommended usage | ❌ Deprecated usage                   |
| -------------------- | ------------------------------------- |
| Edit ticket          | Edit                                  |
| Delete form？        | Are you sure you want to delete form? |

- The operation buttons of the two modal dialog boxes only need to use the verbs in the title under the premise of ensuring that the title description is clear

| ✅ Recommended usage | ❌ Deprecated usage |
| -------------------- | ------------------- |
| Edit                 | Edit ticket         |

- Text specification for imperative Modal
    - Give a specific explanation to the title, do not repeat the information of the title
    - Make sure users know how to act if necessary

- #### Why is the spacing between title and content different under imperative and non-imperative calls?
    In the imperative call scenario, the title and content are more closely related, so expressing this strong correlation with a closer distance is in line with expectations. If users don't want this effect, they can do their own style overrides.
