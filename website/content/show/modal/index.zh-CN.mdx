### 基本

<Framework only="vue">

对话框用 `v-model:visible` 控制显示。`v-model:visible` 只在取消路径更新：取消按钮、关闭按钮、遮罩和 Esc；`onCancel` 返回 Promise 时，在 fulfill 后更新，reject 则保持打开。点击确定只触发 `@ok`，由使用方把 `visible` 设为 `false`。`@cancel` 回调执行时，父级的 `visible` 仍为 `true`。

</Framework>

<Framework only="solid">

对话框由 `visible` 控制显示。`onOk`、`onCancel` 不会自行关闭对话框，由使用方把 `visible` 设为 `false`；它们返回 Promise 时，对应按钮保持加载直到 Promise 落定。

</Framework>

<Framework only="svelte">

对话框用 `bind:visible` 控制显示。`bind:visible` 只在取消路径写回 `false`：取消按钮、关闭按钮、遮罩和 Esc；`onCancel` 返回 Promise 时，在 fulfill 后写回，reject 则保持打开。点击确定只调用 `onOk`，由使用方把 `visible` 设为 `false`。`onCancel` 回调执行时，`visible` 仍为 `true`。

</Framework>

### Hooks 用法

<Framework only="react">

通过 Modal.useModal 创建支持读取 context 的 contextHolder。

</Framework>

<Framework only="vue">

`Modal.useModal()` 返回 `[modal, Holder]`。把 `<Holder />` 放在需要读取上下文的位置，通过 `modal.confirm` 等方法创建的对话框就能读取该位置的 provide、ConfigProvider 与语言包。

</Framework>

<Framework only="solid">

`Modal.useModal()` 返回 `[modal, contextHolder]`。把 `contextHolder` 放在需要读取上下文的位置，通过 `modal.confirm` 等方法创建的对话框就能读取该位置的 context、ConfigProvider 与语言包。

</Framework>

<Framework only="svelte">

`Modal.useModal()` 返回 `{ info, success, error, warning, confirm }`，没有 Holder。它在调用时读取所在组件的 context、ConfigProvider 与语言包，所以要在组件初始化时调用，并且放在需要读取这些上下文的组件里（通常是 ConfigProvider 的子组件）；组件销毁时它打开的对话框一并移除。

</Framework>

### 可拖拽 Modal

<Framework only="react">

通过 `modalRender` 自定义渲染 Modal 内容，可拖拽 Modal 通过 DragMove 组件实现。

</Framework>

<Framework only="vue">

通过 `#modal="{ modal }"` 插槽自定义渲染 Modal 内容，`modal` 是 `role="dialog"` 元素的 VNode，用 `<component :is="modal" />` 放置。可拖拽 Modal 通过 DragMove 组件实现。

</Framework>

<Framework only="solid">

通过 `modalRender` 自定义渲染 Modal 内容，参数是 `role="dialog"` 元素，返回值必须包含它。可拖拽 Modal 通过 DragMove 组件实现。

</Framework>

<Framework only="svelte">

Svelte 的 DragMove 是 attachment `dragMove`。把 `{@attach dragMove(options)}` 直接写在 `<Modal>` 上，attachment 会挂到 `role="dialog"` 元素上，对话框就能拖动。需要自己摆放对话框时，也可以用 `modal` snippet（参数 `{ modal }`，用 `{@render modal()}` 放置）。

</Framework>

## Accessibility

### ARIA

WAI-ARIA: https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/

- 组件版 Modal 的 role 为 `dialog`，遵循 [APG Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
- 确认框（`Modal.confirm`、`info`、`success`、`warning`、`error`，以及 `useModal` 的同名方法）的 role 为 `alertdialog`，`aria-describedby` 指向正文，遵循 [APG Alert Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/)
- aria-modal 在对话框是模态时设置为 true。模态的判定是：有遮罩（`mask`），且挂载在 body 中（以实际容器判断，ConfigProvider 的 `getPopupContainer` 同样计入）或设置了 `maskFixed`。`mask={false}`，或遮罩限定在自定义容器内时背景保持可用，不输出 aria-modal
- aria-labelledby 对应对话框标题；传入 `aria-label` 或自定义头部时不生成该引用
- 组件版 Modal 默认不设置 aria-describedby：正文含表单、列表或多段内容时，整段正文被读出反而干扰；需要时由使用方传入
- 使用方传入的 `role` 与全部 `aria-*` 属性落在 `role` 所在的元素上
- 关闭按钮的 aria-label 来自当前语言包（简体中文为「关闭」，英文为 'Close'）

### 键盘和焦点

- Modal 在弹出时自动获得焦点。对话框内带 `autoFocus`（Vue、Svelte 中为 `autofocus`）的元素优先获得焦点，没有时默认聚焦到取消按钮，可通过在 cancelButtonProps 或 okButtonProps 传入 autoFocus 来控制该行为。`keepDOM` 时再次打开，结果相同；`keepDOM` 加 `lazyRender={false}` 且初始隐藏时，`autoFocus` 元素在 `display: none` 下无法获得焦点，之后的打开落到默认按钮。
- 模态对话框关闭时，焦点自动回归到打开前元素。键盘用户可以使用 `Tab` 键和 `Shift + Tab`，将焦点在 Modal 内循环移动，包括 Modal 自带的关闭按钮和确定取消按钮，此时 Modal 背后的页面不可交互，也不可被 tab 聚焦。
- 非模态对话框（`mask={false}`，或遮罩限定在自定义容器内且未设置 `maskFixed`）打开时同样移入焦点，但不锁定 Tab，页面其余部分保持可用。关闭时只在焦点仍在对话框内或已落到 body 时归还，用户已移到页面其他位置的焦点不动。挂载在 body 中且 `mask={false}` 的 Modal 不锁定 body 滚动。
- 修改 closeOnEsc 默认值为 true，允许用户通过键盘直接关闭 Modal 带来更好的体验

## 文案规范

- 命令式 Modal 与 默认 Modal 两种模态对话框的标题使用 动词 + 名词 的格式，无论是陈述句还是问句

| ✅ 推荐用法   | ❌ 不推荐用法                         |
| ------------- | ------------------------------------- |
| Edit ticket   | Edit                                  |
| Delete form？ | Are you sure you want to delete form? |

- 两种模态对话框的操作按钮在保证标题描述清楚的前提下，只需要使用标题内的动词即可

| ✅ 推荐用法 | ❌ 不推荐用法 |
| ----------- | ------------- |
| Edit        | Edit ticket   |

- 命令式 Modal 的正文规范
    - 对标题进行具体的解释说明，不要重复标题的信息
    - 确保用户知道在必要时如何采取行动

## FAQ

- #### 为什么使用 LocaleProvider 后， Modal.confirm 确认、取消按钮的文本没有国际化？

      <Framework only="react">

    Modal 使用 Portal 将浮层节点插入到 DOM 树中。但这个操作仅能改变节点在 DOM 树中的位置，无法改变节点在 React 节点树中的位置，LocalProvider是基于 Context 机制传递的，必须是从属的 React 子结点才可消费到 Local 相关 Context。因此命令式的 Modal 的内置文本无法自动适配国际化。你可以通过 `okText` 和 `cancelText` 这两个属性来根据 Locale 重新设置 i18 的文本。  
     你也可以通过 Modal.useModal 方法来返回 modal 实体以及 contextHolder 节点。将 contextHolder 插入到你需要获取 context 位置，即可使 Modal 获取到对应的 Context，如 ConfigProvider 或者 LocaleProvider 的配置。

      </Framework>

      <Framework only="vue">

- #### 为什么 title 和 content 的间距在命令式调用和非命令式调用下不同?
    命令式调用场景下，标题和内容的相关性更强，所以用更近的距离表达这种强相关性，符合预期。用户如果不想要这种效果，可以自己做样式覆盖。
