### Theme

`popup` bubble card mode provides two themes `default` and `primary`, set by the `theme` property.

<Demo id="theme" />

### Popup position

`popup` bubble card mode provides 16 positions, optional values are `top`, `topLeft`, `topRight`, `left`, `leftTop`, `leftBottom`, `right`, `rightTop`, `rightBottom`, `bottom`, `bottomLeft`, `bottomRight`, `leftTopOver`, `rightTopOver`, `leftBottomOver`, `rightBottomOver`, and can be set by the `showArrow` property to display the arrow.

<Demo id="position" />

### Set the size of the highlight area

Set by the `spotlightPadding` property.

<Demo id="spotlight-padding" />

### Customize the button

Set by the `nextButtonProps` and `prevButtonProps` properties.

<Framework only="vue">

Use the `nextText` and `prevText` slots for the button text. The text of the button on the last step is set by `finishText`.

</Framework>

<Framework only="solid">

Set the button text with `children` in `nextButtonProps` and `prevButtonProps`. The text of the button on the last step is set by `finishText`.

</Framework>

<Framework only="svelte">

Use the `nextText` and `prevText` snippets for the button text. The text of the button on the last step is set by `finishText`.

</Framework>

<Demo id="custom-button" />

### Controlled

Set by the `current` property.

<Framework only="vue">

Bind the current step with `v-model:current` and the visibility with `v-model:visible`.

</Framework>

<Framework only="solid">

Bind the current step with `current` and write it back in `onChange`; bind the visibility with `visible` and close the guide in `onSkip` and `onFinish`.

</Framework>

<Framework only="svelte">

Bind the current step with `bind:current` and the visibility with `bind:visible`.

</Framework>

<Demo id="controlled" />

### Modal guide

Set by the `mode` property.

<Framework only="vue">

Use the `cover` slot for the cover and the `description` slot for rich-text descriptions.

</Framework>

<Framework only="solid">

Use `renderCover` for the cover and `renderDescription` for rich-text descriptions; they are called for the current step only.

</Framework>

<Framework only="svelte">

Use the `cover` snippet in the step data for the cover, and write `description` as a snippet for rich-text descriptions; a snippet receives `{ item, index }`.

</Framework>

<Demo id="modal" />

## API Reference

---

<Framework only="react">

<UserGuideReactApi />

UserGuide has no root element. In popup mode `className` and `style` land on the popover card; in modal mode `className` and `style` are handed to Modal and land where Modal puts them. Undeclared attributes such as `aria-*` and native events are dropped. The dialog's accessible name comes only from the `title` of the current step.

</Framework>

<Framework only="vue">

<UserGuideVueApi />

UserGuide has no root element. In popup mode `class` and `style` land on the popover card; in modal mode they follow Modal, with `class` on the outermost element inside the portal and `style` on `.semi-modal`. Other undeclared attributes such as `aria-*` are dropped. The dialog's accessible name comes only from the title of the current step (the `title` slot or `item.title`).

</Framework>

<Framework only="solid">

<UserGuideSolidApi />

UserGuide has no root element. In popup mode `class` and `style` land on the popover card; in modal mode they are handed to Modal and land where Modal puts them. Undeclared attributes such as `ref`, `aria-*` and native events are dropped. The dialog's accessible name comes only from the `title` of the current step.

</Framework>

<Framework only="svelte">

<UserGuideSvelteApi />

UserGuide has no root element. In popup mode `class` and `style` land on the popover card; in modal mode `class` lands on the outermost element of the Modal and `style` on `.semi-modal`. Undeclared attributes such as `aria-*` and native events are dropped. The dialog's accessible name comes only from the `title` of the current step.

</Framework>

## Accessibility

- Each step is a dialog named by the step `title`; Escape works like clicking Skip.
- In both modes, focus moves to the primary button (Next or Finish) when each step appears. In popup mode Tab cycles inside the card, and focus returns to the element focused before the guide when it closes; in modal mode, Modal manages the focus cycle and its return.
