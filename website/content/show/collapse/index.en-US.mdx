### Custom Extra Content on the Right-upper Corner

<Framework only="react">

You can use `extra` to set extra content on the right-upper corner.

`header` is rendered inside the panel's toggle button, so it may only hold text, icons and other non-interactive content. `extra` sits beside the button in the same row and may hold controls such as buttons or inputs, whether `header` is a string or a ReactNode.

</Framework>

<Framework only="vue">

Use the `#extra` slot to set extra content on the right-upper corner.

`#header` is rendered inside the panel's toggle button, so it may only hold text, icons and other non-interactive content. `#extra` sits beside the button in the same row and may hold controls such as buttons or inputs.

</Framework>

## Accessibility

### ARIA

- Each panel header follows the WAI-ARIA Accordion pattern: a native `button` wrapped in an element with `role="heading"` and `aria-level="3"`. The button's accessible name is the `header` content.
- The button carries `aria-expanded`, and `aria-controls` pointing at the panel content whenever that content is still in the DOM: always when open, and when closed once `keepDOM` is in effect (including when `keepDOM` is only set in the global defaults of Collapsible) and the content has been rendered, for example a panel opened once and closed again with `keepDOM` and `lazyRender`. A closed panel that `lazyRender` has not rendered yet has no content and no `aria-controls`.
- The panel content has `role="region"` and is labelled by the button through `aria-labelledby`; closed content kept by `keepDOM` is `inert`.
- The expand icon is decorative and has `aria-hidden="true"`; `extra` is outside the button.
- A `disabled` panel uses the button's native `disabled` attribute.

### Keyboard and Focus

- Each panel header button is one Tab stop; disabled panels are skipped.
- `Enter` or `Space` on the focused button expands or collapses the panel, also when `clickHeaderToExpand` is `false`.
- Controls inside `extra` are Tab stops of their own.

## FAQ

- ##### Why is the data in Form cleared when using Collapse?

    When Collapse is collapsed, the related DOM is destroyed and so are the fields data stored in Form. You could set `keepDOM` of Collapse to true to keep the DOM from being destroyed.

- ##### The whole header row is a click hot zone for folding and expanding. If a control (such as Input) is placed in the row, clicking it collapses/expands the panel. How to avoid it?
    Put the control in `extra`, not in `header`: `header` is inside the toggle button and must not contain controls. With `clickHeaderToExpand` set to false only the toggle button and the icon respond to clicks; otherwise stop the click from bubbling to the header row in the control's click handler, or in a wrapping element's click handler if the control does not provide the event object, as in the example below.

<Framework only="react">

```jsx
import React from 'react';
import { Collapse, Input } from '@fibrae/semi-ui-react';

() => (
    <Collapse>
        <Collapse.Panel
            header="Panel header"
            extra={
                <span onClick={(e) => e.stopPropagation()}>
                    <Input aria-label="Panel note" />
                </span>
            }
            itemKey="1"
        >
            <p>Hi, bytedance dance dance. This is the docsite of Semi UI. </p>
        </Collapse.Panel>
    </Collapse>
);
```

</Framework>
