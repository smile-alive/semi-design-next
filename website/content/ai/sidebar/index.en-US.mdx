## Usage Scenarios

The Sidebar is mainly used in AI scenarios for information display and feature configuration, including MCP configuration, reference sources, code preview, rich text preview and editing, etc.

### MCP Configuration

Use `MCPConfigure` to display, enable/disable, configure and search MCP tools.

<Framework only="react">

- Use `options` and `customOptions` to set built-in MCP tools and custom MCP tools
- Use `visible` to control show and hide, and `onCancel` to listen to user close behavior
- Use `onStatusChange` to handle enabling/disabling of MCP tools
- Use `onAddClick` to handle actions after clicking the Add button in custom MCP page
- Use `onConfigureClick` to listen to configuration of built-in MCP tools, and `onEditClick` to listen to configuration of custom MCP tools

For other APIs of MCPConfigure, see [MCPConfigure](#MCPConfigure).

The type of MCP tool item is as follows:

```ts
interface MCPOption {
    icon?: ReactNode;
    label?: string;
    value: string; // required, identifies the tool and must be unique
    desc?: ReactNode;
    active?: boolean;
    disabled?: boolean;
    configure?: boolean; // whether to show configure button
}
```

</Framework>

<Framework only="vue">

- Bind `v-model:options` and `v-model:customOptions` to the built-in and custom MCP tools; switching a tool updates the bound value first and then emits `statusChange`
- Use `v-model:visible` to control show and hide, and `cancel` to listen to user close behavior
- Use `statusChange` to handle enabling/disabling of MCP tools
- Use `addClick` to handle actions after clicking the Add button in custom MCP page
- Use `configureClick` to listen to configuration of built-in MCP tools, and `editClick` to listen to configuration of custom MCP tools
- Use the `#icon` and `#desc` slots for the icon and description of an item, and `#item` to replace the whole row; the slot parameters are `{ item, index, custom }`

For other APIs of MCPConfigure, see [MCPConfigure](#MCPConfigure).

The type of MCP tool item is as follows:

```ts
interface MCPConfigureOption {
    icon?: string; // image URL; use the #icon slot for other content
    label?: string;
    value: string; // required, identifies the tool and must be unique
    desc?: string; // plain text; use the #desc slot for other content
    active?: boolean;
    disabled?: boolean;
    configure?: boolean; // whether to show configure button
}
```

</Framework>

<Framework only="solid">

- Use `options` and `customOptions` to set the built-in and custom MCP tools
- Use `visible` to control show and hide, and `onCancel` to listen to user close behavior
- Use `onStatusChange` to handle enabling/disabling of MCP tools; the component never changes the lists you pass, so write the callback argument back to `options` or `customOptions`
- Use `onAddClick` to handle actions after clicking the Add button in custom MCP page
- Use `onConfigureClick` to listen to configuration of built-in MCP tools, and `onEditClick` to listen to configuration of custom MCP tools
- Use `renderIcon` and `renderDesc` for the icon and description of an item, and `renderItem` to replace the whole row; they are called with `{ option, custom }`

For other APIs of MCPConfigure, see [MCPConfigure](#MCPConfigure).

The type of MCP tool item is as follows:

### Code Display

You can use `CodeItem` in `Sidebar` to display code. `CodeItem` is built based on [JsonViewer](/en-US/react/plus/json-viewer) and [CodeHighlight](/en-US/react/plus/code-highlight).

- `content`: content string
- `isJson`: whether the content is json
- `language`: programming language name, same as `language` in `CodeHighlight`; register it with `CodeHighlight.register` first
- `jsonViewerProps`: configure other JsonViewer props
- `codeHighlightProps`: configure other CodeHighlight props

<Framework only="vue">

The value of JsonViewer is called `modelValue` in `jsonViewerProps`, and both `jsonViewerProps` and `codeHighlightProps` accept `class` and `style`. The custom rendering and search button of JsonViewer are available through the `#customRender` and `#searchButton` slots of `CodeItem`.

</Framework>

<Framework only="solid">

`jsonViewerProps` and `codeHighlightProps` are the props of the Solid JsonViewer and CodeHighlight. They are spread after the built-in defaults, so `value`, `width`, `height` and the like override those defaults, and `class` and `style` are accepted too.

</Framework>

### Rich Text Editor

You can use `FileItem` in `Sidebar` to view and edit rich text content. `FileItem` is implemented based on [tiptap](https://tiptap.dev/docs/editor/getting-started/overview).

<Framework only="react">

- `content`: rich text content, supports the same types as TiptapContent. A change after mount is synced to the editor; it is not applied when it equals what the editor already holds, so typing and the cursor are not interrupted. The sync does not call `onContentChange`
- `editable`: whether the content is editable; a change after mount is synced to the editor
- `imgUploadProps`: configure image upload endpoint and how to set the src after upload. Use `action` to set upload url and `getUploadImageSrc(response)` to return the uploaded image url from the upload response (when omitted, a string response is used as the url, otherwise `response.src`), which will be used as src of img node in rich text. The toolbar shows the image button only when `action` or `customRequest` is set

</Framework>

<Framework only="vue">

- `content`: rich text as HTML. A change after mount is synced to the editor; it is not applied when it equals what the editor already holds, so typing and the cursor are not interrupted. The sync does not emit `contentChange`
- `editable`: whether the content is editable; a change after mount is synced to the editor
- `imgUploadProps`: configure image upload endpoint and how to set the src after upload. Use `action` to set upload url and `getUploadImageSrc(response)` to return the uploaded image url from the upload response (when omitted, a string response is used as the url, otherwise `response.src`), which will be used as src of img node in rich text; the `on` listeners of Upload (such as `onSuccess`) can be passed here too. The toolbar shows the image button only when `action` or `customRequest` is set
- `extensions` and `imgUploadProps` are read only when the editor is created; change the `key` to remount it with new values
- `contentChange` is emitted after an edit, with the content as HTML

</Framework>

<Framework only="solid">

- `content`: rich text as HTML. A change after mount is synced to the editor; it is not applied when it equals what the editor already holds, so typing and the cursor are not interrupted. The sync does not call `onContentChange`
- `editable`: whether the content is editable; a change after mount is synced to the editor
- `imgUploadProps`: configure image upload endpoint and how to set the src after upload. Use `action` to set upload url and `getUploadImageSrc(response)` to return the uploaded image url from the upload response (when omitted, a string response is used as the url, otherwise `response.src`), which will be used as src of img node in rich text; the `on` callbacks of Upload (such as `onSuccess`) can be passed here too. The toolbar shows the image button only when `action` or `customRequest` is set
- `extensions` and `imgUploadProps` are read only when the editor is created; remount the component to apply new values, for example by wrapping it in `<Show when={version} keyed>`
- `onContentChange` is called after an edit, with the content as HTML

</Framework>

### Sidebar

The `Sidebar` has a main view (`mode` is `main`) and detail views (`mode` is `code`, `file` and other custom values).

<Framework only="react">

In the main view you can configure the title through `title`, decide whether to show close button through `showClose`, and configure top button group through `options`.

For content rendering in the main view, you can pass a render function via `renderMainContent`. You can use `AnnotationContent` in `Annotation` to render references, `FileContent` in `Sidebar` to render rich text, and `CodeContent` to render code.

For detail views, if the content is rich text or code, set `mode` to `code` or `file` and provide `detailContent` to display the content with built-in code display component / rich text editor. If you want to customize how the detail view is rendered, you can use `renderDetailContent` to handle it yourself.

</Framework>

<Framework only="vue">

In the main view you can configure the title through `title` or the `#title` slot, decide whether to show close button through `showClose`, and configure the top button group through `options` (each item is `{ name, key }`); `v-model:activeKey` binds the selected item. Use the `#optionIcon="{ item, index }"` slot for the button icon, or `#optionItem` to replace the whole button, whose `onClick` parameter selects the item.

For content rendering in the main view, use the `#mainContent="{ activeKey }"` slot and render by the selected item. You can use `AnnotationContent` in `Annotation` to render references, `FileContent` in `Sidebar` to render rich text, and `CodeContent` to render code.

For detail views, if the content is rich text or code, set `mode` to `code` or `file` and provide `detailContent` to display the content with built-in code display component / rich text editor; a new `key` in `detailContent` remounts it. If you want to customize how the detail view is rendered, use the `#detailContent="{ mode }"` slot, and customize the detail header through `#detailHeader="{ mode, detailContent }"`; with empty content, both fall back to the built-in ones. Clicking the back button of the detail header emits `backWard`.

</Framework>

<Framework only="solid">

In the main view you can configure the title through `title`, decide whether to show close button through `showClose`, and configure the top button group through `options` (each item is `{ name, key }`); `activeKey` together with `onActiveOptionChange` manages the selected item. Use `renderOptionIcon` for the button icon, or `renderOptionItem` to replace the whole button, whose second parameter `onChange` selects the item.

For content rendering in the main view, pass a render function via `renderMainContent`, called with the selected `activeKey`. You can use `AnnotationContent` in `Annotation` to render references, `FileContent` in `Sidebar` to render rich text, and `CodeContent` to render code. The render function runs again for every signal it reads, so read state signals such as the expanded panels only in the props you pass to the child components, which keeps the content from being rebuilt as a whole.

For detail views, if the content is rich text or code, set `mode` to `code` or `file` and provide `detailContent` to display the content with built-in code display component / rich text editor; a new `key` in `detailContent` remounts it. If you want to customize how the detail view is rendered, use `renderDetailContent`, and customize the detail header through `renderDetailHeader`; when they return empty content, both fall back to the built-in ones. Clicking the back button of the detail header calls `onBackWard`.

</Framework>
